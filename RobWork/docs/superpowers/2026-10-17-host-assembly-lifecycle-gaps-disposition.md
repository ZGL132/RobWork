## 1. 核心判断（一句话，修正版）

> **现有验证对组件行为覆盖较多，对生产装配的完备性、跨组件生命周期和失败后的状态一致性覆盖不足。**

## 2. 三项发现的证据强度分级（首版按三个独立根因叙述，本版修正）

| # | 发现 | 证据强度 | 依据 |
| --- | --- | --- | --- |
| ③ | 需求草稿源未进入生产草稿保存链 | **直接代码证据** | 生产 `attachModule` 仅挂 modeling（UiPlugin.cpp:2485）；`RequirementsDraftSource` 已实现但仅在测试中构造使用（RequirementsUiModule.hpp:459 注释声称"随装配挂接"，无生产调用点——实测 drafts/ 目录从未创建） |
| ① | 桥绑定生命周期不闭合 | **代码事实成立，因果链部分待证** | 桥在已绑定时拒绝重复 attach（RuntimePublishBridge.cpp:82-97）；`switchHostSession` 无生产调用点。**但**"某条关闭路径漏 detach"是合理假设而非证实——detach 调用在关闭清理中实际存在（UiPlugin.cpp:4713）；需复现确认三选一：清理未进入／清理提前抛错／时序直接重复 attach |
| ② | 打开链路异常穿透致整站退出 | **退出分支存在，传播链待复现** | StudioMain.cpp:560-573 在 `app.exec()` 外捕获并 return -1；本次异常是否实际经过该路径需复现证据 |

**归并修正**：①与②很可能是**同一次故障的触发环节与放大环节**（非两个独立根因）；③是另一项独立装配缺口。"零件全对"同样需收敛为"**这些零件在已执行的测试中通过**"——草稿链尚有默认分支锚与 `DraftQueryPortStub`（ui/app/PortAdapters.*，生产路径），即便补上挂接，保存→查询→恢复全链仍需验证。

## 3. 流程盲区复盘（修正版）

成立的核心判断：**组件正确 ≠ 组合正确**——每个组件都在"被正确使用"的测试前提下通过（内存闭包当磁盘、挂好的 fake 模块、harness 演示绑定），唯独生产装配无人把线接起来。harness 自述"端口缝隙的演示绑定"（RequirementsHarnessMain.cpp:18），其通过不能证明真实宿主链路接通。

首版三处过满表述，修正如下：

1. ~~"静态扫描天生看不见少掉的好东西"~~ → 静态检查**可以**核对必需目标/模块注册/处理器/配置是否齐全；问题是这些"必须存在"属性**尚未纳入**检查。
2. ~~"CI/ctest 在结构上跑不到生命周期场景"~~ → 同进程关闭重开可做集成测试；真实磁盘恢复可用临时目录；进程重启可由父进程两次拉起子进程。真实 GUI 需要 Windows 桌面环境，但**并非只能人工**。
3. ~~"其他防线拦干净了，连中三个是必然"~~ → 本轮发现集中暴露装配与生命周期覆盖不足；其他层仍有残余风险。

保留的判断：**注释信任偏差**真实存在（注释声称"随装配挂接"而调用不存在，前序会话包括 AI 均曾把注释当事实引用）——注释应视为**待核对的声明**，不能替代调用点与行为证据。

## 4. 处置建议（集成父批次，供所有者裁决）

父批次「宿主装配与生命周期收口」，两个子批，各自独立验收标准：

### 子批 A：生命周期与异常恢复（F-910，覆盖①②）

1. **复现前置**：先在真实宿主复现并记录传播链（detach 是否走到／清理是否提前抛错／时序），把"合理假设"升级为"证实根因"后再定修复方案——不在未证实前改代码。
2. **修复方向（裁决项）**：打开回调按**当前绑定态**分派（未绑定→attach；已绑定→switch，或关闭路径补齐所有中止/失败形态的 detach）。注意：`detach→attach` 对"关闭再打开"是合法序列，`switch` 仅在保留旧呈现的切换场景必需——**约束对象是各业务路径的状态转换与失败回滚，不是三个函数的文本配对**。
3. **异常隔离三要素**（不可只规定"在哪里加 catch"）：
   - 捕获边界：打开/关闭/切换操作边界＋可能执行这些操作的 Qt 回调边界；
   - 回滚责任：保留诊断信息＋执行对应补偿或清理（异常抛出前存储上下文/桥绑定/草稿会话/界面可能已部分更新）；
   - 恢复成功条件：验证状态回到"旧项目完整保留"或"干净的无项目状态"——**仅恢复确认后才允许提示可重试**；状态不可确认→停止相关操作＋显式故障处置流程。
   - fail-fast 语义保留在桥/内核内不吞。

### 子批 B：草稿持久化（F-911，覆盖③）

1. 经**真实生产装配入口**补 `attachModule(requirements, RequirementsDraftSource)`；
2. 核对 V-13"草稿 60s 周期落盘"是否落地（当前装配只见手动/关闭触发，未见周期定时器——疑点随批核对）；
3. 挂接后全链验证：保存→查询→恢复（含默认分支锚与 DraftQueryPortStub 现状的处置）。

### E2E 场景矩阵（两子批共用验收面；草稿恢复与正式修订恢复**分列**）

| 场景 | 核心断言 |
| --- | --- |
| S1 同进程：打开 A→关闭→重新打开 A | 桥与会话状态正确复位，无重复挂接 |
| S2 切换：A→B（成功/取消/失败三态） | 成功切到 B；取消或失败时 A 保持一致 |
| S3 未应用编辑→草稿保存成功→关闭/重启→恢复 | 恢复未应用内容，不额外产生正式修订 |
| S4 编辑→应用成功→关闭/重启→打开 | 正式修订及其内容正确恢复（应用成功后草稿可能已清理——与 S3 是两种持久化语义） |
| S5 草稿保存失败、呈现释放失败 | 错误可见，状态符合约定，不误报成功 |

**杀进程恢复承诺边界**：只承诺恢复**最后一次成功持久化的草稿**，不承诺未触发保存的编辑全部保留。
**测试纪律**：测试必须复用真实生产装配——**禁止测试夹具自行把漏掉的线接好**（否则再次掩盖生产缺陷）。

## 5. 治理改进（修正版四条，详见 IRD-NOTE-006）

1. **装配完备性门禁**：检查"当前产品配置下的必需模块 ID 集合 == 生产装配实际注册的模块 ID 集合，且无重复注册"——经真实生产装配入口断言注册结果，**不做实现类数量 vs 调用次数比较**（循环挂接/可选模块/测试替身/等数错挂都会使计数失效）。attach/detach/switch 文本配对仅作审查线索。
2. **异常隔离边界策略入 units/ui.md**：三要素（捕获边界/回滚责任/恢复成功条件）——见 §4 子批 A。
3. **真实宿主 E2E 冒烟**：按 §4 五场景作为集成批次 DoD 项；留痕入 traceability（走证据索引）。
4. **V 矩阵必验项 owner 化（修正）**：V-13 已追溯 T05、V-22 已追溯 T08 且测试以 GTEST_SKIP 如实登记环境不可用（GoldenDatasetsContractTest.cpp:2000 段）——既有责任链存在，缺口是**真实宿主验证未绑定明确集成节点作为交付阻断条件**。处置：当前交付范围内必验项挂 owner＋执行阶段/截止点＋实际状态＋证据；延期须明确风险接受人与补验条件；未来规划项不阻断局部任务，但产品交付时不得无限期悬空。

附小项：**装配性断言注释必须带可核对锚点**（调用点位置或承接任务号），否则按废注释打回——直接针对注释信任偏差。
