# 结构优化插件 Phase 8：全链验收、性能审计与发布计划

本阶段建立在 Phase 7 的 UI、候选比较、隔离预览和 staging 导出之上，目标是形成可复现、可审计、可发布的运动学结构优化版本。每个 S 必须独立验证、使用中文 commit，并且不得把构建产物或临时 WorkCell 提交到仓库。

## S80：全链验收矩阵与准入契约

- 固定模型、冻结需求、设计空间、随机种子、运行策略和证据阶段作为验收输入。
- 明确模型完整性、需求指纹、候选可行性、Verified 证据、报告/CSV、预览隔离和项目资源解析的准入条件。
- 产出本文件和稳定错误码，后续检查器只消费结构化结果，不从 UI 文案推断状态。

## S81：确定性与可行性全链验收

- 新增纯核心验收检查器，比较重复运行的候选顺序、稳定索引、变量指纹、得分和可行性。
- 检查硬约束失败不得排在可行方案之前，DataInsufficient/Failed/Canceled 不得被标记为 Feasible。
- 覆盖取消、空结果、基线缺失、重复索引和非有限结果。

## S82：性能预算与审计

- 对候选数量、总耗时、模型构建耗时、评估耗时、缓存命中和敏感性评估进行预算检查。
- 预算超限只生成结构化 Warning；负数、NaN、Inf 或计数矛盾生成 Error。
- 将审计摘要写入报告/CSV，并提供独立性能套件。

## S83：资源、线程与取消安全

- 检查运行结束后控制器处于 Idle/Completed/Failed 的合法终态，重复 start 被拒绝，取消后旧进度不能覆盖新运行。
- 检查候选结果和导出工件不含临时路径、非有限数字或悬挂资源引用。
- GUI 运行仍必须遵守 Windows `QT_QPA_PLATFORM=windows` 和单进程规则。

## S84：发布清单、版本和工件完整性

- 新增发布清单结构，记录产品版本、协议/JSON schema、评价器版本、构建标识、必需文件和指纹。
- 校验项目、结果、报告、CSV、候选模型包的相对资源 ID 和文件存在性。
- 发布清单序列化为稳定 JSON，禁止绝对路径和非有限数字。

## S85：发布文档和用户验收证据

- 更新架构、README、变更记录、已知限制和验收命令。
- 记录固定种子复现方式、性能预算解释、历史报告读取规则和发布前清理要求。

## S86：Phase 8 CTest 发布门

- 注册 model-only、性能、资源安全、报告发布和 GUI 集成测试。
- 在 Windows 下逐个绝对路径 executable 运行，执行 `git diff --check`，确认工作树干净。
- 只有全部门通过后才允许声明 Phase 8 完成。
