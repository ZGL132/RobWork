# 机械臂结构尺寸优化插件分阶段实施计划

> **适用对象：** 后续按任务接力实施的智能体和研发工程师。每个任务必须在独立提交中完成，并在交接记录中写明提交号、执行命令、测试结果、剩余风险和输入输出变更。

**目标：** 在已有“运动学结构尺寸优化”实现的基础上，先完成可交付的首版工作流，再逐步演进为可插拔的机器人系统工程优化平台。平台将按“运动学 -> 轨迹 -> 动力学 -> 驱动选型”的依赖顺序扩展，不允许把未来领域公式直接耦合进现有优化器或 UI。

**实施原则：**

- 一个阶段只交付可独立验收的能力；未通过验收不得开始下一阶段。
- 所有评价器只计算领域指标、约束、告警和工件；优化器只负责候选生成、调度、筛选、局部精修与排序。
- 硬约束失败始终排在可行方案之后；评价失败、评价器缺失、输入不足与物理不可行必须区分。
- 新的指标、变量、评价器、报告字段均使用稳定 ID 和版本化 JSON，不以 UI 显示文字作为协议。
- 每个智能体只认领一个任务，不顺带重构其他阶段的代码；禁止清理或覆盖已有用户改动。

## 1. 当前基线（2026-07-27）

### 已具备且应复用的能力

| 能力 | 当前实现位置 | 结论 |
| --- | --- | --- |
| 完整机器人模型 JSON | `robotmodelbuilder/RobotModelSpecJson.*`、`robotanalysiscore/RobotAnalysisJson.cpp` | 已具备，可作为优化任务模型快照基础。 |
| 无 UI 的运动学分析核心 | `kinematicanalysis/KinematicAnalyzer.*`、`sdurws_kinematicanalysis_core` | 已拆出核心组件，结构优化器已直接依赖它。 |
| 结构优化核心 | `structureoptimizer/StructureDesignMutator.*`、`CandidateModelFactory.*`、`StructureCandidateEvaluator.*`、`StructureObjectiveScorer.*` | 已具备结构变异、临时 WorkCell、IK/碰撞/工作空间评价和固定六项评分。 |
| 搜索与鲁棒性 | `StructureCandidateGenerator.*`、`HybridStructureOptimizer.*`、`StructureSensitivityAnalyzer.*` | 已具备 Random、Grid、LHS Hybrid、精英复核、坐标局部搜索和正负步长灵敏度。 |
| 任务控制和 UI 骨架 | `StructureOptimizationController.*`、`StructureOptimizerWidget.*`、三个表模型、插件入口 | 已具备 QtConcurrent 单 worker 运行、暂停/取消、五页签骨架和静态插件注册。 |
| 基础测试与导出 | `StructureOptimizationTest.cpp`、JSON/CSV/XML 导出器 | 已覆盖算法、模型工厂、缓存、控制器和部分 UI 状态。 |

### 已确认的缺口

1. 当前评分和约束模型仍以结构优化专用类型和六个固定评分项为中心，尚未提供系统级统一指标字典、通用目标项和评价器接口。
2. `StructureCandidateEvaluator` 直接依赖 `KinematicAnalyzer`，还不是可注册的 `KinematicEngineeringEvaluator`。
3. 轨迹、动力学、驱动选型、离散产品变量、Pareto 多目标和并行评价尚未实现。
4. 当前插件的“项目适配、完整编辑绑定、隔离预览、统一报告导出”需要按 `2026-07-24-structure-optimizer-completion.md` 补齐并回归验证。
5. 当前 Debug 构建重新配置后在链接 `sdurw_core` 时因缺少 `synchronization.lib` 失败；在该构建环境恢复前，不能宣称回归基线通过。

## 2. 阶段总览与准入关系

| 阶段 | 名称 | 主要交付 | 前置条件 |
| --- | --- | --- | --- |
| P0 | 构建基线与首版工作流封板 | 可运行、可编辑、可预览、可导出的运动学结构优化插件 | 无 |
| P1 | 系统工程优化公共契约 | 通用评价器、指标、目标约束、工件和缓存协议 | P0 |
| P2 | 运动学评价器迁移与优化器升级 | 可插拔运动学评价器和 `SystemEngineeringOptimizer` | P1 |
| P3 | 轨迹评价与联合优化 | 路径可行性、节拍、路径碰撞、轨迹工件 | P2 |

## 3. P0：构建基线与首版工作流封板

**阶段目标：** 让已有首版从“已有核心和界面骨架”成为工程师可以完整使用、结果可复现的插件。P0 不新增轨迹、动力学或选型公式。

### P0-T1：恢复并固定构建验证环境

- **输入：** 当前 `build/Desktop_Qt_6_11_1_MSVC2022_64bit-Debug`，MSVC、Qt、vcpkg 和 RobWork 依赖。
- **实施：** 定位 `synchronization.lib` 的来源和缺失原因；统一 MSVC 初始化脚本、依赖目录和 CMake 配置；禁止通过复制未知库文件绕过问题。
- **输出：** 可复制的构建前置说明和已验证命令。
- **验收：** 成功构建并运行 `sdurws_robotmodelbuilder_jsontest`、`sdurws_robotanalysiscore_test`、`sdurws_kinematicanalysis_test`、`sdurws_structureoptimizer_test`。
- **交接条件：** 记录完整构建命令、工具链版本和 CTest 输出摘要。

### P0-T2：审计并补齐问题编辑和项目工作流

- **关联计划：** 直接落实 `2026-07-24-structure-optimizer-completion.md` 的 Task 2 和 Task 3。
- **文件：** 新建 `StructureConstraintTableModel.*`、`StructureOptimizationProjectAdapter.*`；修改 `StructureOptimizerWidget.*`、表模型、插件入口、CMake 和测试。
- **实施：** 完整双向绑定变量、任务、约束、权重和全部 `RunConfig`；支持打开/保存 `*.structure-optimization.json`；拒绝缺少完整 `RobotModelSpec` 的项目，不从裸 WorkCell 猜测模型规格。
- **验收：** 非默认策略、约束、权重、随机种子和模型快照往返后逐字段一致；运行期间问题编辑锁定；无效项目显示稳定错误码。

### P0-T3：候选比较、隔离预览和导出封板

- **关联计划：** 继续落实 `2026-07-24-structure-optimizer-completion.md` 的 Task 4 至 Task 7。
- **文件：** 新建 `CandidatePreviewController.*`、`StructureOptimizationExportService.*`、`StructureOptimizationReportWriter.*`；修改候选表、widget、plugin、测试和 README。
- **实施：** 按候选稳定索引而不是排序行号进行预览；临时 WorkCell 预览失败不得改变源 WorkCell；导出项目、结果、CSV、Markdown 报告和可行候选 XML 包；文本输出使用原子写入。
- **验收：** 基线差值正确、不可行候选不可导出模型、关闭预览能恢复原工作单元、冲突/取消/失败不留下半成品文件。

### P0-T4：首版发布回归与用户验收

- **实施：** 使用一个六轴样机和一个带碰撞障碍的任务集，执行 Random、Grid、Hybrid 三种策略；固定随机种子重复执行；检查暂停、取消、恢复、导入、预览和导出。
- **验收：** 同输入同种子输出相同候选顺序和结果；必达点不可达或碰撞的候选不优于可行候选；报告可定位变量、指标、约束失败原因和输入快照。
- **发布物：** 用户操作说明、示例项目、测试证据和已知限制清单。

## 4. P1：系统工程优化公共契约

**阶段目标：** 建立可容纳运动学、轨迹、动力学和选型的领域接口，不改变 P0 对用户承诺的计算结果。

### P1-T1：创建共享工程评价模型

- **文件：** 在 `robotanalysiscore` 新建 `EngineeringEvaluationTypes.hpp/.cpp`、`EngineeringMetricRegistry.hpp/.cpp`、`IEngineeringEvaluator.hpp`、对应测试和 CMake 注册。
- **实施：** 定义 `CandidateEvaluationContext`、`EvaluationRequest`、`EngineeringEvaluationResult`、`EngineeringMetric`、`EngineeringConstraintResult`、`EngineeringArtifact`、状态与错误码；注册稳定指标 ID、单位和分组。
- **验收：** 指标 ID 重复、未知指标、单位冲突、非有限数值和版本不兼容均被拒绝；结果可 JSON 往返且未知扩展字段可忽略。

### P1-T2：目标、约束和变量模型泛化

- **文件：** 新建或扩展 `EngineeringOptimizationTypes.*`；适配 `StructureOptimizationTypes.hpp`、JSON、CSV、验证器和测试。
- **实施：** 以 `ObjectiveTerm(metricId, direction, normalization, weight)` 和 `ConstraintRule(metricId, operator, threshold, hard)` 替换固定六分项的内部协议；变量定义支持连续、整数、离散枚举，但 P1 只允许连续变量进入实际搜索。
- **兼容性：** 旧版六权重配置必须迁移为等价的六个目标项；旧项目可加载、保存后升级为新 schema。
- **验收：** 固定输入下，旧版与迁移后的运动学结果、可行性和排序等价；整数/枚举变量在未启用搜索策略时得到明确“暂不支持”错误。

### P1-T3：工件、缓存和可追溯协议

- **文件：** 扩展候选缓存、结果 JSON、报告 writer 和测试。
- **实施：** 缓存键包含量化变量、模型哈希、任务环境哈希、评价器 ID/版本和配置哈希；工件按评价器输出保存引用或可序列化摘要；记录耗时和输入快照哈希。
- **验收：** 修改动力学配置不能错误复用旧结果；仅修改选型配置时可以复用先前的运动学工件；报告可列出每个指标的提供者和版本。

## 5. P2：运动学评价器迁移与优化器升级

**阶段目标：** 将现有首版算法保留为第一个评价器实现，优化器从结构专用调度升级为可组合评价链调度。

### P2-T1：实现 `KinematicEngineeringEvaluator`

- **文件：** 新建 `KinematicEngineeringEvaluator.*`；将 `StructureCandidateEvaluator.*` 收缩为兼容适配层或删除；更新核心 CMake 与测试。
- **实施：** 调用 `sdurws_kinematicanalysis_core`，输出 `kinematics.reachability.weighted`、操纵度 P10、关节裕度、工作空间覆盖、碰撞最小间隙、IK 解集等统一结果和工件。
- **验收：** 与 P0 同一基准任务相比，关键原始指标一致；运动学失败以 `Infeasible` 返回，不抛出未处理异常。

### P2-T2：实现评价器管线和系统调度器

- **文件：** 新建 `SystemEngineeringOptimizer.*`、`EngineeringEvaluatorPipeline.*`；保留 `HybridStructureOptimizer` 为兼容包装或迁移实现。
- **实施：** 按能力和前置工件排序评价器；候选生成后依次执行结构变异、模型工厂、评价器链、统一约束与目标评分；支持 Quick/Verified 两级请求。
- **关键规则：** 精英选择采用“可行性 + 代理得分 + 最小变量距离多样性”，不得只按运动学总分 Top N；局部搜索必须基于当前启用的完整评价链。
- **验收：** 只注册运动学评价器时，结果与 P0 兼容；添加 fake 第二评价器后，评价顺序、约束合并和工件传递符合契约。

### P2-T3：首版系统化回归与迁移发布

- **实施：** 导入 P0 项目，迁移至新 schema，执行优化并导出；验证缓存命中、取消、失败诊断、报告和旧数据加载。
- **验收：** P0 示例项目无需人工修改即可运行；新报告中能清晰区分“运动学最优”和“系统评价器未启用”。

## 6. P3：轨迹评价与联合优化

**阶段目标：** 将“离散点可达”升级为“工艺路径可实际执行”。

### P3-T1：轨迹任务与路径数据模型

- **文件：** 新建 `robotanalysiscore/TrajectoryTaskTypes.*`、轨迹 JSON schema、编辑模型和测试。
- **实施：** 支持路径点、参考坐标系、TCP、速度/加速度/加加速度限制、停靠点、载荷切换和最小安全间隙；任务点与轨迹任务可以共存。
- **验收：** 轨迹 JSON 往返；非法参考帧、缺失 TCP、空路径和不连续时间约束均被拒绝。

### P3-T2：实现 `TrajectoryEvaluator`

- **文件：** 新建 `trajectoryanalysis` 核心组件及 `TrajectoryEngineeringEvaluator.*`；不得放入结构优化 UI。
- **实施：** 利用运动学评价器输出的 IK 候选进行连续解选择，完成路径插补、关节连续性校验、路径碰撞检查和节拍计算；输出轨迹工件。
- **验收：** 覆盖“点可达但路径不可行”“可行但越过关节限制”“路径近碰撞”“多 IK 分支连续选择”四类测试。

### P3-T3：接入优化和 UI

- **实施：** 将轨迹可行性和最小间隙设为可配置硬约束，周期时间设为软目标；在 UI 中增加路径任务编辑和候选轨迹摘要，避免在表格中展示整段时序数据。
- **验收：** 启用轨迹评价后，离散点可达但路径不通的候选被淘汰；局部精修不会以只改善运动学分数的方式接受该候选。

## 7. P4：动力学评价与负载闭环

**阶段目标：** 基于已验证轨迹计算真实关节载荷，建立结构尺寸、质量惯量和执行性能的闭环。

### P4-T1：质量与载荷数据契约

- **文件：** 扩展 `RobotModelSpec` 关联的质量、质心、惯量、末端负载和外部力配置；新增动态任务 JSON 与验证器。
- **实施：** 明确单位、参考坐标系和缺失值策略。未提供可信质量参数时，动力学评价器必须返回“数据不足”，不能使用隐含常数给出伪精确结果。
- **验收：** 质量、质心、惯量坐标变换和载荷切换具有单元测试；输入不完整的错误码稳定。

### P4-T2：实现 `DynamicsEvaluator`

- **文件：** 建立 `dynamicsanalysis_core` 和 `DynamicsEngineeringEvaluator.*`，或复用已有经过验证的 RobWork 动力学能力。
- **实施：** 消费 P3 轨迹工件，输出关节位置、速度、加速度、峰值/RMS 力矩、功率和周期能耗时序；提供抽样精度和计算预算配置。
- **验收：** 用解析或可信基准模型验证重力项、惯性项和峰值时序；轨迹未就绪时评价器拒绝执行。

### P4-T3：接入系统评分与报告

- **实施：** 支持 `dynamics.torque_peak_ratio`、`dynamics.velocity_peak_ratio` 和 `dynamics.energy_per_cycle` 的目标/约束；候选详情支持摘要与时序工件链接。
- **验收：** 力矩超限方案被判定不可行；仅优化运动学的设置明确提示没有动力学保证；缓存可复用同一轨迹时序。

## 8. P5：驱动选型与混合变量优化

**阶段目标：** 在满足轨迹和动力学约束的前提下，联合优化结构尺寸与电机/减速器选择。

### P5-T1：驱动产品库与选型规则

- **文件：** 新建 `driveselectioncore`，定义版本化产品库、额定参数、热模型、组合规则、成本和供货状态；导入导出与测试独立于 UI。
- **实施：** 计算电机连续/峰值转矩、转速、热余量、惯量匹配，减速器转矩/速度/寿命/背隙余量。
- **验收：** 已知电机减速器组合的可行性与余量可复算；产品库版本变更会使缓存失效。

### P5-T2：实现 `DriveSelectionEvaluator`

- **实施：** 消费动力学时序，为每轴搜索可行驱动组合，输出 `drive.selection.feasible`、热余量、减速器余量、成本、质量和推荐组合工件。
- **验收：** “无可行组合”是硬约束失败；多组可行组合按配置的成本/裕度策略稳定排序。

### P5-T3：实现混合连续-离散搜索

- **文件：** 扩展候选生成器、缓存、局部搜索和 UI 变量编辑器。
- **实施：** 连续尺寸使用 LHS 与局部步长搜索；枚举产品使用受限组合生成或分层搜索；变量量化和去重覆盖混合向量。
- **验收：** 相同种子下混合搜索可重现；枚举变量不被坐标搜索当作浮点数扰动；局部搜索使用全链目标和硬约束。

## 9. P6：高级系统工程优化

**阶段目标：** 解决多目标权衡、制造鲁棒性和大规模计算需求。

### P6-T1：Pareto 与决策配置

- **实施：** 增加非支配排序、拥挤度和 Pareto 前沿结果；保留加权单目标模式，避免强制所有用户理解多目标算法。
- **验收：** 测试数据上的 Pareto 层级正确；UI 可以比较而不混淆“第一名”和“折中方案”。

### P6-T2：鲁棒优化

- **实施：** 将 P0 已有正负一步灵敏度升级为可配置公差样本和最坏情形/分位数目标；支持制造偏差、负载偏差与摩擦参数偏差。
- **验收：** 同一标称最优方案可根据鲁棒性规则被重新排序；报告提供风险变量和建议公差。

### P6-T3：性能和并行化

- **实施：** 在评价器无共享可变状态、缓存键完备、结果合并稳定后，支持并行候选评价；保持固定种子下结果稳定，进度与取消线程安全。
- **验收：** 单 worker 与多 worker 的候选集、最终排序和报告一致；压力测试无 WorkCell 泄漏、竞态或缓存污染。

## 10. 每个任务的强制实施模板

每个智能体领取任务时按以下顺序执行：

1. 阅读本计划、前置阶段验收记录和相关接口；运行 `git status --short`，记录非本任务改动。
2. 先写覆盖目标行为的失败测试，确认失败原因与任务一致。
3. 做最小实现，不引入下一阶段能力或兼容层之外的重构。
4. 运行目标测试、相关模块 CTest 和必要的人工插件验收。
5. 更新接口文档、JSON schema、指标字典或示例项目；未完成项必须写入交接记录。
6. 单任务单提交。提交前检查 diff，不包含构建产物、临时 WorkCell、用户文件或无关格式化。

交接记录固定包含：任务编号、提交号、输入/输出契约变更、执行的测试、结果、已知风险、下一任务的前置条件。
