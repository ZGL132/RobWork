## 2. 第一条研发案例与场景库

所有案例固定模型来源、软件版本、策略、配置、器件目录版本、线程数、随机种子、输入快照与参考数据。基线资产只读，改型产生独立方案与新修订。实际机型参数、厂商曲线和实测容差由数据负责人确认；缺失时先做解析和合成验证，不编造厂商或实测数据。

| 场景 | 工程师要完成的任务 | 核验重点 |
| --- | --- | --- |
| S1 六轴基线重建 | 导入已有机型，核对零位、尺寸、轴向、TCP、物性与目录 | 导入补全清单、单位/坐标系、物性来源、一般关节姿态 FK |
| S2 工作范围改型 | 修改臂长或基座姿态，满足新工位和区域覆盖需求 | 可达性、关节裕量、碰撞、结果失效范围、方案差异 |
| S3 工具与负载改型 | 修改工具质量、质心、惯量和负载工况 | 重力方向、力矩峰值/RMS、驻留、器件裕量、重复计入 |
| S4 节拍提升 | 缩短任务循环、修改速度/加速度限制 | 连续性、段内碰撞、动力负荷、热负荷、时间与曲线联动 |
| S5 器件替换 | 对比两个电机/减速器组合并应用其一 | 正反转/驱动制动、曲线范围、淘汰原因、回填后必须复算 |
| S6 设计对比 | 基线与两个改型比较、采用候选、输出报告 | 同工况/同策略比较、八项指标可算性、基线不变、取舍依据 |
| S7 数据不足与失败恢复 | 缺惯量/网格/效率数据，失败后修复并重算 | DataInsufficient、定位与修复动作、旧证据保留、不虚假通过 |
| S8 并发与持久化 | 运行中取消、切换项目、保存失败、检查点恢复 | 迟到结果归属、事务完整、进度/统计不重复、恢复状态真实 |

第一轮主线顺序为 S1→S2→S3→S4→S5→S6。S7/S8 是必须伴随的反例，不另做一个“只有成功路径”的演示项目。七轴、混合链、耦合与连续工艺在对应功能验收之后加入扩展回归；4/5 轴产品化不在打磨范围。

## 3. 计算正确性的验证方法

### 3.1 每个关键算法建立四层证据

1. 解析或独立参考：预期值不调用被测产品函数，不与产品共享同一变换链、坐标转换或公式封装。RobWork 与产品共享链规范时，二者互比只证明适配一致，不能单独证明模型正确。
2. 数学/物理性质：坐标变换不变量、虚功、功率、能量与量纲核对。每项性质明确适用条件，不能把“负载增大则所有时刻力矩单调增大”这类错误直觉作为断言。
3. 非标与边界：非零 DH 长度、非零偏置/扭角、一般姿态、近奇异、限位、多解、近零、NaN/Inf、输入缺失、工况不齐和方向反转。
4. 真实装配端到端：由产品命令入口产生快照，经实际评估器、结果接纳、界面显示和报告输出核对，替身测试只补充覆盖。

### 3.2 不改变既有数值标准

- FK/编译链位置与姿态等价按附录 D 第 4 项：1e-9 m / 1e-9 rad。
- IK 默认残差按第 1/2 项：1e-6 m / 1e-6 rad；多解在关节空间逐轴去重，不以末端位姿去重。
- 解析/独立参考按第 9 项：相对 1e-9，加逐例声明的绝对容差；比较逐元素，参考接近零时仍有明确判据。
- 并行归约按第 8 项相对 1e-12；速度/加速度校核按第 10 项。每例都区分计算对照容差和产品运行校验容差。
- 惯量对称性按相对容差，SPD 特征值严格大于零；不得用放宽阈值或静默修正掩盖错误输入。
- 碰撞细分步长、预算与代表点集沿用冻结的 P-06；采样复检不宣称连续时间碰撞的数学完备证明。
- 鲁棒性判定沿用 P-04；仍未冻结的通过线/降级线及待裁决语义不能由实现者自设。

### 3.3 重点算例

| 领域 | 独立对照/性质 | 必须观察的错误模式 |
| --- | --- | --- |
| 变换与 FK | 手工构造 SE(3) 乘积，二维两杆解析位置，完整六轴一般姿态 | 零位对、运动后错；DH 与显式两侧同错；TCP/基座变换漏乘 |
| IK 与覆盖 | 已知构型生成任务，再对每个解独立 FK 回代；已知多解与固定覆盖计数 | 搜索未果冒充不可达；错误构型合并；数据不足被移出分母 |
| 轨迹 | 简化运动解析曲线与限制检查；端点无碰撞但段内碰撞案例 | 漏任务点/驻留；插值跳变；平滑后未复检；预算耗尽仍通过 |
| 动力学 | 定义轴向与角度零点的单摆静态重力矩；简化链独立方程；功率/能量核对 | 重力坐标错误、惯量移轴错误、驻留遗漏、摩擦非有限污染 |
| 传动 | Δq_joint=C·Δθ_motor；τ_motor=Cᵀ·τ_joint；同一坐标约定下虚功相等 | 转置/逆矩阵误用；惯量双计；效率在驱动/制动方向错误使用 |
| 选型 | 手算工作点与厂商曲线逐点对照，包括曲线端点和范围外 | 负工作点绕过限值；多工况串值；缺效率/峰值数据仍可行 |
| 优化 | 小变量空间穷举参考可行集/Pareto 集，Quick→Verified 真实合并结果 | Quick 被当正式证据；误淘汰；采用取错记录；恢复重复统计 |

简化链解析算例可在模型级夹具运行，不因此放开产品不支持的链型。真实机型端到端仍使用当前已批准链型。

## 6. 每个修复任务的固定实施步骤

1. **立卡**：标明复现 SHA/输入、需求 ID/AT、单元职责、改动允许面、前置、验收方法；建议、需求变更与既有实现缺陷分开登记。
2. **复现**：先在当前冻结 SHA 跑最小失败用例或记录真实 GUI 失败；沿调用链确认问题位于算法、输入、装配还是呈现。
3. **独立预期**：写清公式、单位、参考系、符号、数据来源和容差；没有独立参考时注明证据边界，不用当前输出直接充当真值。
4. **补回归**：对计算/状态缺陷建立能确实翻红的行为测试；纯布局/文案修改采用定向人工或现有 GUI 验证，不写镜像实现的测试。
5. **小步修复**：只改已确认根因；公共接口契约与详细中文注释同步；不复制别的单元权威逻辑、不增加未登记依赖。
6. **验证**：双模式构建、相关模型/契约测试、架构门禁、文档/任务验证和所属 S 场景复测；记录 XML、JSON、日志和必要截图。
7. **提交与送验**：四段式中文 commit，推 origin 任务分支；发出任务 ID、base..head、40 位冻结 SHA 和证据位置。
8. **独立验收**：全新上下文按协议 4.1～4.11 复测；至少两处失败能力抽验；失败写不可变记录，返工后全量重验。
9. **合入与消账**：所有者决策合入 redesign-main；主线复测受影响场景；同步契约、矩阵和 findings；核对远程，不把本地完成当交付。

## 7. 验证执行与证据组织

现有脚本入口（以仓库根为工作目录，执行时使用实际环境与契约）：

```powershell
pwsh -File RobWork/scripts/industrialrobot/validate-docs.ps1
cmake --build build --config Release --target ird_gates
```

每批的双模式及全部测试使用 `gate-all.ps1`，正式运行前核对其 Qt/工具链/Python/DLL 前置、超时与 SKIP 口径；新鲜构建树使用源码树 ini 模板，worktree 显式传主仓 vcpkg toolchain 绝对路径。脚本成功退出不替代逐项证据检查。

Windows Qt Widgets/GUI 测试必须在 VS x64 developer 环境运行，设置 `$env:QT_QPA_PLATFORM='windows'`，一次使用绝对路径启动一个测试 executable。不使用 offscreen，不合并 Widget/Meta executables。平台插件异常时停受影响进程、检查继承 QT_*/QML_* 环境后再按规则重启。模型 QCoreApplication 测试不要求 GUI 插件。

建议证据在现有 `traceability/` 内按最终 canonical 任务 ID 组织，并由契约纳入允许面：

- 审查表：需求/接口/公式/关键调用点/已有用例/新增反例/结论与证据。
- 缺陷：复现输入、SHA、严重程度、影响链、根因、修复 SHA、验收记录、消账证据。
- 数值：参考来源、坐标系与量纲、参数、逐项实际/参考/误差/容差、近零与异常结果。
- 交互：任务脚本、起始项目、步骤、成功判据、操作证据、受助情况、时间和误操作。
- 每次执行：40 位 SHA、组件版本、输入身份、策略、配置、线程/种子、测试命令、退出码、PASS/FAIL/SKIP 与报告文件。

不要建立第二份独立“缺陷真账”；新问题继续使用 findings.json 与任务/验收记录，新增视图是汇总而非权威替代。历史 audit/ 为未跟踪资产，证据使用前核对 SHA/来源，需长期保存者按契约转入规范目录。

## 8. 退出标准、组织与排期

### 8.1 现有硬标准

- 关键计算满足 REQUIREMENTS 附录 D；解析/独立参考与适用 AT 有可复现证据，不能仅比较两套共享错误的实现。
- 主界面与正式报告结论能追溯输入快照、策略、工况与结果，数据不足、过期、预览不伪装正式通过。
- NFR-PERF-01：交互 P95≤200 ms，无超过 2 s 无响应窗口；PERF-02：2 s 内进入 Canceling 停派发、普通批次 10 s 内结束。
- PERF-03：5,000 任务点、100,000 采样结果、10,000 候选摘要可加载/保存/分页；PERF-04：合计峰值内存≤物理内存 70%。
- PERF-05：固定候选基准 8 线程中位吞吐≥单线程 4 倍；PERF-06：10,000 Quick＋100 Verified 在 8 小时内完成并可兼容恢复。测量沿现有协议。
- UX：至少 5 名目标用户、主流程完成率≥80%；主动作、公共状态、错误文案、选择与编辑行为按既有需求核验。
- DEL-02：开放 Blocker=0；遗留 Critical 有责任人、影响说明和计划日期。findings 的 blocking/major 等历史等级先做事实与规则映射，不机械等同 DEL 分级。

### 8.2 建议追加的项目质量目标

在正式设计案例涉及的计算范围内，建议不接受尚未解决的已确认数值错误、资格误判或无提示的数据损坏。该目标比简单“测试全绿”更严格；若作为发布门禁采用，由所有者登记，不擅自替代 DEL-02。

每单元都要有已审范围和未审范围，每案例都有成功和失败恢复证据。一次总体审计的覆盖率、一次测试通过数都不能当作“算法无错误”的证明。

### 8.3 组织和建议排期

角色：实施工程师负责复现/修复/自测；独立验收者负责冻结 SHA 复测；机器人算法/机械/驱动专家核对参考物理语义；数据负责人提供模型/目录/实测；目标用户参与任务测试；所有者裁决语义、质量目标与合入。

建议按 6～10 个工作周规划一次首轮打磨，假设核心实现持续投入、验收与专家评审及时、六轴数据可用。B0 完成后按真实缺陷数量重新估算，时间不替代门禁。建议的窗口如下：

| 窗口 | 主工作 | 可见产出 |
| --- | --- | --- |
| 第 1 周 | B0；用户观察；S1 基线 | 基线、历史问题复核、可运行案例、首批修复卡 |
| 第 2～3 周 | B1/B2；同步修复高频操作阻断 | S1/S2/S4 独立数值证据与产品路径 |
| 第 3～5 周 | B3/B4 | S3/S5/S6，选型和优化决策闭环 |
| 第 5～7 周 | B5；B6 代表规模验证 | 统一交互、可解释报告、故障与性能证据 |
| 第 7～10 周 | B6 部署、B7 用户/试点与复核 | 外部环境运行、目标用户达标、交付材料 |

以上窗口有交叠，表示不同专业评审、观察和验证可交错；依赖任务仍顺序放行，共享文件修改串行。真实实测或企业签署暂不可用时，相应验收保持未执行，其他不依赖工作继续。
