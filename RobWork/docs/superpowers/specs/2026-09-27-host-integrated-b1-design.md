## 1. 背景与目标

### 1.1 背景

产品当前存在两条界面形态路线并行推进的事实：

- **方案 A（独立工作台）**：`ui` 单元的 WorkbenchShell 以独立顶层窗口（harness `sdurws_ird_ui_app`）为首选形态宿装五区工作台，宿主插件（`sdurws_ird_ui_plugin`）作为开发期验证通道嵌入 RobWorkStudio；
- **宿主融合（O-38/O-43 裁决链）**：WP-10-T16~T18 已把五区内容装配进 RobWorkStudio 主窗口（多 Dock 拓扑＋宿主状态栏＋宿主菜单），但业务导航仍以插件自持面板为主，尚未确立"谁是主导航、谁是辅助视图"的产品形态。

所有者于 2026-09-27 批准**方案 B.1：宿主融合、项目树主导、渐进迁移**——把"RobWorkStudio 是唯一产品主窗口"从验证形态升格为产品形态承诺，并冻结双树边界与迁移路径。本文是该方案的唯一设计权威；契约与实现与本文冲突时，按 DTB §5.4 偏差登记流程处理，不得代码先行。

### 1.2 目标

1. 冻结产品形态：十三条设计决策（§2）成为后续全部界面任务的验收前提；
2. 冻结双树边界：工业项目树与官方 TreeView 各自承载的对象清单（§3）不得互相越界；
3. 冻结第一版选择联动契约（§4）：明确承诺什么、不承诺什么；
4. 确立渐进迁移路径（§5）：方案 A 面板经 Provider 迁移，不整体推倒重写；
5. 建立可审查的串行迁移任务链（§6）：11 份执行契约，依赖顺序与共享 UI 文件互斥约束入 PIPE 编排。

### 1.3 非目标

- 不修改 `REQUIREMENTS.md` 任何语义（本次是架构与产品形态收口；若实施中发现必须改变需求语义，任务转 blocked 并报告所有者）；
- 不新增框架功能、不修改 RobWork/RWS 框架源码（SA-02 红线不变）；
- 不在本批次实现 trajectory/dynamics/selection/optimization 等尚未产出单元卡的域迁移（其插件尚未落位，无迁移对象）；
- 不推翻 SA-01 静态白名单装配口径（WP-24-T03 的产品交付路径不变）。

## 2. 十三条设计决策（产品形态冻结）

以下十三条为**产品形态验收前提**。每条标注机制承载与既有决策的关系；契约 acceptance 必须可对照核查。

| # | 决策 | 机制承载与说明 |
| --- | --- | --- |
| D1 | **RobWorkStudio 是唯一产品主窗口** | 宿主主窗口承载菜单栏/状态栏/Dock 管理/中央区；产品不再存在第二顶层主窗口。harness（`_app`）降格为纯开发验证通道，不属产品交付路径（SA-01 口径不变）。承接 O-43 已裁决的宿主融合方向并升格为终态承诺 |
| D2 | **ui 平台能力转为宿主内部控制器** | WorkbenchShell 不再以"顶层窗口"为产品形态：ui 单元的命令注册表/快捷键权威（SA-16）、状态投影（UX-10 七态）、会话状态机（§5.2）、DraftController 等平台能力，作为**宿主 Dock 内的控制器簇**存在；其 Dock 拓扑已由 UI-T18 落位（主 Dock＋属性右 Dock＋任务底 Dock），本条冻结该形态为终态 |
| D3 | **工业项目树是业务主导航** | 项目树（IndustrialProjectTree）承载业务对象导航（清单见 §3.1），是用户在业务对象间移动的第一入口；选择服务（SelectionService）是业务选择的唯一汇聚点 |
| D4 | **官方 TreeView 是已应用 WorkCell 的辅助运行时树** | 框架 TreeView 只呈现**已应用**（编译后）WorkCell 的运行时结构（清单见 §3.2）；它是三维场景结构的辅助检查视图，不是业务导航入口，不承载业务对象 |
| D5 | **共享属性检查器呈现常用字段** | 属性检查器（PropertyInspector）为全域共享面板（宿主右 Dock），呈现当前选中对象的常用编辑字段；它是唯一跨域属性呈现面，域私有大批量编辑不在此展开 |
| D6 | **复杂编辑进入复杂编辑页面** | DH 参数、物性、区域定义、导入向导、求解配置等复杂编辑收口到各域**复杂编辑页面**（域面板内的编辑视图/对话框），不经共享属性检查器展开大批量字段（UX-04/05 参数表公共件仍为这些页面的构件） |
| D7 | **RWStudioView3D 是唯一三维视图** | 三维呈现只存在于宿主中央区的 RWStudioView3D（框架组件）；域插件不再创建第二三维视口；失败点/薄弱区/轨迹等渲染数据经渲染适配层投放到该唯一视图（KIN-07 既有口径的形态收口） |
| D8 | **Jog 承载会话姿态，零项目修订** | Jog 面板（关节/笛卡尔点动）修改的仅是 ui 会话态中的会话姿态（KIN-06/ARCH §7.7 口径）：不产生修订、不触发失效、不进入缓存身份；Jog 是会话姿态的第一操作入口 |
| D9 | **Playback 承载 TimedStatePath 播放** | 轨迹/路径回放统一经 Playback 面板消费 TimedStatePath（frame 抓取的时间参数化状态序列）；播放驱动的是运行时状态呈现与会话姿态，不产生修订（TRJ-07 动画语义的宿主形态收口） |
| D10 | **呈现 WorkCell 与计算 RuntimeSnapshot 隔离，复用相同构造规则** | 宿主呈现持有的 WorkCell 视图与评估计算消费的 RuntimeSnapshot 是**两个生命周期独立的对象**（呈现视图不进入运行身份/缓存身份/当前性判定）；但两者必须经**同一内部构造规则**（同一编译链产出/同一 RuntimeNameMap 命名）构造——禁止呈现侧私建第二构造路径（ARC-03/SA-04/SA-05 不变）。详见 §4.4 |
| D11 | **方案 A 面板经 Provider 渐进迁移，不整体推倒重写** | 既有域面板（modeling/requirements/kinematics 插件界面）以 Provider 适配器逐个接入项目树/属性检查器/选择服务；迁移期间旧面板自持区域与新共享设施并存，逐域切换、逐域验收；**禁止"一次性重写全部面板"**（每份迁移契约只覆盖本域） |
| D12 | **框架源码保持零修改** | 宿主融合全部经框架既有扩展点（RobWorkStudioPlugin/IPluginUiRegistrar/Dock 管理/TreeView 事件）实现；任何框架行为缺口走 patches/ 登记流程（SA-02），不得私改 |
| D13 | **ui_plugin 与各 `_app` 过渡期保留为开发验证通道** | `sdurws_ird_ui_plugin`（动态加载验证通道）与各域 `sdurws_ird_<unit>_app`（GUI 手动点验通道，DTB §5.1 v0.20 约定）在迁移期保留；其退役条件见 §5.4——退役本身是 WP-24-T09 的验收内容之一，不得由迁移任务顺手删除 |

**与既有决策的关系**：D1/D2 是 O-43 裁决方向的终态化；D3/D4 冻结 O-38 ③"三维让位"之后的导航分工；D7 重申 UI-T16 落位的"宿主中央 RWStudioView3D 唯一所有三维"；D8/D9 是 ARCH §7.7 会话态规则在宿主形态下的面板级落点；D10 是 ARCH §7.3 编译链唯一性在呈现面的重申（新增的只是"呈现视图与快照生命周期隔离"这一边界）；D11/D13 是迁移治理约定；D12 重申 SA-02。**无任何一条弱化既有 SA-01/SA-02/SA-04/SA-05/SA-16。**

## 3. 双树边界（冻结）

两棵树的节点类型清单为**封闭清单**：新增节点类型必须先修订本表（B1-SPEC 增量修订），不得在实现中私自扩展。

### 3.1 工业项目树（IndustrialProjectTree）——业务主导航（D3）

承载**项目修订数据**（`.rwdesign` 中有 ObjectId 的业务对象与项目结构节点）：

| 分组 | 节点 |
| --- | --- |
| 项目结构 | 项目（projectId）、方案（分支/方案节点）、草稿（draft 状态标记） |
| 建模对象 | RobotDesign 及其关节/连杆/工具/场景/命名位姿等子对象（modeling 域 ObjectId） |
| 需求对象 | 任务点、区域、工况、需求集（requirements 域 ObjectId） |
| 分析配置 | AnalysisConfiguration 及各域分析配置节点（kinematics 求解配置等独立持久化对象） |
| 结果/证据/报告 | 各域结果对象、ResultEnvelope/AnalysisSnapshot 证据节点、ReviewReport 报告节点 |

树节点身份一律为 ObjectId（CON-01）；显示名经名称端口解析（UX-02 工程用语），树自身不缓存第二套命名。

### 3.2 官方 TreeView——辅助运行时树（D4）

承载**已应用 WorkCell 的运行时结构**（编译产物，非项目修订数据）：

| 节点类型 | 说明 |
| --- | --- |
| WorkCell | 已应用工作单元（编译链产物根） |
| Device | 设备（rw::models::Device 派生） |
| Frame | 坐标系框架（含 MovableFrame/FixedFrame 等） |
| Joint | 关节 |
| Drawable | 可绘制几何 |

TreeView 由框架组件承载（RobWorkStudio 既有行为），本产品**不向其注入业务对象节点**、不改造其交互；其刷新时机跟随已应用 WorkCell 的重编译/切换，与项目修订无直接对应。

### 3.3 边界不变量（验收可核查）

- INV-B1：工业项目树中不存在 Frame/Joint/Device/Drawable 等运行时结构节点（运行时结构只在 TreeView/三维视图）；
- INV-B2：官方 TreeView 中不存在项目/方案/草稿/需求/结果等业务节点；
- INV-B3：两树都不持有对方的选中状态；业务选中唯一汇聚点是 SelectionService（§4.1）；
- INV-B4：呈现 WorkCell 重建（重编译/项目切换）后，TreeView 内容与三维场景一致，且不产生项目修订、不改变业务树选中（业务选中对象存在性经 ObjectId 校验后决定保持或置空——失效呈现按 UX 当前性口径，不静默换选）。

## 4. 第一版选择联动规则（冻结）

### 4.1 选择服务（SelectionService）

`ui` 单元新增的唯一业务选择汇聚点：维护"当前选中 ObjectId 集合"（含来源标记：项目树/三维拾取/搜索/命令），广播选择变更事件（⑤事件端口形态）。域 Provider（§5.2）消费选择事件驱动自身高亮/属性呈现；共享属性检查器消费选择事件呈现字段（D5）。三维拾取产生的 ObjectId 反解与名称呈现经 RuntimeNameMap（SA-05，⑥端口），不在选择服务内私建名称映射。

### 4.2 联动契约（第一版承诺）

| # | 联动 | 承诺内容 |
| --- | --- | --- |
| L1 | 项目树选择 → 共享属性检查器 | 项目树选中业务对象后，共享属性检查器**必须**刷新为该对象的常用字段视图（D5；对象不可编辑态/只读态按字段级呈现） |
| L2 | 项目树选择已应用对象 → 三维高亮 | 选中对象若存在已应用 WorkCell 对应物（经 RuntimeNameMap 正向映射存在），**可以**触发三维高亮——"已应用"判定失败的选中（纯草稿/纯结果对象）不产生三维动作，不报错 |
| L3 | TreeView Select Frame → 项目树定位 | 官方 TreeView 显式 Select Frame 事件经 RuntimeNameMap **反解**（运行时名→ObjectId）成功时，项目树**必须**定位并选中对应业务对象；反解失败（框架自建 Frame、无业务对应）时项目树不动、不报错 |
| L4 | 项目树选择 **不** 强制联动 TreeView 树行 | **不承诺**项目树选择后强制选中 TreeView 私有树行（框架 TreeView 的选中 API 与刷新时序属框架私有行为，SA-02 禁止为其打补丁；若后续框架能力允许可在 B1-SPEC 增量修订中升级为承诺） |

### 4.3 呈现 WorkCell 与 RuntimeSnapshot 的隔离与复用（D10 详述）

| 维度 | 呈现 WorkCell（宿主） | 计算 RuntimeSnapshot（execution/worker） |
| --- | --- | --- |
| 生命周期 | 随宿主呈现会话（打开/切换/重编译刷新） | 随任务运行（runId 绑定，迟到归档保护） |
| 身份 | 不进入运行身份/缓存身份/当前性判定 | 五元组身份＋切片依赖（CON-05/06） |
| 构造 | **同一**编译链（CanonicalModel→WorkCell/DWC）同一基座—世界变换（AT-37 单一消费口径） | **同一**编译链同一变换 |
| 命名 | **同一** RuntimeNameMap 双射 | **同一** RuntimeNameMap 双射 |

验收面：呈现侧与计算侧对同一 ObjectId/运行时名的互换解析结果一致（复用 RT-NM 黄金断言形态）；呈现视图的构建与销毁不产生修订、不写缓存（可核查的事件面断言）。

## 5. 渐进迁移策略（D11/D13 详述）

### 5.1 迁移单元与次序

迁移按域串行推进（§6 链序）：**建模 → 需求 → 运动学**（三域插件均已落位；trajectory 及之后域未落位，无迁移对象，天然排除）。每域迁移交付同一组 Provider 接入面：

- **TreeNodesProvider**：向工业项目树供给本域树节点（ObjectId→节点模型）；
- **PropertyPagesProvider**：向共享属性检查器供给本域常用字段页（D5 范围），并声明本域复杂编辑页面入口（D6 范围）；
- **SelectionAdapter**：消费 SelectionService 事件，驱动本域面板高亮/过滤；向选择服务上报本域三维拾取结果。

### 5.2 迁移期间的双形态并存

迁移中每域面板保留既有自持区域（方案 A 形态）直到本域 Provider 验收通过；切换验收点＝本域树节点/属性页/选择联动全部可用且旧自持导航路径标记 deprecated（保留可用）。禁止在迁移提交中删除未迁移域的可用性。

### 5.3 共享 UI 文件互斥（编排红线）

迁移链任务（UI-T21、UI-T22、WP-13-T20、WP-14-T10、WP-15-T18、UI-T23）涉及共享装配面（SelectionService/项目树/属性检查器/宿主装配层）：

- 这些任务**串行领取**（PIPE strictQueueOrder 之外追加的硬约束，登记于 PIPE §6.2）：同一时刻至多一个迁移链任务处于 in-flight；
- 域迁移任务只允许修改本域目录与域契约明确的接缝文件；共享面变更只发生在 UI-T21/UI-T22/UI-T23 三个 ui 任务中；
- 违反互斥的并行实施被验收段直接判 fail（范围越界，ACC 对抗项）。

### 5.4 退役条件（WP-24-T09 的输入）

方案 A 正式产品路径退役（UI-T20 发布桥＋全域迁移完成后）须同时满足：

1. 正式产品装配（WP-24-T08 骨架）以宿主融合形态为唯一装配路径（SA-01 静态白名单不变）；
2. 三域迁移验收全部 pass 且 UI-T23 集成收口 pass；
3. 退役清单（方案 A 顶层窗口路径、deprecated 自持导航、迁移期临时桥接件）逐项登记并经所有者确认；
4. `sdurws_ird_ui_plugin` 动态加载通道与各 `_app` harness 的处置按 D13：**退役决定归 WP-24-T09**，harness 若保留为回归工具则移出产品交付路径声明（DTB §5.1 口径复查）。
