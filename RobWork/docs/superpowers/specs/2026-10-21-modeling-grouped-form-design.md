### 1.1 布局与折叠

- 模式导航、当前目标、单位和底部操作区常驻；中部只有一个纵向滚动区域。导航和目标条在窄窗换行，仍不够时导航横滚；不依赖拉宽结构树露出按钮。
- 表单可用宽度≥560逻辑像素时，XYZ/RPY各排一行；不足560时分量按X、Y、Z或R、P、Y逐行排列。数值编辑器最小可编辑宽度96逻辑像素；这是布局尺寸，不是物理阈值。极窄停靠窗允许内容横滚，禁止裁掉输入和确认操作。
- 所有业务字段均在基础分组中直接呈现；分组默认展开。折叠按模型身份、对象种类和组键保存为会话呈现态；切关节保持相同组布局，重新打开工程恢复正常初态。分组错误时自动展开并定位首个错误。
- 无项目、无选中关节、目标已删除、只读分别给出明确空态/原因。只读保留选择、折叠、单位浏览能力，编辑和提交禁用。
- “更多”承接现有传动、DH/权威转换、几何及物性等入口，不因重排导航移除已有功能。连杆选择显示连杆相关属性/物性/几何，不显示上一关节的编辑值。

### 1.3 类型切换

类型仅改变候选表单，确认前不改工作集。恢复原类型可撤销本轮类型切换；所有待删除/重填项在内联影响区逐项列出。

| 变化 | 必须显式确认的处理 |
| --- | --- |
| Revolute→Continuous | 已有硬限位改为NotApplicable；用户选择“以原上下限作为工作范围”才复制数值，否则工作范围保持未提供；不能自动认定已确认 |
| Continuous→Revolute | 移除已确认工作范围作为当前分析输入；用户明确选择沿用范围作为硬限位或重新填写上下限；不得自动恢复历史硬限位 |
| 角量类型↔Prismatic | 零偏、限位、速度/加速度的量纲变化，原数值仅列为旧值，不作为新量纲值沿用；须重填零偏与限位，速度/加速度可显式保留未提供状态 |
| 可动→Fixed | 明确列出速度/加速度将变为NotApplicable；隐藏运动项不能等于保留可用限值；其它字段遵守现有模型规则 |
| Fixed→可动 | 恢复适用字段的输入入口；缺失轴线/范围以缺项呈现，不制造默认值 |

切类型影响提示必须在最终提交前展示，用户取消时保留原工作集和暂存输入。StandardDH下改为非旋转类型需要先走已有权威转换；不在此绕过DH展开规则。

### 1.4 显示单位与完整字段表单

- 初批标签明确为“当前页显示单位”，长度m/mm、角度rad/deg；仅在基座/工具/场景/命名位姿等实际全部接线并验齐后改为“建模显示单位”，不使用“全局”误导范围。
- 调用core注册单位及ParamEditModel换算。角度选择同时映射角速度、角加速度；长度选择同时映射线速度、线加速度；时间仍为秒。无量纲不参与。
- 有合法暂存值时切单位，SI值和待确认字段集合保持不变；有非法文本时阻止切换、保留文本并定位错误。无修改切单位不脏化，不生成变更记录。
- 所有字段共用一份数值暂存模型；名称/类型暂存在同一个关节编辑会话。两处同时可见时同步回显，但不能因格式化互相触发新编辑。
- 关节页不保留重复参数表或第二写入口；批量粘贴通过焦点字段原生键盘操作完成，全部字段仍走底部整表提交。独立对象列表和只读差异表继续保留其列表语义。
- 未提供字段显示空输入和“未提供”，不显示0；已有值删除文本按“输入不完整”处理，重置可恢复，不借此新增长期字段清除语义。

### 1.5 暂存、确认和三维

本页“确认写入草稿…”首先展开非模态差异区，完整列出改名、类型、数值、字段状态、来源和量纲变化，显示旧值→新值及影响。差异区“确认写入”才执行；“继续编辑”返回输入，保留暂存。“重置输入”回到当前草稿基线，非模板默认值、非工程已发布版本。

确认后一个关节整表作为一次草稿操作，一次局部撤销恢复全部字段与来源。失败保留全部输入及错误，工作集、资源、变更摘要、重演队列、局部撤销栈、项目修订和正式三维均不变。无实际语义变化不产生成功事件或空撤销项。

选择继续驱动已发布对象的三维高亮；编辑输入和确认写草稿都不伪装正式场景已更新。状态明确显示“草稿已修改，正式三维待项目级应用”。仅项目级“应用草稿”成功后场景切换并按稳定ObjectId重新绑定当前选择；失败保留原正式场景。

### 1.6 切对象、刷新和键盘

- 存在未确认输入时，树、三维、模式导航或项目关闭触发同一非模态离开守卫：“确认后切换”“放弃输入并切换”“留在当前对象”。数据非法时第一项不能绕过校验；选择来源恢复/下行定位不得造成回环。
- 目标切换决议前不替换当前编辑会话；临时记录目标选择意图，放弃切换则恢复共享选择与高亮，而不是只恢复树中文字。
- 同目标同基线刷新只更新只读说明，不覆盖暂存。外部草稿基线变化时进入冲突态，保留输入和差异，要求“按新基线重载（丢弃输入）”或“逐项重新确认”；不能悄悄把旧输入写到新对象。
- OID相同但关节顺序改变须重新按OID定位；目标删除、项目/分支更换、只读变更、延迟回调世代过期均拒绝旧提交。
- Tab遵循名称→类型→轴线→位置→姿态→零偏→区间→速度→加速度→操作区；折叠和禁用字段跳过。Enter完成当前字段，不隐式越过差异确认；Esc先退出差异区，不能无提示丢全部输入。

## 2. 接口与实现边界

### 2.1 已核查的现状与不能复用的行为

ModelingPanelWidget.cpp::onJointEditTypeChanged直接提交类型；applyJointDetailEdits分组调用submitJointFieldEdit，拒绝不阻断其他组。每组接受可触发历史记录，不满足“整表一次”。ParamEditModel::confirmApply的void出口仅表示移交，随后乐观推进基线，不表示领域已接受。JointEditField没有名称入口。以上均需改接，不能仅加QGroupBox后宣称完成。

现有applyJointFieldEditBatch是“多关节同字段、部分成功”的公共契约，不修改为整表原子，不用相同方法名承载相反语义。既有旧单字段调用保持兼容。

### 2.2 最小公共扩展提案（实施前精确登记）

仅在modeling/Template.hpp追加独立整表入口与局部结果类型，不改JointEntry、Codec、runtime、存储、现有枚举和端口签名：

```cpp
enum class JointFormEditErrorCode {
    TargetMissing, StaleBaseline, IdentityChanged, UnsupportedFieldChange,
    InvalidLocalName, DuplicateLocalName, InvalidFieldState, FieldRejected
};
struct JointFormEditError {
    JointFormEditErrorCode code;
    std::string fieldKey;
    std::string detail;
    std::optional<JointEditError> fieldError;
};
std::optional<JointFormEditError> applyJointFormEdit(
    ModelingWorkingSet& ws,
    const JointEntry& expected,
    const JointEntry& proposed);
```

这是拟议设计，非已批准实施面；下一批实施前按项目设计流程精确登记Template.hpp、Template.cpp、对应测试和任务契约。错误枚举为局部编辑结果，不擅自注册为跨单元诊断码。正式代码必须补齐中文Doxygen、参数方向、单位及错误契约。

- expected是表单打开时的关节值，proposed是同OID候选；当前草稿目标与expected逐字段比较不一致即StaleBaseline。项目/分支/根身份与表单世代另外由私有会话守卫核对。
- 可变白名单仅localName、type、axis、origin、zeroOffset、bounds、workingRange、maxVelocity、maxAcceleration。objectId不变，dhDerived禁止由此入口修改；不得夹带链重排、连杆或部件修改。
- 仅对实际变化字段执行业务校验，未改的来源和缺供原样保留。新提供值的来源由域入口标为UserProvided，不能信任UI传入DerivedReadOnly等来源。类型转换引起NotApplicable/NotProvided的变化须符合1.3已确认的规则。
- 在候选副本上进行最终类型/区间/字段状态组合核查，避免逐字段检查旧类型造成顺序依赖；复用/抽取Template.cpp现有纯校验内核，禁止复制物理规则到插件。
- 名称字符复用LocalNameValidation.hpp；唯一性/命名空间沿现有modeling→runtime名称构建规则，禁止UI另设一套“所有种类全域重名”规则。改名保持OID、所有OID引用及链序；基于名字的派生映射在发布时重建。
- 接受只交换已验证候选、追加一条整表变更摘要；任何拒绝保持完整工作集相等。无差异返回成功但不追加变更，调用方据候选等价性避免成功通知/历史项。

### 2.3 私有组件

在modeling/plugin拆出JointFormSession.hpp/.cpp（暂存/目标基线/候选及提交结果）和JointGroupedForm.hpp/.cpp（Qt布局、控件、状态及差异展示），避免继续把状态机塞进ModelingPanelWidget.cpp。ModelingPanelWidget仍负责树选择、模式和既有sink接线；ModelingUiModule仍持有工作集及局部历史。

新页直接读取ParamEditModel的pendingChanges/currentValueSi组装候选，确认成功后才setBaseline清理暂存；不走会提前推进基线的confirmApply。字段控件直接绑定唯一模型，任何重复参数视图和独立应用入口均不存在；显示回填由signal blocker和表单世代守卫控制。

整表重演记录须携带目标OID、expected/proposed和组身份；不能将改名遗漏或退化成按旧下标重演。PanelRefresh保留旧PendingEdit兼容轨，新增私有整表轨；新修订重演同样调用applyJointFormEdit，整组成功或阻断手工处理，不部分重演。

### 2.4 已确认的单位注册缺口

当前core/src/Units.cpp注册了m/mm、rad/deg，但速度/加速度只注册SI，尚无mm/s、mm/s^2、deg/s、deg/s^2。完整单位联动不能仅调用现有setDisplayUnitForKind便宣称可用，更不能在插件手写倍乘伪装已注册单位。

拟在core单位表尾追加上述四个符号，量纲分别为LinearVelocity、LinearAcceleration、AngularVelocity、AngularAcceleration，SI因子分别为0.001、0.001、π/180、π/180。既有17项顺序/符号/SI因子保持，无新QuantityKind、公共方法或存储格式；显示上标²仍由界面呈现，机器符号用^2。精确实施面为core/src/Units.cpp、core/test/UnitsTest.cpp和units/core.md，须随GF-A设计门登记T30范围后实施。

新增测试须验证四符号/量纲、SI往返、异量纲拒绝，及原17项语义保持；UI单位联动用真实core换算验证。此项是既有单位权威的字典补齐，不新增跨单元依赖边。

## 3. 失败语义

用户输入错误（非法名称、零轴、非法区间、负速度、缺分量、类型组合冲突）走可定位值结果；错误组自动展开，保留原始文本。目标失效/基线冲突为会话状态拒绝，不丢输入。真实环境失败沿项目既有诊断，不转换成“保存成功”。

线程违约、空装配依赖等编程错误沿既有fail-fast处理；用户从界面可触发的错误不通过异常崩溃表达。领域返回FieldRejected时保留原JointEditError和字段键用于错误定位，不解析中文detail猜错误种类。

候选校验不以整模型Ready为前提：别的连杆物性缺失、其它关节未完成不能阻止修好当前关节。真正的整模型就绪、策略超限确认和双编译继续归项目级应用；不能在表单中自行放行4π阈值等策略。

## 4. 生命周期、权威和其他建模页

Qt控件由父子树持有；JointFormSession由当前建模面板持有，持有编辑意图和打开时的值副本，不作为第二份模型权威。工作集→modeling，修订/写路径→project，正式三维/名称→runtime，单位→core，历史→ModelingUiModule。临时副本不进入存储，不跨项目复用。

延迟销毁的旧页借用模型须活到destroyed；事件必须核对QPointer、目标OID和世代。旧控件退出当前控件树后deleteLater，防止findChild误取旧控件。关闭、历史恢复和应用成功要清理暂存及差异区，不能复活旧输入。

完整建模界面采用同一视觉框架，但不在关节表单一批重写所有领域编辑：

| 模式/对象 | 分组内容 | 原有语义必须保留 |

## 5. 线程与确定性

控件、编辑会话、工作集采纳、局部历史及选择守卫均仅UI线程。无需新worker、后台草稿写入或新的跨单元边。

内部始终SI，差异按字段固定次序（名称→类型→轴线→原点→零偏→区间→速度→加速度）；来源状态显式比较。单位和格式化遵守core，有限性与姿态规则复用领域。数值字符串格式变化不算内容变更；相同旋转的Euler等价表示不得制造姿态差异。最近修改按成功时显示单位记录，切单位不重写历史文字。
