# 轨迹规划交付闭环与交互优化设计

**目标**：修复轨迹审核发现的 8 项问题，使轨迹规划从算法库、正式宿主、交互面到真实三维联动形成可验证闭环。

## 范围

本批覆盖 TRJ-01～TRJ-08 及已解冻的 TRJ-08-S1～S3。保留现有建模、需求和运动学未提交改动，不重写轨迹计算内核已经通过的算法。修复内容分为：正式宿主装配、View3D 服务接线、UI 状态与首屏、4 个算法/诊断缺陷、序列端到端编排、GUI 回归目标。

## 方案

### 宿主装配与三维联动

`DomainPluginAssembly` 增加 trajectory 门面成员和面板取用函数。装配顺序沿现有白名单，在 kinematics 之后注册 trajectory；注册失败按已有域失败隔离语义记录状态。trajectory 面板服务由宿主注入：命令可用性读取统一状态，命令提交进入既有宿主命令登记口，播放帧通过公共 `TrajPlaybackSample` 传给宿主 View3D 适配器。

View3D 适配器只负责把帧中的关节值应用到会话姿态、刷新 TCP/轨迹线图层和失败段定位；计算、碰撞和时间参数化仍留在 trajectory/runtime/policy。没有 View3D 对象时明确显示“未装配”，不伪造三维成功。

### 算法与诊断修复

- UI 命令提交只有 `outcome.accepted == true` 才调用 `commandSubmit`。
- 面板构造完成后立即刷新曲线，保证首屏下拉框和曲线存在。
- CartesianLine 的姿态检查增加 `det(R)` 接近 `+1` 的条件，反射矩阵进入明确失败诊断。
- PTP 请求消费调用方提供的逐轴单位/关节类型；移动轴诊断使用 `m`，转动轴使用 `rad`，不由数值猜测。
- Sequence 编排增加 CartesianLine 规划回调/端口输入，由宿主把每个 approach/retract 的起终点位姿、候选和 IK 服务注入，成功后把段终点构型推进到后续 PTP；缺少编排缝时返回可定位失败素材，不返回空几何的“成功”。

### 交互布局

工作流页按“就绪状态、规划命令、播放定位、最近诊断”分组；命令按钮显示状态原因并在计算中/无输入/只读时禁用。曲线页首屏自动加载位置曲线，关节和通道切换只改变投影。失败诊断显示段号、路径参数和建议动作，并提供“定位到三维”入口；所有 UI 操作仍是投影/查表/命令提交，不在 UI 线程做规划。

## 错误与兼容

旧的 trajectory assembly 描述符和空服务语义保持兼容；新增服务缝默认空。旧序列调用若未提供 CartesianLine 编排缝，返回明确的 `TRJ-NO-PATH`/DataInsufficient 素材，禁止静默产生空几何。旧 PTP 请求默认按转动轴 `rad` 解释，新增逐轴单位字段后由调用方显式覆盖。

## 验证

每个修复先增加能复现原问题的失败测试，再实现最小修复。验证分为：轨迹计算测试、契约测试、宿主装配测试、Windows Qt GUI 测试和真实 View3D 手工证据。自动测试通过不替代正式宿主和三维证据。
