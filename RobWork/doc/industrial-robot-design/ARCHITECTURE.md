## 1. 文档定位、驱动因素与设计原则

### 1.1 在正向设计链中的位置

```
REQUIREMENTS.md          —— 需求语义（是什么、验收什么）
        │
ARCHITECTURE.md（本文）  —— 架构方案（系统由什么组成、边界在哪、机制如何运作）
        │
DETAILED-DESIGN.md       —— 20 单元详设（单元内结构、数据类型、接口签名）
        │
units/*.md ＋ development-task-breakdown.md —— 单元任务卡与任务/构建约定
        │
实现（industrialrobot/ 20 单元，从头构建）
```

### 1.2 架构驱动因素

从需求 §1 产品定位（单位和输入清楚、过程可追溯、结果可解释、失败可恢复、批量计算不阻塞界面、常用操作路径短、报告可复核）与 NFR 家族提炼六个质量属性，作为全部架构决策的检验标准：

| # | 质量属性 | 含义 | 主要需求依据 |
| --- | --- | --- | --- |
| Q1 | 可追溯 | 每项正式结论可定位到输入快照与证据 | CON-01~06、EVI-01/02、NFR-COR-04、RPT-01/03 |
| Q2 | 失败可恢复 | 崩溃/中断不损坏项目，任务可取消可恢复 | NFR-REL-01~03、PM-08、TASK-01~03、NFR-PERF-02 |
| Q3 | 确定性 | 同输入＋版本＋配置＋种子 → 等价结果、稳定排序 | NFR-COR-01/02、OPT-06、ARC-03 |
| Q4 | 响应性 | 批量计算不阻塞界面；>1 s 工作转后台 | NFR-PERF-01~03、UX-10、PM-16 |
| Q5 | 单一权威 | 同一语义（模型真值、名称、策略、单位、文案、命令入口）只有一个所有者 | ARC-01~05、NFR-MNT-03/07、UX-13（M-13） |
| Q6 | 离线安全 | 企业内网离线运行；导入通道有路径/预算/注入防护 | NFR-DEP-01~03、NFR-SEC-01~07 |

### 1.3 设计原则

| # | 原则 | 说明 |
| --- | --- | --- |
| PA-1 | 权威唯一 | 每类影响计算的语义只有一个所有者单元：修订与写路径→project；运动学真值→runtime；名称解析→runtime；共享策略→policy；评估协作→evidence；单位/指标/诊断文案→core/diagnostics；命令入口与快捷键→ui（§7.11） |
| PA-2 | 不可变历史 | 修订只增不改；撤销/重做产生新修订（PM-18）；旧结果保留为原快照的历史证据（CON-02） |
| PA-3 | 一切计算经快照 | 评估只消费完整不可变快照（CON-01），插件不直接读写对方的活对象 |
| PA-4 | 端口先行 | 跨单元协作只经六类稳定端口（§7.2），构建红线强制（§3.2） |
| PA-5 | 计算与界面分离 | 计算内核零 Qt 依赖；界面只消费只读投影与会话态（NFR-MNT-01）；命令服务不直接依赖 Widgets——交互确认经命令上下文回调解耦（§7.1，SA-15） |
| PA-6 | 框架为基线、不作分叉 | RobWork/RobWorkStudio/RobWorkSim 零源码修改，确需修改走集中补丁登记（§5，SA-02） |
| PA-7 | 架构一次成型、分期启用 | R1/R2 全量范围共用同一架构；R2 能力（MDL-18/21、KIN-09~11、SEL-09-S1/MDL-12-S1、TRJ-08-S1~S3、OPT-D、PM 分期子项）在既有单元内扩展，不新增架构机制（§10.2 核对表） |

### 1.4 命名与引用约定

- 需求条目引用 `REQUIREMENTS.md` 的 ID（如 ARC-01、AT-18）；本文不重定义、不收窄、不扩大其语义。需求附录引用按 v1.8 起编号：附录 A（旧代码功能级台账）、附录 B（旧功能处置三分类）、附录 C（待冻结前置）；附录 D（数值容差汇总表）按 v1.13 起存在（P-01 冻结产物），正文 §7.6 等已引用。
- 架构决策编号 `SA-xx`，正文定义于所属章节，登记册见 §9。既有工件已引用的编号保持不变（`patches/PATCHES.md` 引用 §5〔SA-02〕）。
- 构建目标命名沿用骨架：库目标 `sdurws_ird_<unit>`，别名 `RWS::ird::<unit>`；插件/测试/工作进程目标 `sdurws_ird_<unit>_plugin / _test / _contract_test / _worker` 随单元任务卡登记，骨架不预建空目标。

### 2.3 分层总图与层规则

```
L5  应用壳层      RobWorkStudioApp 启动流程 ＋ WorkbenchShell（ui）＋ 静态插件装配
L4  业务插件层    modeling │ requirements │ kinematics │ trajectory │ dynamics
                  selection │ optimization │ workflow（编排）        ＋ 各插件自己的界面目标
L3  平台服务层    project │ execution │ io │ reporting │ diagnostics │ ui（界面支撑）
L2  计算内核层    core │ evidence │ policy │ runtime │ drivetrain(共享计算服务)
                  ＋ 各业务单元的"计算库"部分（ird_<unit> 本体，零 Qt）
L1  框架基线      RobWork(rw) │ RobWorkSim(rwsim) │ RobWorkStudio(rws) │ Qt │ 第三方
```

| 层 | 允许依赖 | Qt 约束 | 说明 |
| --- | --- | --- | --- |
| L5 应用壳 | L4/L3/L1 | Widgets 允许 | 启动、装配、白名单注册（PM-17） |
| L4 业务插件 | L3/L2/L1；**彼此互链禁止** | 插件界面目标可用 Widgets；计算库目标零 Qt | 跨业务协作只经端口（§7.2） |
| L3 平台服务 | L2/L1；**同层允许有向依赖**（按 §3.5 单元依赖表，禁止环、仅经公共接口——A3 处置） | 允许 Qt Core/Gui；**禁 Widgets**（ui 单元唯一例外） | 磁盘、进程、渲染、装配等系统服务 |
| L2 计算内核 | L1 的 RobWork 数学/运动学类型；**零 Qt** | 禁止一切 Qt 模块 | 可被模型测试直接调用（NFR-MNT-01） |
| L1 框架基线 | — | — | 冻结版本基线（NFR-DEP-05），零源码修改（SA-02） |

### 3.2 依赖规则与四条构建红线（SA-10）

依赖方向只允许"上层→下层"且不得跨层回指；同类层内部：平台内核间按 core←{evidence,policy,runtime} 方向、彼此不横向互链（drivetrain 只依赖 core/evidence）；平台服务可依赖全部平台内核，**同层依赖允许但必须落在 §3.5 单元依赖表的既有有向边上（无环）**；**业务域单元之间互链禁止**。

四条构建红线（与 `industrialrobot/CMakeLists.txt` 骨架注释一致，任一命中即构建失败）：

| 红线 | 内容 | 需求依据 | 检验方式 |
| --- | --- | --- | --- |
| R-1 | 业务目标互链禁止（业务域单元计算库/插件目标不得链接彼此） | ARC-02 | 构建依赖图门禁（WP-01-T01 承载） |
| R-2 | 跨单元私有头禁止（只经各单元 `include/` 公共头协作） | ARC-02 | include 路径扫描 |
| R-3 | Widgets（及任何 Qt 模块）进入计算核心禁止：L2 计算内核与业务计算库零 Qt | NFR-MNT-01 | 链接依赖静态扫描（Widget 头/控件互读零命中，NFR-MNT-02） |
| R-4 | RobWork 名称前缀拼接/剥离禁止（唯一例外：runtime 名称解析器实现，登记例外清单） | ARC-04、NFR-MNT-07 | 静态检查＋例外登记 |

**SA-10（依赖红线即构建门禁）**：上述红线不是评审约定而是构建期硬门禁；例外只能登记在权威所有者单元（如 R-4 的名称解析器、R-3 的 ui 单元），未登记例外出现即失败。

### 3.3 业务域单元的二分结构

每个业务域单元交付两类目标：

```
ird_<unit>          计算库（L2，零 Qt）：领域对象、评估器、算法；可被模型测试直接调用
ird_<unit>_plugin   插件界面（L4，Qt Widgets）：面板、参数表、三维交互；只消费端口与只读投影
```

插件界面不持有计算逻辑与业务判定；计算库不感知界面存在。`_test`（单元测试）、`_contract_test`（跨单元契约测试）、`_worker`（进程外计算入口，仅需要的单元）随单元任务卡登记。

### 3.4 workflow 单元定位

workflow 是业务层之上的**编排单元**：消费平台事件（修订产生、结果写入、失效通知）与各域就绪状态投影（由 ui 的 StageStatusModel 汇聚），产出七阶段导航的门控状态与"下一步建议"（UX-01/12）；生命周期入口（新建/打开/另存/导入导出向导）整合于此（PM-01~07/10/11）。workflow 不直链任何业务域单元，只经端口与事件协作。

### 3.5 单元级依赖表（A3 处置；构建门禁 R-1/R-2 的实施依据）

依赖形态三类：**接口依赖**＝仅消费对方 `include/` 公共头与端口接口（构建体现为链接其库目标）；**实现链接**＝直接链接并调用实现（仅下层对更下层使用）；**运行时注入**＝实例由 L5 应用壳装配期注入，消费方只依赖 core 中的接口类型，无编译期依赖。

**共享契约的位置**：跨单元共享的纯契约——领域事件接口（⑤端口）、端口数据类型、`DiagnosticRecord`/`ConfirmableFinding` 数据契约——定义于 **core**（L2），任何层都可依赖 core，避免同层契约所有权倒挂；注册表与设施实现归各自所有者单元（契约/实现分离）。

| 依赖方 → 被依赖方 | 形态 | 用途 |
| --- | --- | --- |
| evidence / policy / runtime → core | 接口依赖 | 身份/版本包络、契约类型 |
| drivetrain → core, evidence | 接口依赖 | 评估器接口、映射结果类型 |
| diagnostics → core | 接口依赖 | 诊断契约基类型（实现归 diagnostics） |
| project → core, diagnostics | 接口依赖 | ConfirmableFinding 注册/构造（§7.1）、身份类型 |
| execution → core, evidence, diagnostics, project | 接口依赖 | 任务身份类型、评估器调度、任务诊断、**results 存储端口** |
| io → core, diagnostics | 接口依赖 | SafePath/BudgetGuard 类型、导入诊断 |
| reporting → core, evidence, diagnostics, project | 接口依赖 | 查询端口（②）、结果引用、证据契约 |
| ui → core, diagnostics | 接口依赖 | 事件契约、状态词、命令注册表类型 |
| 各业务域单元（L4） → L2/L3 公共接口 | 接口依赖 | 全部经 §7.2 端口（R-1/R-2 红线不变） |
| 事件总线、命令上下文回调等实例 | 运行时注入 | L5 应用壳装配注入；消费方零编译期依赖 |

门禁实施：上表之外的同层边（含反向边与新边）＝未登记依赖，构建失败；表内有向无环（project←execution/reporting、diagnostics←project/execution/io/ui，无回边）。

## 4. 运行时视图：进程、线程与资源治理

### 4.1 进程模型（SA-08）

- **主进程**：RobWorkStudioApp 壳＋工作台 UI＋静态插件＋平台内核＋命令服务与调度器。UI 线程绝不执行长计算（Q4）。
- **工作进程**：由 execution 的 WorkerLauncher 池化管理，复用产品代码基的计算内核（零 Qt）。承载批量/长时计算：批量 IK、区域采样、避障搜索、优化评估（Quick/Verified）。
- **隔离性**：工作进程崩溃只导致当前任务失败（NFR-REL-02），主界面不退出、项目不损坏；主进程对其保活心跳与重启上限。
- **通道**：请求队列（含输入切片身份）→ 结果流（分批/流式，NFR-PERF-03）→ 取消信号 → 心跳/进度。通道消息全部携带任务身份五元组（§4.5）。
- **冷启动路径（M-14）**：进程启动、静态插件装配、RobWork 符号绑定与框架初始化构成冷启动时长主体，以软指标 P95 ≤ 8 s 牵引（不作验收门禁，超限登记原因与改进项）；架构手段：白名单静态装配、按需初始化渲染与重量级符号、闪屏可禁用（PM-17）。热启动打开性能（PM-16 门禁 P95 ≤ 3 s）主要由项目加载协议（§6）与对象库惰性装载支撑。

轻量同步计算（单点 FK、单位换算、表单校验）可在调度线程内联执行，门槛为可预测 <1 s（NFR-PERF-01"超过 1 s 的工作转后台"）。

### 4.2 线程模型

| 线程 | 职责 | 约束 |
| --- | --- | --- |
| UI 线程（主） | 事件循环、界面渲染、用户交互 | 不做计算；命令提交入口 |
| 命令执行 | ProjectCommandService 串行执行领域命令（含前置断言、可确认诊断交互与编译） | 修订产生全局串行、单调递增（ARC-01 并发契约）；编译类命令可与界面并行但不能与下一命令并发 |
| 调度线程 | execution 任务派发、状态机推进、结果接纳 | 唯一写 results/ 的路径之一（另一为命令服务写修订） |
| 工作线程（进程内池） | 计算内核内部并行（固定线程数进入运行身份，NFR-COR-02） | 并行归约满足容差；不要求浮点逐字节相同 |

### 4.3 任务生命周期（TASK-01）

任务状态机九态（与 PM-03"任务清单 9 态短标签"对齐；逐转移矩阵与强制终止矩阵的验收归 execution 单元详设与 TASK-01 验收）：

```
 Queued ──► Preparing ──► Running ──► Completed
   │            │           │ │ │
   │            │           │ │ └──► Failed（执行异常，含诊断）
   │            │           │ └─────► Interrupted（进程/会话中断，恢复后显示"已中断" NFR-REL-03）
   │            │           └───────► Paused ⇄ Running（R2 承诺，能力须声明）
   │            │           │
   └────────────┴───────────┴───► Canceling ──► Canceled（用户协作取消；正常取消不属于错误 UX-03）
   └───────────────────────────────┘（Queued/Preparing/Running/Paused 四态均有取消出口——A5 补齐）

 取消路径细则：
   Queued → Canceling：未派发即取消，直接出队 → Canceled（无在途批次，不适用 2 s 协作窗）
   Preparing → Canceling：丢弃组装中的快照/派发物 → Canceled
   Running → Canceling：在途批次按 §4.4 协作取消（2 s 进入 Canceling、10 s 收敛）
   Paused → Canceling：暂停中取消（AT-35/V12-06 明确要求）——暂停态无在途批次，
     取消请求经暂停确认边界直达 Canceling → Canceled，**保留最近检查点**（可续跑）
 强制终止：Canceling 超时（§4.4）→ 终止工作进程 → 任务 Failed（保留最近检查点）
```

每个任务类型在注册时**声明能力**：是否支持暂停、检查点粒度、强制终止代价（TASK-01）；不支持暂停的任务在 R1 收到暂停请求时给出明确状态反馈（不静默忽略）。

### 4.4 取消与终止协议（NFR-PERF-02）

1. 取消请求 2 s 内进入 Canceling 并停止派发新批次；
2. 普通批次 10 s 内自然结束 → Canceled；
3. 超时允许强制终止独立工作进程，任务记 Failed，最近检查点保留可续；
4. 正常用户取消不产生错误诊断（UX-03），取消失败/异常中断走错误路径。

### 4.5 迟到结果接纳（运行登记表核对→归档，当前性独立判定；TASK-03 / PM-13 / CON-02/05——A1 处置，A8 修订）

请求与完成事件携带身份五元组：`projectId / branchId / revisionId / runId / attemptId`。execution 维护**运行登记表（RunRegistry）**：每次派发请求时登记完整五元组＋**归档位置**（任务快照绑定修订的 `results/<run-id>/` 路径）＋任务类型与评估键；重试时新 attempt 追加登记、旧 attempt 标记为被取代。

**第一段·登记表核对（完整五元组）**：完成事件以五元组在登记表查找匹配记录——
- **任一字段与登记记录不一致即拒绝**（丢弃＋开发诊断）：`runId` 未知（无登记，含跨项目迟到事件——绝不写入新项目的 results/，AT-10）、`branchId` / `revisionId` / `projectId` 与登记记录不符、`attemptId` 为已被取代的陈旧尝试；
- 同 runId 同 attemptId 重投递 → 幂等（不重复写、不报错）。

**第二段·按登记记录接纳并归档**：核对匹配的结果，**归档位置取自登记记录本身**（不重新推导），写入原修订的 `results/<run-id>/`，不写入当前 HEAD、不写入新修订——即使运行期间 HEAD 已前进（例：运行期间仅电机成本变更，新修订不影响运动学输入切片，结果仍应可接纳使用）。

**当前性独立判定**：接纳后由 ResultCurrentness 对比**结果切片内容身份 vs 当前 HEAD 切片内容身份**（CON-05，按内容身份而非修订号比较；**HEAD 变化仅用于此处，不参与接纳判定**）：输入未受影响 → Current，可正常消费；输入已变化 → Superseded，保留为原快照历史证据（CON-02）。项目已切换会话时，迟到结果不进入当前界面会话、不成为"当前结果"（TASK-03），但归档与当前性判定仍照常执行。

结果接纳前还须执行运行时名称反解（§7.4，CON-06）；归档写入受写锁权限约束（§6.8，存储上下文生命周期——A7）。

### 4.6 资源治理（NFR-PERF-04）

execution 的 ResourceController 汇总主进程＋全部工作进程内存占用：默认上限为物理内存 70%；接近上限**先节流**（降低并行度/暂停派发新任务）→ 仍超限给"资源不足"诊断。大任务强制分批＋流式结果＋检查点（NFR-PERF-03/04）。

## 6. 数据视图：项目存储与对象模型

### 6.1 `.rwdesign` 目录结构（唯一规范项目格式）

```
<project>.rwdesign\
  HEAD                 提交指针（原子替换的单文件）
  project.json         项目静态标识（projectId、schemaVersion、格式标识——创建期一次写入，不参与事务；分支表/方案清单/项目显示名为不可变元数据对象，见 §6.3——A2 处置）
  revisions\<rev-id>\  修订清单：命令摘要、对象引用集、父修订、时间
  objects\             不可变对象库（按对象 ID＋内容版本编址）
  results\<run-id>\    任务运行结果与证据（绑定修订）
  checkpoints\         长任务检查点
  reports\             报告工件（ReviewReport 渲染产物、证据包）
  drafts\              未应用草稿（定时落盘，PM-04）
  catalog\             器件目录锁定版本（SEL-08）
  .staging\            事务暂存区（崩溃恢复扫描对象，PM-08）
```

磁盘写入**唯一归属 project 单元**（需求 §17 表注）；其余单元经端口请求读写。

### 6.2 对象身份与版本包络（CON-01）

- 每个持久化对象有稳定 `ObjectId` 与内容版本，构成身份/版本包络；跨插件、结果与持久化引用一律用 ObjectId（ARC-04）。
- 对象不可变：修改=新内容版本＋新修订引用；同内容可共享存储。
- 值来源（ValueProvenance）随值保存：用户提供 / 几何解析估算 / 目录回填 / 导入映射 / 派生只读（MDL-05/16 的来源标记、DYN-06 可信等级的依据）。

### 6.3 修订与分支模型（ARC-01、PM-12）

- 修订 = 命令摘要 + 对象集引用（不复制对象）；修订只增不改，HEAD 原子切换。命令摘要含可确认诊断的放行留痕（§7.1，M-10）。
- **项目级元数据对象化（A2 处置）**：分支表（分支→baseRevisionId→HEAD 修订）、方案清单、项目显示名构成 `ProjectMetadata` 不可变对象（入 objects/，按内容版本编址，随修订引用）。创建分支/方案操作/改名（PM-11-S2）＝领域命令 → 新 `ProjectMetadata` 版本＋新修订引用 → HEAD 原子切换——与一切修订同协议，天然事务化，不存在"project.json 与 HEAD 分别更新"的中间态。分支记录 baseRevisionId 不复制对象；URDF 基线修订只读，编辑只发生在方案分支。
- 撤销/重做 = 反向/正向领域命令产生**新修订**，不改写历史（PM-18）；空历史给稳定提示。
- 草稿基线冲突：baseRevision ≠ HEAD 时拒绝提交旧草稿（StaleRevisionRejected），定位冲突、保留草稿（PM-04）。

### 6.4 事务写协议（SA-09、NFR-REL-01）

```
单一提交根＝HEAD（A2 处置：修订、分支表/方案清单/项目名〔ProjectMetadata 对象〕全部经同一提交点，project.json 静态化不参与事务）

写入：  修订目录＋新对象（含 ProjectMetadata 新版本）整体写入 .staging
     → 全部文件哈希校验
     → 内容发布：.staging 内容就位为 objects/ 与 revisions/ 正式路径（内容寻址、只增不改，
       部分就位不破坏旧版本——HEAD 仍指向旧内容）
     → HEAD 原子替换（唯一提交点：携带修订 id 与对象清单摘要）→ 清理 .staging
失败/中断：旧版本保持完整（HEAD 未切换即未提交）
恢复顺序（启动，PM-08）：①扫描 .staging 残留 → 忽略未提交内容＋恢复诊断；
     ②校验 HEAD 引用的正式内容完整性（哈希）；③未被任何修订引用的悬挂对象 → 开发诊断
     （只读清理报告归 PM-08-S1/R2）
例外：版本目录内单资源写入允许"暂存＋原子替换"（不适用于 HEAD/修订清单/ProjectMetadata）
```

崩溃后已提交修订与 HEAD 字节不变（AT-11/13 故障注入验收）。

### 6.5 快照、切片与结果数据

数据形态由 §7.6 机制定义，落位：分析快照与结果入 `results/<run-id>/`（绑定修订与任务身份）；检查点入 `checkpoints/`（兼容契约见 CON-04：版本与输入切片身份匹配才命中，部分/失败结果不得作为正式缓存命中）。

### 6.6 外部资源与引用保护（CON-03、NFR-REL-04、PM-09）

Verified 结果与正式报告引用的外部资源（网格、目录）必须有项目内不可变副本（入 objects/）并受引用保护；外部源缺失/变化由 io 检测（Missing/Changed）；用户重关联经显式命令产生新修订。**外部资源三段边界（PM-01/NFR-SEC-01，v1.11 R4）**：导入向导对外部源的一次性读取 → 草稿期外部引用记录（绝对路径＋内容哈希，io 持有检测）→ 转正式（Verified/正式报告）前按 CON-03 固化为项目内不可变副本并受引用保护，未固化阻断正式结论；项目内持久化引用与项目包解包成员不逃逸项目资源区（SafePath 管辖范围即此二者）。

### 6.7 项目包与用户设置

- `.rwpack`：ZIP 传输封装，解包逐字节还原目录与哈希；导入执行预算与路径穿越防护、全量校验、失败不留目标目录（PM-05、NFR-SEC-01/02）。
- 用户级设置（最近项目、导出勾选、上次目录、命令面板快捷键绑定）不入 `.rwdesign`；求解配置等分析设置独立持久化（PM-14、KIN-13），两者不混。

### 6.8 项目写锁、存储上下文与只读模式（SA-17、PM-07——A4 处置；A6/A7 修订）

- **锁的所有权与形态**：项目写权限由 project 单元统一持有。锁＝`.rwdesign\lock` 文件＋**操作系统级排他锁**（Windows：对锁文件的独占范围锁或独占打开句柄，**存储上下文存续期间持续持有；存储上下文结束时显式释放，进程意外退出/崩溃时由 OS 自动释放**）；锁文件内容＝持有进程 PID＋主机标识＋心跳时间戳。**心跳仅作界面提示与诊断（"持锁进程疑似无响应"），不作为写权限判据**——写权限的唯一依据是 OS 排他锁的持有状态。
- **第二实例**：OS 排他锁获取失败 → **立即只读**（writable=false，不阻塞等待——PM-07），读取锁文件内容提示持有进程 PID；不推测持有者活性、**不因心跳过期而接管**。
- **接管（陈旧锁清理）的原子性**：仅当 OS 排他锁**可被获取**（原持有进程已退出/崩溃、OS 已释放，或其存储上下文已显式释放锁）时才允许接管——先获取 OS 锁（**获取动作本身原子：两个实例同时接管只有一个成功，失败方走只读**），再读取残留锁文件作恢复诊断（PM-08）并重写锁内容。**原进程仅卡顿时仍持有排他锁，其他实例无法接管；原进程退出或显式释放锁后，其他实例才可取得写权限**——因此不存在"卡顿恢复进程与新接管者并存"的双写者窗口。
- **失权写入防护（纵深防御）**：全部写事务在**开始时**校验自身 OS 排他锁句柄仍有效；失权（句柄异常失效、存储上下文已结束后的迟到写请求等实现层边缘情形）→ 拒绝写入、转只读并诊断——任何写入路径不依赖"曾经持锁"的历史状态。
- **存储上下文与锁的生命周期（A7）**：**界面会话与存储上下文分离**——UI 关闭/切换项目仅结束界面会话；**存储上下文**（连同写锁）保持到本实例发起的全部在途运行接纳归档完成、草稿落盘完成为止（PM-03 关闭对话框"等待"选项即等待此完成；协作取消亦经 §4.4 归档检查点后结束）。迟到结果因此总在锁持有期内归档（§4.5）。极端情形下若锁已释放仍出现归档请求（实现层防御性规则），必须**先重新取得写权限**，否则拒绝归档并诊断。
- **崩溃恢复**：异常退出后 OS 排他锁由系统自动释放、锁文件残留 → 下次打开经上述接管路径清理并给恢复诊断（PM-08）。
- **介质只读**：打开期写探测失败 → writable=false，走同一只读路径。
- **写入口权限检查（全部收口于 project 存储端口）**：领域命令（修订/分支/回填/重关联）、drafts 落盘、results 写入、checkpoints 写入、reports 工件、catalog 锁定——writable=false 或失权时一律拒绝并给稳定诊断（含持有者 PID 信息）。只读模式下会话态操作（浏览、FK 预览、单位切换、命令面板会话命令）不受限；需写 results/ 的正式评估在只读模式拒绝启动并诊断说明。

## 7. 关键机制设计（横切）

### 7.1 修订、命令与可确认诊断放行（支柱一，SA-03 / SA-15）

**唯一写路径**：一切"应用修改"经 project 的 ProjectCommandService，以领域命令对象表达（可序列化、可反演以支持撤销）。插件与界面没有其他产生修订的途径。

```
编辑草稿(drafts) → 就绪校验(REQ-06 等) → 领域命令
   → 前置断言（按命令类型；MDL-06 物理合法性断言、SEL-10 复算提示等）
       ├─ 硬断言：物性①~③（m>0/SPD/三角不等式）、限位区间有效性（qmin<qmax）、
       │   continuous 工程工作范围有限性 —— 任一未通过 → 就地阻止＋精确定位非法对象
       └─ 策略校验（可确认）：有限限位旋转关节行程上限（默认阈值 4π，阈值属
           EngineeringPolicySet〔ARC-05/WP-07〕，可按机型配置，M-10）
           超限 → 产出 ConfirmableFinding（比较型诊断：实际行程/阈值/单位/对象）
             ├─ 用户显式确认 → 放行继续执行；确认记录写入命令摘要，随修订持久化留痕
             └─ 未确认 → 阻止应用（不产生修订）
   → 副作用执行（如双编译 WorkCell/DWC，任一失败不提交，MDL-06）
   → 事务提交（§6.4）→ 新修订 + 修订事件 + 依赖失效通知（§7.6）
```

- 并发契约：命令全局串行、修订单调递增；并发修改冲突在命令边界拒绝（ARC-01 验收：项目命令与并发修改契约测试）。
- **SA-15（可确认诊断放行流）**：ConfirmableFinding 是 diagnostics 的比较型诊断扩展，携带确认状态与确认凭据；命令服务在断言阶段收集待确认项集合，经**命令上下文回调**交由 ui 层呈现确认对话（用户确认/拒绝），命令服务凭确认凭据继续或终止。该回调是纯接口（L3 project 不依赖 Qt Widgets，保持 PA-5）；确认决策记录归命令摘要，ui 不持有判定权。工作进程内的批量计算不产生可确认诊断（确认只发生在命令边界）。
- 修订事件驱动下游：ui 更新对象树与状态、evidence 重算当前性、workflow 更新阶段门控。

### 7.3 权威模型与确定性编译（支柱三，SA-04）

三段链，运动学真值唯一（ARC-03）：

```
RobotDesign（权威参数化，项目对象）
   │  权威源二选一（MDL-02）：StandardDH ｜ 显式 Joint+Origin+Axis（七轴默认，S-R-S 锁定显式）
   │  一等字段：Axis（MDL-09）、基座安装姿态（MDL-22）、工程工作范围（MDL-12，分析消费属性不回写）
   ▼  runtime 确定性编译（纯函数：同输入对象集 → 同输出字节）
CanonicalModel（SE(3) 关节链规范模型：连杆几何/惯量/限位/摩擦/重力投影、基座—世界变换，含 RuntimeNameMap）
   ▼  runtime 运行时适配（RobWorkModelAdapter）
WorkCell / DynamicWorkCell 实例（供 rw/rwsim 算法）＋ 碰撞场景（供 policy 适配）
```

- 一切 FK/IK/Jacobian/轨迹/动力/碰撞计算只消费 CanonicalModel（经适配器）；任何单元不得绕过该链自建运动学表示。
- 确定性：编译不读隐藏状态、不依赖线程时序；同修订重复编译产物一致（ARC-03 验收：编译前后 FK/世界轴线一致）。
- 原子性：WorkCell 与 DynamicWorkCell 双编译任一失败不提交新修订（MDL-06）。
- **基座—世界变换单一不变量（M-11）**：安装姿态定义为基座坐标系相对世界坐标系的旋转（世界系与地面固连、重力恒定），作为权威参数编译进 CanonicalModel 的单一 `R_world_base` 字段；**三维视图呈现（倒挂/壁装倒置渲染）、环境几何（MDL-15，世界系固连）、碰撞检测（经 ARC-05 共享评估）与逆动力学重力投影（DYN-01）四类消费方一律消费同一编译产物，禁止任何下游自行叠加或二次旋转**（防止碰撞几何与重力方向错位）；契约测试覆盖倒挂/壁装机型的渲染位姿、碰撞几何与重力矩一致性（AT-37）。多机协同/变位机不在首版范围，后续引入遵循同一单一变换口径。
- DH↔显式转换（MDL-10）在 modeling 提供服务，但转换产物必须经同一编译链等价验证后才可成为权威 DH。
- URDF/Xacro 导入（MDL-03/11/12/19）产出 RobotDesign **草稿**与诊断报告，确认后经命令端口进入修订。

### 7.4 名称解析（支柱四，SA-05）

- 编译时生成完整 RuntimeNameMap：关节/Frame/限位/几何/碰撞规则/动力学引用全部由 ObjectId 解析为 `RobotName.LocalName`，不遗漏、不重复前缀、不引用旧机械臂名（MDL-14）。
- 名称→对象的反解是接纳结果的强制步骤：工作进程/其他入口返回的运行时名称必须先反解为 ObjectId 才能进入结果（CON-06）。
- 前缀拼接/剥离的唯一合法位置是 runtime 名称解析器实现（R-4 红线例外登记，NFR-MNT-07）。
- 验收：名称往返无漏/旧/双前缀（AT-18）。

### 7.5 策略权威（支柱五，SA-06）

- EngineeringPolicySet 是唯一权威策略对象，持有：碰撞规则（排除对/安全间距）、环境对象参与、工程判定阈值（近限位比、条件数警告等，KIN-13 明确归本处）、**有限限位旋转关节行程上限阈值（默认 4π，可按机型配置——M-10 归属本处）**。持久化为项目对象。
- 每个计算快照保存**已解析**策略的版本/内容身份；策略进入依赖切片与缓存键（CON-06）——策略变更→依赖它的结果失效。
- CollisionEvaluator 唯一共享实现（policy 单元＋RobWork 碰撞适配）：运动学/轨迹/优化/选型各入口调用同一实例（NFR-COR-05，AT-19：对象 ID 对、判定与原因码完全一致）。
- 界面只显示策略摘要与跳转入口（UX-08 统一"工程策略"入口）；分析配置不得覆盖策略（KIN-13），显示开关不进入计算与缓存身份。

### 7.6 快照、证据与缓存管线（SA-07 / SA-13）

```
当前修订 ＋ 选择的工况集 ＋ AnalysisConfiguration(KIN-13) ＋ 已解析 EngineeringPolicySet
   ▼ 组装（一次评估一份）
AnalysisSnapshot（完整、不可变；含 RuntimeNameMap 与策略内容身份——CON-06）
   ▼ 依赖分析
InputSlice（评估输入切片＋依赖清单；切片内容身份 = 缓存键与失效判据——CON-05）
   ▼ 评估运行（§4 进程模型；检查点兼容契约 CON-04）
ResultEnvelope{ outcome × engineeringStatus × payload }   ← 构造边界校验：非法组合直接拒绝（TASK-02，SA-13；合法组合表以需求 §8.1 表 3 为准）
   ▼ 写入 results/<run-id>/（绑定修订）
ResultCurrentness：对比结果切片身份 vs 当前 HEAD 切片身份 → Current / Superseded
```

- 三态正交（CON-02）：结果完整性（成功/取消/失败）、当前性（Current/Superseded）、工程判定（可行/工程不可行/数据不足）互不替代；Superseded 不改变历史 payload，保留为原快照历史证据。
- 失效按切片依赖传播：电机成本变更不失效运动学/轨迹；TCP 变更失效运动学及下游（AT-05 矩阵）。
- 正式判定（EVI-01/02）：评估模式、证据等级、RequiredEvidenceProfile 契约全局唯一；证据不足不得显示通过；正式计算与判定必须覆盖全部启用必验工况（多工况包络合并不替代覆盖规则）；工程判定的汇总优先级（输入非法＞**通用证据门禁**＞确定性不可行＞证据缺失＞齐备）与不可行替代证据按需求 §8.1 表 2/表 4 执行——**碰撞判定作用域为构型/路径级**（解被过滤/路径被淘汰重规划），任务级不可行仅限必经状态碰撞、解析界限或约束矛盾证明；数值搜索未果（含全部解因碰撞被过滤）判 DataInsufficient（v1.15/C5/C6、v1.16/C8）。
- 取消/失败/中断结果不得进入正式报告或可行集（TASK-02）；部分结果不作为正式缓存命中（CON-04）。
- 采样类评估（区域覆盖 KIN-04、工作空间采样 KIN-09）的样本集合由采样计划确定性生成并**随快照冻结**，进入运行身份与缓存身份——复评不得增删更换样本（R8）；评估中验证覆盖不充分（如轨迹细分预算耗尽，TRJ-04/R9）一律产出 DataInsufficient，不得默认接受。

### 7.7 会话态与显示层规则

- 会话姿态（双击任务/候选、动画、可视化点回写——KIN-06/TRJ-07/KIN-09）只修改 ui 会话态（SelectionModel/DraftController 管辖），不产生修订、不触发失效、不进入缓存身份（AT-04）。复位关节至 Home/Zero 同属会话姿态（UX-13 工业高频命令，KIN-06 语义）。
- 显示单位（KIN-12）是纯投影：core 唯一换算实现，界面/导出层调用；切换不改 SI 真值、不产生修订、不触发重算。
- 求解配置（AnalysisConfiguration，KIN-13）独立持久化，进入运行身份与缓存身份；修改后按实际依赖提示受影响结果需重算。
- 工程用语（UX-02）：界面不显示哈希、Schema、内部插件名；对象定位统一经 ObjectId→名称端口呈现局部名。

### 7.8 诊断与单位单一权威（SA-12）

- 诊断对象字段（ERR-01）：稳定诊断码（StableCodeRegistry 注册）＋ subjectObjectId＋局部/运行时名称＋上下文＋原因＋建议动作；比较型校验额外含实际值/期望值/单位；不适用字段显式标记，不伪造数值。**ConfirmableFinding（§7.1，SA-15）是其中携带确认状态的比较型子类**，注册于同一 StableCodeRegistry；诊断对象的数据契约（含 ConfirmableFinding 基类型）定义于 core，注册表与两级日志设施归 diagnostics（契约/实现分离——§3.5，A3）。
- 两级日志：用户诊断（无调用栈/内部哈希）与开发诊断；崩溃转储与日志脱敏（NFR-SEC-07）、本机路径按配置脱敏。
- 单一权威定义（NFR-MNT-03）：指标 ID 与注册表、状态词（UX-10 七态）、单位换算、诊断文案各只有一个所有者（core/diagnostics/ui 分域拥有），重复定义被红线与评审拦截（NFR-MNT-04/05）。

### 7.9 导入安全（SA-14，NFR-SEC-01~03）

所有外部输入通道（URDF/Xacro 展开、网格、CSV、目录包、项目包）统一经 io 的防护设施：

1. SafePath：资源引用不得逃逸项目资源区（路径穿越防护）；
2. BudgetGuard：单文件大小、XML/压缩包递归深度、解压总量上限，超限拒绝＋诊断；
3. CSV 数据-only 解析（不执行公式/命令）；CSV 导出对 `=、+、-、@` 开头可能被解释为公式的文本统一转义，结构化证据保留原始值。**转义 roundtrip 语义（M-15＋R5）**：转义仅发生在 CSV 文件层——导出携带方言标识（文件头标记行）并采用可逆编码（转义符 `'` 自身亦被转义，导入剥离恰好一个前导 `'`），任意原文（含自带前缀）roundtrip 逐字符一致；导入侧仅对携带方言标识的文件执行前缀剥离，无标识的外部 CSV 一律原样读入；转义形式不得进入结构化数据层（io 的读写器是唯一转义/还原实现，SA-12 单一权威的延伸）。

Xacro 展开属受控预处理，展开结果进入与 URDF 相同的安全解析边界（MDL-19）。

### 7.10 评估器组合、优化域与传动映射（OPT 支撑）

- 优化候选 = 基线 RobotDesign ＋ 变量补丁（CandidatePatch，连续/量化/离散器件变量，OPT-02）→ 临时候选模型 → **同一编译链**（§7.3）→ **同一评估器注册表**执行静态约束与指标（OPT-03/07 阶段分期：阶段 B 仅运动学/碰撞静态子集；`drivetrain.ratio` 为 StageB 绑定的连续变量——可编辑并编译进候选，完整驱动性能评估归 OPT-D，V12-02）。
- 候选归属于 OptimizationRunResult，不产生项目修订；"设为当前方案"必须经命令端口创建方案分支＋新修订＋完整复算（OPT-08 采用守卫，AT-12）。
- Quick 保守淘汰→Verified 复核双层（OPT-06）；会话内缓存＋确定性随机种子；同种子同线程数等价集合与稳定排序（NFR-COR-02，AT-09~11）。
- **传动映射契约（DYN-04，M-12 口径）**：统一走 drivetrain 的 DriveTrainMappingEvaluator（③评估器端口消费），dynamics 与 selection 不各自实现映射。映射动力学：关节侧广义力由 DYN-01 之 RNEA 在关节空间**精确**计算（含全部惯量、离心/科氏与重力耦合项）；驱动端映射按虚功原理执行——常矩阵 C 下 τ_motor＝Cᵀ·τ_joint＋电机侧转子惯量项（J_rotor·θ̈，θ̈＝C⁺·q̈；无耦合链等价于对角传动比映射）；**不采用对角化或准静态近似、不丢弃交叉耦合项**；C 非常矩阵或病态时给诊断并阻止（不静默等效）；转子等效惯量按 SEL-10 单独处理，禁止与壳体质量重复计入。含耦合矩阵（MDL-21，R2）时 SEL-03/04/05 消费的电机侧工作点按同一口径生成。

### 7.11 命令面板与全局快捷键注册（支柱横切 C，SA-16 / M-13）

命令入口是"常用操作路径短"（需求 §1）的架构承载，全部收归 ui 单元的两个权威设施：

- **CommandRegistry（命令注册表，ui 持有）**：命令项 = {命令 id、显示名、搜索关键字集、类别、是否可绑定快捷键、执行回调句柄（经端口/事件解耦，不直链业务单元）}。各插件在装配期经注册端口登记命令；UX-13 首版最小命令集（新建项目、打开项目、保存草稿、应用修改、撤销、重做、切换方案、另存为、包导出、报告导出＋工业高频：运行碰撞检查、切换显示模式、复位关节至 Home/Zero）为验收底线。
- **HotkeyBindingTable（全局快捷键唯一注册点，ui 持有）**：应用级快捷键一律经此注册；同键重复绑定在**注册边界拒绝**并产出比较型诊断（冲突键、已占用命令——ERR-01 口径），不覆盖、不静默；绑定属用户级设置（PM-14，不入项目）。业务插件界面**作用域内**的快捷键（焦点在自身面板时生效）允许自持，但**全局作用域快捷键私占禁止**——纳入 NFR-MNT-07 静态检查延伸（SA-16）。
- **命令面板**：消费 CommandRegistry，提供名称/关键字**模糊搜索**与完整键盘导航；未绑定快捷键的命令经面板可达（可达性兜底，UX-13 契约）。
- 与 §7.7 的关系：命令面板中的"切换显示模式""复位关节"等会话态命令不产生修订（KIN-06 语义）；产生修订的命令一律经①命令端口。

## 8. 场景视图：端到端架构走查

### S1 建模应用、编译与确认放行（MDL 主线，AT-01）

```
modeling 插件(编辑) → drafts 落盘(PM-04)
用户点"应用" → ①命令端口: ApplyRobotDesign
→ project 前置断言:
     硬断言失败（物性/限位区间/工作范围）→ 就地阻止＋定位非法对象
     行程超限（如 ±1080° 多圈关节，默认阈值 4π）→ ConfirmableFinding
        → ui 确认对话（实际行程/阈值/单位）→ 用户显式确认 → 放行，确认记录入命令摘要
        → 用户拒绝/未确认 → 阻止，不产生修订
→ runtime 双编译 CanonicalModel→WorkCell/DWC＋RuntimeNameMap(任一失败不提交)
   （CanonicalModel 含 R_world_base 单一基座—世界变换，M-11）
→ 事务提交(§6.4) → 新修订 → ⑤事件: 修订产生+失效通知
→ ui 对象树刷新；evidence 重算当前性；workflow 阶段门控更新
```

### S2 批量验证与失效矩阵（AT-03/05）

```
kinematics 插件 → ②查询端口取当前修订对象 → 组装 AnalysisSnapshot(含已解析策略+AnalysisConfiguration)
→ ③④端口注册的批量 IK 评估器 → execution 派发工作进程(进度/取消 §4.3-4.4)
→ 结果流分批回传 → 身份五元组验证(§4.5) → 名称反解(§7.4)
→ ResultEnvelope 构造校验 → 写 results/<run-id>/ → ResultCurrentness 更新
失效示例：TCP 对象新修订 → 切片身份变化 → 运动学及下游标 Superseded；电机成本对象变更 → 运动学/轨迹仍 Current
```

### S3 静态优化运行与候选采用（AT-09/12）

```
optimization → 预检 Preflight(写集冲突/绑定/上游工件，OPT-11) → 基线评估(Evaluate Baseline)
→ 变量补丁生成候选（含 drivetrain.ratio 连续变量，StageB 编译进候选）
→ 同一编译链+同一评估器(静态子集) → Quick→Verified → Pareto 非支配集
→ 候选表(可算指标/其余"—")；全部结果入 OptimizationRunResult(不产生修订)
用户"设为当前方案" → ①命令端口 → 创建分支+新修订+触发完整复算(基线对象字节不变)
```

### S4 选型回填与复算提示（AT-30）

```
selection → 目录导入(io 校验+锁定版本) → 硬筛选 → ③评估器: DriveTrainMappingEvaluator 校核
→ 可行组合+逐项淘汰原因(实际值/阈值) → 用户应用选型
→ ①命令端口: 回填各轴 DriveTrainDesign(目录版本+安装关系；壳体/转子惯量区分合成，不重复计入)
→ 新修订+依赖失效提示(运动学/动力/选型/优化指标需复算)；复核完成前不沿用原通过结论
```

### S5 崩溃与恢复（AT-11/13）

```
进程崩溃 → 重启扫描: .staging 残留/锁心跳/孤儿草稿 → 恢复横幅(一句话+详情/恢复/放弃, PM-15)
已提交修订与 HEAD 字节不变；未提交版本忽略+恢复诊断；中断任务显示"已中断"可重跑(NFR-REL-03)
诊断文件写出并脱敏(NFR-SEC-07)
```

### S6 跨入口碰撞一致（AT-19）

```
kinematics / trajectory / optimization 三入口 → 同一修订+同一已解析策略
→ ④端口同一 CollisionEvaluator 实例(工作进程内同样经共享实现)
→ 对象 ID 对、碰撞判定、允许/排除原因码完全一致(缓存键亦含策略内容身份，避免双算不一致)
```

### S7 项目切换与迟到结果（AT-10；§4.5 登记表核对）

```
项目 A 运行中任务 → 用户切换项目 → 统一确认对话框(PM-03: 草稿三选+任务二选)
→ 界面会话切至项目 B；项目 A 存储上下文(含写锁)保持至在途运行归档完成(A7)
→ 任务完成事件迟到回主进程 → 以完整五元组查运行登记表(§4.5 第一段；一次性判定，
   不存在"先按当前会话判失配丢弃、再按原项目接纳"的两个步骤)：
   → 无匹配登记(如跨项目迟到事件) → 丢弃+开发诊断，绝不写入项目 B 的 results/ (AT-10)
   → 匹配(属项目 A 的运行) → 从登记记录取得归档位置，写入项目 A 原修订的 results/<run-id>/
→ 当前性独立判定：结果切片内容身份 vs 项目 A 当前 HEAD 切片内容身份(CON-05)
   → 输入未变(如仅电机成本变更) → Current，可供后续消费
   → 输入已变 → Superseded，保留为原快照历史证据(CON-02)
→ 无论何种当前性：不进入当前会话、不成为"当前结果"(TASK-03)
→ 项目 A 在途运行全部归档完成 → 存储上下文与写锁释放(A7)
```

### S8 倒挂机型：同一变换的一致消费（AT-37）

```
RobotDesign 安装姿态 = 倒挂 180° → 编译进 CanonicalModel 的 R_world_base（单一权威，M-11）
→ 三维视图倒置渲染 ‖ 环境几何(世界系固连) ‖ 碰撞检测(policy 共享评估) ‖ 逆动力学重力投影(DYN-01)
   四消费方读取同一编译产物 → 倒挂静态重力矩符号/量值正确，碰撞几何与重力方向不错位
（反例被契约测试锁定：任何下游叠加二次旋转的实现都无法通过 AT-37 一致性断言）
```
