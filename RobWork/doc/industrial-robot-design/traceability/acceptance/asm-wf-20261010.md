## 三、建议级问题（不阻断，供实施者/后续批次参考）

1. **openProject .rwpack 分流的收集缝双重调用**（WorkflowHostAdapters.cpp:591-597）：分流命中 PackageFile 后先 `collectPackageImport(request)`（预填 packFile），收集成功再调 `startPackageWizard(PackageFlowKind::Import)`，后者 Import 段再次 `collectPackageImport(request)`（:734-737）——真实宿主对话框场景下用户可能面对两次输入收集。测试 `ControllerPackageImportEntersViaOpenProtocol` 钉扎的行为与实现一致（替身缝幂等），不构成缺陷级证据；建议宿主装配批次注入真实对话框缝时复核收集次数语义（或在文档登记该分流的契约形态）。
2. **必填桥反例为抽样式**：`AssembleFailsFastOnMissingRequiredBridges`（HostAdapterTest.cpp:379-404）只逐一清空 currentStore/presentFailure 两个代表桥，11 个必填桥未逐参数化（端口侧 13/13 已逐一）。presentFailure（失败可见面，F-565/566 最关键项）已覆盖；建议后续批次补全逐一参数化。
3. **selection 卡 P-SEL-9 状态列同步**：selection.md §19.1 P-SEL-9 行状态仍为「登记（T09 裁决前：……编排面不落位）」——本批 workflow 侧编排核已落位。本任务 scope 未含 selection.md（不越界），两侧卡同步义务属后续批次（workflow.md v1.5 已登记该义务）。
4. **Switch 候选激活的 projectId 来源**（WorkflowHostAdapters.cpp:649-652）：`activateStore(std::move(outcome.candidateStore), m_bridges.currentProjectId())` 使用切换前的 projectId——`CloseFlowOutcome` 无 candidateProjectId 字段（Lifecycle.hpp:1439-1467），activateStore 契约「宿主接手后负责会话层登记」可闭合该语义，但依赖宿主实现自行取正确 id；建议宿主装配批次在 activateStore 实现内以 store 自身身份复核。
