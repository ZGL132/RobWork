## 阻断级问题 B-1：冻结树不可构建——提交混入另一未合入批次的未提交内容

**现象**：`ui/plugin/UiPlugin.cpp` 六处（2576/2709/2731/3816/4159/4211 行）调用 `sdurws::ird::modeling::ModelingPluginAssembly::guardPendingInputs(...)`，但本树 `modeling/assembly/sdurws/ird/modeling/ModelingPluginAssembly.hpp` 无该成员——MSVC C2039 ×6（build-integrated.log 2385~2407 行，失败工程 `sdurws_ird_studio.vcxproj`；增量复验 `sdurws_ird_ui_plugin.vcxproj` 同样失败）。

**四树对证**（`git show <ref>:<hpp|UiPlugin.cpp> | grep -c guardPendingInputs`）：

| 提交 | 声明（hpp） | 调用（UiPlugin.cpp） |
| --- | --- | --- |
| 119dce6bb（两任务共同基线） | 0 | 0 |
| **5f199617c（本任务送验 SHA）** | **0** | **6** |
| 35ea15486（WP-17-T11 送验 SHA） | 0 | 0 |
| ce5a0be42（wp13-t30 分支尖端，**未合入 redesign-main**） | 1 | 0 |

即：`guardPendingInputs` 的**声明与定义都在 wp13-t30 的 ce5a0be42**，本分支并不包含它；六处调用由本任务自己的提交带入。

**诊断性复验**（验收者临时把 ce5a0be42 的 ModelingPluginAssembly.hpp 移植进复现 worktree，用后即弃）：UiPlugin.cpp 编译通过，但链接 `sdurws_ird_ui_plugin.dll` 报 **LNK2019**——`ModelingPluginAssembly::guardPendingInputs(std::function<void(void)>)` 无法解析（定义同样只在 ce5a0be42）。即混入面横跨声明＋定义两层，单补头文件也不能构建。

**根因定性**：实施工作树在实施期间持有 wp13-t30 的未提交建模改动（契约 note 自述"保留进入本批前需求/建模等未提交修改"），实施者在本地产物完整的状态下构建并得出"集成 Release 构建退出 0"的结论；提交时 UiPlugin.cpp 整文件入库，把属于未提交建模批的六处调用一并带入，而其依赖的声明/定义留在未提交区。**提交对象 ≠ 构建验证对象**——违反 ACC §4.2"复现优先于采信"的根基，也违背契约 note 自己"不混入本契约验收"的承诺。

**返工建议**（二选一，由实施者会话执行后重新发起全量验收）：
1. 从 UiPlugin.cpp 剔除六处 guardPendingInputs 调用（它们属于 WP-13-T30 批次语义，不属本契约）；
2. 待 wp13-t30 合入 ce5a0be42 后，将本分支变基于其上，使声明/定义随基线到位。
