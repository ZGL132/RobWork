# 验收协议（ACC，2026-10-22 精简）

## 1. 何时独立验收

按根 AGENTS.md §6.4：公共接口、跨单元接线、数值核心、身份/持久化、安全边界、复用迁移及所有者明确要求的任务需要独立验收。普通局部修正与文档维护自查即可，不额外开验收会话。

## 2. 独立性

独立验收由未实施该改动的会话/人员执行，不能以实施者自查冒充。对具体 SHA 的代码和证据作判断；可阅读提交说明定位问题，但结论必须来自产物、真实运行和相关条款。

## 3. 现场与证据

人工验收用一个干净的检出现场，确认所验 SHA；按影响选择增量构建、相关测试或必要 fresh 配置。记录可以随任务提交，不强制第二个记录 worktree/evidence 分支。

自动 PIPE 继续使用冻结 SHA、漂移检测、detached 现场、`acc/<taskId>/<attempt>` 记录分支与 lastFailureRecord 回传；仅自动编排时读取 PIPE 对应章节。阶段门明确规定的独立验收范围不缩减。

## 4. 核查清单（只执行适用项）

按所有者 2026-10-23 的提速要求：同版本、相同相关输入的真实证据直接引用；普通能力包不重复全库重配、全量测试、历史证据深查、双 PowerShell 版本测试或整套治理夹具，不为固定篇幅、表格格式、多份台账另开验收。仅在构建/依赖、对应规则或环境变化以及实际失败时重跑相关项。数值独立正确性、真实生产上游调用、模型/状态所有权、受影响业务回归与必要独立审查仍须满足；未执行项明确写“引用既有证据”或“不适用”，不得补写 PASS。

## 5. 结论

记录任务/分支/被验 SHA、pass/fail、实际执行命令与结果、证据路径和未解决项即可，不规定篇幅。passed/skipped/failed 分列。FAIL 返工后重验受影响项，已通过且输入未变的无关验证无需重复。

## 6. 合入

所有者决定是否合入 redesign-main；实施者不自行合入。main 冻结。历史验收证据保留，不能改写为新一轮 pass。

以下是 GOV-T21 原治理包的专项条件，不推广为每个后续能力包的固定重验清单。
