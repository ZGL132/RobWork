### 1.2 设计目标

1. **三入口路径规划**：关节空间 PTP 与任务点作业序列（TRJ-01）、笛卡尔直线接近/撤离段
   ＋段内 IK 连续性检查（TRJ-02）、RobWork 规划器避障路径搜索（TRJ-03，规划器与参数可配置）。
2. **简化、平滑与复检协议**（TRJ-04）：简化/平滑产物必须按冻结协议复检——P-06 数值
   冻结前**复检不启用**；协议五要素（端点＋段内采样、双上界取严、阈值唯一来源 policy、
   证据缺失 DataInsufficient、失败段定位）全文贯彻。
3. **时间参数化**（TRJ-05）：至少加速度连续运动律＋关节速度/加速度限值校验＋总节拍与
   分段时间输出；TRJ-08 接口约束（jerk/工艺速度/连续工艺段预留评估维度，零空字段）。
4. **失败段诊断定位**（TRJ-06）：无路径/分支跳变/奇异邻域/限制超标给出具体段落与原因码。
5. **结果消费面**（TRJ-07）：动画/曲线/局部重规划/标准轨迹导出——呈现归 ui、数据归本单元，
   动画与导出零修订（AT-04）。

### 1.3 语言、标准库与构建约束（与 core.md/io.md §1.4 同源）

- C++17（各目标显式 `CXX_STANDARD 17`）；零 Qt（L2/L3 计算库——R-3；Qt 仅 L4 插件
  `sdurws_ird_trajectory_plugin` 按层规则消费 Widgets，文件域隔离与 kinematics WP-15-T12
  先例同构：Qt 面板置 `plugin/` 子目录，`include/`+`src/` 产品扫描域零 Qt）。
- 纯 std 标准库＋RobWork 数学/规划器设施（经封装隔离，SA-02 框架零修改）；第三方依赖
  一律经 vcpkg（本单元阶段 A 无新增依赖预期）。
- 物理单位制：真值一律 SI（m/rad/s）——显示换算归 ui DisplayUnitProjection（SA-12 先例，
  L-K8 同款纪律：换算零自实现全经 core Units）。

## 4. 轨迹数据模型

### 4.1 段类型词表与路径模型

```text
TrajectoryPath ＝ 有序段序列（不可变——构造后无 setter，PA-2 同款纪律）
  ├─ JointSegment      关节段：起/终关节配置＋运动律占位（§7 参数化前无时间轴）
  ├─ CartesianSegment  笛卡尔段：起/终 TCP 位姿（refFrame 声明）＋姿态插值方式
  └─ ObstacleSegment   避障段：规划器产物路点序列＋规划器身份与参数摘要（溯源）
```

- 段模型最小完备：段身份（序号）、类型、端点、约束引用（限值/阈值来自已解析策略的
  **内容身份**而非数值拷贝——阈值漂移即失效，复检以"同一策略内容身份"为前置）。
- **零空字段纪律（TRJ-08）**：段/路径模型不预留"将来可能用"的可空槽位；扩展维度
  （§7.3）以接口扩展点表达，不以字段占位表达。
- 分支语义：相邻段端点构型经 kinematics 构型签名（`ConfigurationSignature` ③端口
  投影）比对，不一致即分支跳变（`TRJ-BRANCH-JUMP`——TRJ-06），如实定位不静默拼接。

### 4.2 路点与 pathParameter 约定

- 路点＝（关节配置 q［rad］，可选 TCP 位姿注记）；pathParameter∈[0,1] 段内归一化，
  路径级参数＝（段序，段内参数）二元组——与 policy §6.x PathSequence"输出携带
  pathParameter、保留样本顺序"的口径对齐（连续性信息不归本单元声明协议对面）。
- 采样位置输出：复检证据需要的采样点序列由本单元产出（policy 只按给定样本评估——
  policy §13 行 TRJ-04），样本顺序与间距即 §6 细分调度的直接产物。

### 4.3 内容身份与不可变历史

- 路径/段/复检结论均携带内容身份（core ContentIdentity 同源纪律）；评估产物入
  results 归档（经 execution 通道），零修订写路径（trajectory 不设 project
  commandType——O-35 同款：本域无自有领域命令，呈现面命令归 ui 词表）。

## 5. 路径规划三入口

### 5.1 关节空间 PTP 与作业序列（TRJ-01）

- 入口：单段 PTP（起/终关节配置）与任务点有序序列（②端口切片取 requirements 任务点
  投影——零写路径）。
- 行为：逐段关节空间直插（阶段 A 语义）；序列段间分支一致性校验（§4.1 分支语义）。
- 失败：超限（起/终点越关节限位）→ `TRJ-LIMIT-EXCEEDED` 定位到段；不可达点 →
  `TRJ-NO-PATH` 附点序号。
- 基准：AT-06 PTP 基准用例（DTB T04 验收）。

### 5.2 笛卡尔直线接近/撤离段与段内 IK 连续性（TRJ-02）

- 入口：TCP 位姿起/终（refFrame 显式声明——位姿在哪个坐标系，_ERR 单位/坐标系纪律）。
- 连续性检查编排：沿段按细分采样发③端口 `kin.task-point-ik` 请求（单点/序列 IK 评估
  服务——kinematics 交接表 line 870 明文），消费逐采样 IK 结局：
  - 全采样存在通过硬过滤的解 → 段连续（存在性口径——与 KIN 采样词表同源语义）；
  - 存在解析界限不可达采样 → 段不连续，定位采样位置（pathParameter）；
  - 搜索未果/数据不足 → 段结论 DataInsufficient（如实，不计分子——KIN 同款不互相推导）。
- **适用条件**（§8.1 C2 例）：纯关节路径的段内 IK 连续性＝NotApplicable（条件不满足
  不计缺失）——检查编排按段类型分派。
- 直线/姿态插值方式随请求声明；本单元零自实现 IK（§2.3）。

### 5.3 避障路径搜索接入（TRJ-03）

- 规划器封装缝：RobWork 规划器经接口封装调用（SA-02——框架零修改，封装层隔离版本
  行为差异）；**规划器与参数可配置**＝装配参数面（规划器实现选择）＋请求参数（采样
  分辨率/超时——随请求声明并入结果溯源，零私设默认值）。
- 候选管理（C8）：候选路径先经④端口碰撞评估（policy 同一 CollisionEvaluator 实例），
  碰撞候选淘汰并触发重规划（重试预算随请求声明；预算耗尽 → `TRJ-NO-PATH` 如实）。
- 规划器未装配 → `TRJ-PLANNER-UNAVAILABLE` 拒绝（诚实降级，零虚构路径）。
- 基准：AT-06 避障基准用例（DTB T06 验收）。

## 6. 简化、平滑与碰撞复检协议（TRJ-04——本单元核心契约）

### 6.1 协议要素总表（R2 五要素＋R9 度量——REQUIREMENTS §12 TRJ-04 原文承接）

| # | 要素 | 本文落点 |
| --- | --- | --- |
| ① | 复检覆盖＝各段端点（路点）＋段内采样 | §6.2 采样调度 |
| ② | 细分按"关节空间最大步长＋笛卡尔最大步长"双上界取严（数值随 P-06 冻结） | §6.2/§6.3 |
| ③ | 安全间距阈值消费工程策略（ARC-05 权威）——复检零私有线宽/阈值 | §6.2 阈值来源 |
| ④ | 验证器或碰撞证据缺失（KIN-05 口径）→ 该段 DataInsufficient，不得视为无碰撞 | §6.3 结论词表 |
| ⑤ | 复检失败段按 TRJ-06 定位输出 | §6.4 |
| R9 | 笛卡尔步长以 TCP 参考点＋全部参与碰撞验证几何的代表点集最大位移计量；细分在双上界**同时满足**时终止；预算耗尽 → DataInsufficient 附实际步长与预算占用 | §6.3 |

### 6.2 采样调度与数值来源

- **P-06 冻结门槛**：细分协议数值（关节/笛卡尔默认步长、细分预算、代表点集生成规则）
  由 WP-16-T02 横切卡冻结入 REQUIREMENTS 附录 C 之后方可启用；冻结前任何复检请求
  ＝调用方契约违约（`TRJ-INPUT-ILLEGAL` fail-fast——DTB T02 行"未冻结不得启用复检"）。
  工程策略可调整预算（REQUIREMENTS TRJ-04"可经工程策略调整"——经④端口已解析策略
  读取，调整值不落本单元）。
- 采样调度：逐段细分——关节步长（最大关节位移）与笛卡尔步长（R9 代表点集最大位移）
  双上界取严决定细分深度；代表点集生成规则随 P-06 冻结（R1 阶段先以 TCP 参考点
  计量并在结果中如实标注口径，冻结后切换——切换即协议版本变更，见 §13 待裁决①）。
- 阈值来源：碰撞复检经④端口 `IPolicyProvider` 已解析策略执行（policy 唯一
  CollisionEvaluator 实现——ARC-05/CON-06）；本单元只产出采样位置序列并汇装结论。
- 简化/平滑本体：R1 采用确定性算法（道格拉斯-普克式关节空间简化＋三次样条平滑——
  具体算法随 T07 实现卡登记，验收锚＝平滑后 C² 连续＋复检通过）；平滑产物**必须**
  走本协议复检，未复检产物不得进入正式结论（EVI-01 口径）。

### 6.3 细分终止、预算与结论词表

- 终止条件：双上界同时满足（最严对象——R9）；预算＝最大细分层数/子段数（P-06 冻结
  默认、工程策略可调）。
- 预算耗尽 → 该段结论 **DataInsufficient**＋`TRJ-RECHECK-BUDGET-EXHAUSTED`＋附实际
  达到的最大步长与预算占用（REQUIREMENTS TRJ-04 R9 字面——不得默认接受未充分验证段）。
- 证据缺失（验证器/碰撞证据不在场——KIN-05 口径）→ 该段 **DataInsufficient**＋
  `TRJ-RECHECK-EVIDENCE-MISSING`（④要素——不视为无碰撞）。
- 段结论词表：`Passed / CollisionFound（定位）/ DataInsufficient（附因）`——与报告域
  章节投影（trajectory-cycle，reporting §5.1 行 9"分段/节拍/失败段"）同源，零第二套词表。

### 6.4 失败段诊断定位（TRJ-06）

- 四类原因：无路径（`TRJ-NO-PATH`）/ 分支跳变（`TRJ-BRANCH-JUMP`）/ 奇异邻域
 （`TRJ-SINGULARITY-NEAR`）/ 限制超标（`TRJ-LIMIT-EXCEEDED`）。
- 定位模型：`FailureSegment{段序, pathParameter 区间, 原因码, 证据引用（ResultBinding
  ——runId＋字段路径，报告域 EvidenceRefInvalid 同款纪律）}`——每条结论必带绑定，
  渲染层呈现为可追溯引用；无绑定的结论条目在构建边界拒绝。
- 奇异邻域判定的可操作度阈值来自已解析策略（零自设）。
