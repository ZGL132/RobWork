# PA-2：修订不可变历史——只增不改

## Problem

评估类软件的证据链（CON-01/CON-02）要求每项正式结论可定位到产生它的输入快照。若项目文件修订允许原地覆盖：历史证据失去载体（"当时的输入是什么"无从回答）、撤销/重做语义发散（覆盖式 undo 破坏重做分支）、审计与复评没有稳定基准。

## Decision

修订历史只增不改：撤销/重做都产生新修订，不覆盖旧数据（PM-18）；旧结果保留为原快照的历史证据（CON-02）。登记为设计原则 PA-2；修订与写路径的权威归属 project 单元（PA-1）。

## Alternatives considered

（事后重构，非当时记录——原决策时文档链未逐项登记备选，2026-10-17 迁移时按决策语境辨识）

1. **原地修改＋定期快照备份**——否决：备份粒度无法对齐每一次修订，追溯链有缝；备份是运维动作不是语义保证；
2. **纯事件溯源（一切操作存事件，状态靠重放）**——精神同构，部分吸收：PA-2 的"只增"与事件溯源的 append-only 一致；项目域采用修订快照链而非纯事件流，平衡重放成本与直读性能；
3. **只增修订链**（采纳）。

## Consequences

- 项目文件体积随修订数线性增长（压缩/归档策略由后续任务承载，不改变只增语义）；
- 一切"改项目"的 API 实际是"追加新修订"语义——接口设计从第一天起消除原地变异的心智预期；
- 与 PA-3（一切计算经快照）配合：评估输入永远是自洽的完整快照，缓存与证据引用（CON-05 内容寻址）才有稳定键；
- traceability 证据文件同守只增纪律（根 AGENTS §4.2"证据只增不改"）。

## Verification

- project 单元测试套件承载修订语义不变量（撤销/重做产生新修订、旧修订可取回——具体测试面见 `units/project.md` 测试任务节）；
- ACC 验收核查证据链可追溯性；
- 执法分级：`context/rule-enforcement.md` §3.1（PA-2 行，review＋单元测试）。
