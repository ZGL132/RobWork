# ird-handoff：会话交接记录

**时机**：任一会话结束前（任务完成、部分完成、被阻塞、轮次耗尽——都要交）。
**目标**：接手会话只拿仓库＋任务 ID＋本记录即可继续，不依赖原会话对话历史（PIPE §0 自足性精神）。

## 交接模板

```markdown
# 交接记录：<taskId 或批次名>（<日期>）

## 目标
<本会话要完成什么（一句）>

## 完成项
- <条目>（<分支>@<SHA>）
- …

## 未完成项
- <条目>——卡在 <哪一步/哪个门>

## 提交清单
- <branch>@<SHA>：<一句话摘要>

## 改动文件
<路径清单（新增/修改分组）>

## 执行命令与结果
<ird-verify-change 四态格式摘要>

## 证据
<路径清单：gtest XML / ird-test-report / 构建日志 / 截图>

## 阻塞
- <问题描述>——已登记：<findings 编号 / DTB §4 O-xx / governance-log P-xx>
（未登记的阻塞必须先登记再交接）

## 下一步
1. <接手会话的第一个动作（具体到命令或文件）>
2. …
```

## 纪律

- **失败如实**：未完成与失败项不粉饰、不省略（根 AGENTS §7 三态汇报）；
- **阻塞必已登记**：交接前把阻塞落入 findings/DTB §4/governance-log，交接记录只引编号；
- **状态引用**：流水线相位写"读 state.json"而非转抄状态值（PIPE 权威红线）；
- 落位：随批留痕（`traceability/` 对应目录）或按任务卡指定位置；治理 Task 8 将固化 `context/handoff-template.md`（本 Skill 即其内容源）。
