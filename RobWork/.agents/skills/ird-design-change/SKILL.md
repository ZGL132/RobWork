# ird-design-change：变更设计（不动码）

**时机**：discover 画像完成后、写第一行代码之前。
**输入**：变更画像（ird-discover-change 的输出）。
**权威依据**：REQUIREMENTS 条目语义、units/<unit>.md 接口/状态机/错误语义、ARCHITECTURE 端口与分层。

## 设计八节（输出物）

1. **行为规格**：改完之后系统 observable 行为是什么，逐条对应 `requirements[]` 的需求条目语义（不重定义、不收窄、不扩大）。
2. **接口变化**：公共头（`include/sdurws/ird/<unit>/`）与端口签名的增改；跨单元只经六类端口（R-1/R-2 约束）；命名遵循框架惯例（PascalCase/camelCase）。
3. **失败语义**：错误二分归类——调用方契约违约（fail-fast：断言/异常）vs 环境错误（稳定诊断码登记，单元前缀助记码，不吞错）。
4. **生命周期与所有权**：新对象的持有者/释放责任；PA-1 权威归属核对（修订→project、真值/名称→runtime、策略→policy、单位/文案→core/diagnostics、命令入口→ui——不实现别人的语义）。
5. **线程约束**：新共享状态的访问限制（任务执行线程/UI 线程/后台 worker）。
6. **测试矩阵**：单测 / 契约 / GUI / 性能四类各自的用例清单，用例名带 AT 追溯；测试替身只打端口边界（源码区 AGENTS §4 政策）。
7. **文档影响**：单元卡增量修订项、DTB 任务行状态、是否触碰需求语义（**触碰即停**——需求语义变更归所有者裁决，DTB §4 登记）。
8. **决策记录判定**：本变更引入新的长期决策（含否决了明显备选）→ 起草 `proposed` Note（`.agents/notes/`，六段式）；无新决策 → 记"无"。

## 设计门（过不了不得动码）

- 跨单元协作边新增/修改，或公共接口（公共头、端口）变化 → **先所有者/架构审阅**（DTB §4 登记），再实施；
- 涉及确定性/身份/摘要路径 → 设计必须写明规范化规则（单位、浮点格式化、排序键——SA-04 纪律）。

## 禁止项

- 设计未过门即动码；
- 私改需求语义或"顺手"扩大任务范围；
- 在设计中省略失败语义（只写 happy path）。
