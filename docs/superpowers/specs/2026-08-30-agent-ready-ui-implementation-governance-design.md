# 工业机械臂界面智能体实施入口闭环设计

> 日期：2026-08-30
>
> 状态：方案已确认，待同步治理文档
>
> 适用范围：工业机械臂混合式工程工作台的 UI 实施任务、工作包、追踪与验证

## 1. 目标

把已经完成的工业机械臂工作台界面规范转化为符合仓库规则、可由智能体逐卡实施的治理闭环。完成后，智能体能够在某张任务卡进入 `Ready` 时，仅依据权威文档、该任务卡和登记命令确定：

- 要实现的具体界面范围；
- 允许和禁止修改的文件；
- 唯一公共组件与业务 Dock 所有者；
- 输入、输出、状态、按钮、表格和错误行为；
- RED 测试、构建目标、GUI 验证命令与证据路径；
- 前置任务、停止条件和下一张任务的解锁条件。

本次只闭合 UI 实施治理，不修改产品代码，不绕过契约接受、任务状态和独立验证流程。

## 2. 核心原则

1. 保持“一张任务卡、一个隔离工作区、一个实现提交、一组证据”。
2. 业务 Dock 由对应领域 WP 实现；RobWorkStudio 外壳、公共 Dock 和公共组件由 WP-10 实现；跨阶段工作流与项目入口由 WP-22 实现。
3. 业务模块不得读取其他插件 Widget，不得复制公共状态、策略或诊断组件。
4. 中央三维视图始终由 RobWorkStudio 提供，任何任务不得以业务页面替换。
5. 不把所有下游任务批量改成 `Ready`；状态仍按前置 `Done` 和九项开工门禁逐卡解锁。
6. `Proposed` 契约仍通过 WP-00 治理流程提升为 `Accepted`，本次文档修改不代替签署。
7. 新增任务只填补没有明确实施所有者的 UI 交付，不拆改已冻结的计算任务语义。

```text
WP-10 公共 UI
  ├─ 公共状态、选择、场景投影、表格、诊断、策略面板
  └─ WP-10-T06 RobWorkStudio 工作台外壳与 Dock

业务领域 WP
  ├─ WP-13-T08 建模 GUI
  ├─ WP-14-T07 需求 GUI
  ├─ WP-15-T07 运动学 GUI
  ├─ WP-16-T07 轨迹 GUI（新增）
  ├─ WP-17-T07 动力学 GUI（新增）
  ├─ WP-19-T07 选型 GUI（新增）

  └─ WP-21-T07 R2 联合优化 GUI（新增）
```

## 5. 新增任务卡

### 5.1 WP-10-T06 工作台外壳与 Dock

职责：

- 在 RobWorkStudio 主窗口接入工业工作流工具栏；
- 保持原生三维视图为中央部件；
- 建立左、右、底三类公共 Dock 区域和标签化规则；
- 实现 1920×1080、100%～150% 缩放布局；
- 实现工业默认布局恢复、浮动 Dock 屏外恢复；
- 只提供业务 Dock 注册和抬升接口，不创建业务字段。

目标：`sdurws_ird_workbench_gui_test`。证据必须包含三档缩放截图、Dock 移动/浮动/恢复记录、其他 RobWorkStudio 插件布局未被重置的断言。

### 5.2 WP-16-T07 轨迹工作台 GUI

职责：

- 只读任务序列、轨迹段表、段属性；
- 关节位置/速度/加速度曲线；
- 碰撞、限位、分支表；
- 播放、暂停、逐段、时间游标和三维同步；
- 空态、部分失败和过期结果展示。

目标：`sdurws_ird_trajectory_gui_test`。GUI 不实现规划算法，不编辑需求，不创建第二套播放状态。

### 5.3 WP-17-T07 动力学工作台 GUI

职责：

- 输入摘要、关节包络、关节详情；
- 转矩/力、速度、加速度、功率、机械能、摩擦曲线；
- 峰值窗、RMS、能量汇总和三类可信度；
- 曲线游标与轨迹、三维视图联动；
- 明确排除电机侧和电气量。

目标：`sdurws_ird_dynamics_gui_test`。GUI 只消费 `DynamicResult`，不得修改动力学语义或传动映射。

### 5.4 WP-19-T07 器件选型工作台 GUI

职责：

- 运动轴列表与三维关节高亮；
- 目录摘要、轴需求、默认/高级筛选；
- 可行方案、淘汰方案、能力曲线和工作点；
- 2～4 组合比较、整机草案及一次应用；
- 移动关节范围外、目录失效和全淘汰状态。

目标：`sdurws_ird_selection_gui_test`。不生成综合总分，不外推目录曲线，不显示内部目录字段。

### 5.5 WP-21-T07 联合优化工作台 GUI

职责：

- 新机/改造与静态/关节模式；
- 变量、目标、约束、设置；
- 分层漏斗、总体进度、候选表和 Pareto；
- 快速淘汰审计、稳健性、候选比较；
- 正式复核和设为当前方案。

目标：扩展 `sdurws_ird_optimization_gui_test`。R1 静态 UI 仍由 WP-20-T07 所有；本卡只增加 R2 联合能力，不修改静态核心。

### 5.6 WP-22-T06 项目入口与新建向导

职责：

- 无项目欢迎页、最近项目和项目菜单；
- 三步新建项目向导；
- 从模板、从 URDF、空白项目创建；
- 从 URDF 新建字段、行内错误、失败不留半成品；
- 成功后进入建模阶段；
- 建模页不出现 URDF 导入、模型导入、导入报告或独立模型检查。

实现归 `ui/workflow/`，复用 WP-04 项目命令、WP-11 安全读取和 WP-13 URDF 语义映射。GUI 验收并入 WP-22-T05 的 `sdurws_ird_workflow_test`；T05 的前置增加 T06。

## 8. 任务卡统一 UI 验收字段

每张 GUI 卡必须明确写入：

1. 权威 UI 章节和版本；
2. 允许创建、修改和删除的精确路径；
3. 禁止修改的公共接口和其他业务插件；
4. Dock 名称、页面分区、字段组、表格列和主要操作；
5. 每个主要按钮的启用、禁用和运行中状态；
6. 空态、输入错误、计算失败、结果过期和部分结果行为；
7. 表格—三维—属性面板选择联动；
8. 1920×1080 与 100%、125%、150% 缩放要求；
9. 中央三维视图保持和其他插件布局保护；
10. 用户界面禁止内部术语的静态扫描；
11. RED 测试、正常/边界/失败三类 Given/When/Then；
12. Windows Qt GUI 的逐个绝对路径执行规则；
13. 证据路径、截图矩阵、命令、退出码和实现提交；
14. 公共组件不足、契约未接受或所有权冲突时的停止条件。

## 9. 追踪与生成资产

- 新增任务卡后，由 `generate-traceability.ps1` 重生成 `requirement-traceability.csv`，禁止手工编辑。
- 新卡分别追踪 UX、对应领域需求和验收场景；任务卡必须出现在相关需求行的任务集合中。
- 文档校验器和任务卡索引使用当前文件实际数量，不在脚本中硬编码 144 或 150；说明文档可以记录当前预期为 150。
- 新增 GUI CMake 目标必须在任务卡、工作包、模块方案和测试入口中名称一致。

## 10. 状态与契约门禁

本次治理修改完成后：

- `WP-00-T01` 保持当前唯一 `Ready`；
- 六张新增任务全部登记为 `Planned`；
- 既有 `Planned` 任务不提前解锁；
- 契约注册表仍保持实际状态，不用文档提交伪造 `Accepted`；
- 独立治理者在 WP-00 及后续前置完成后，才按九项门禁逐卡改为 `Ready`。

因此“可直接开始”表示智能体能够立即领取当前唯一 `Ready` 任务，并在后续任务逐卡解锁时无需重新决定 UI 所有权和验收语义，而不是绕过依赖同时开发全部任务。
