## 1. 执行摘要

本项目拟基于 RobWork、RobWorkStudio 和 RobWorkSim，建设一套面向工业机械臂方案设计与初步设计阶段的工程软件。软件服务于 4～7 轴工业串联机械臂的新机型设计和既有机型改型，帮助工程人员把分散的建模、需求表达、运动学验证、轨迹规划、动力学校核、驱动选型和结构优化工作串成一条可复核的设计链路。

软件的首要业务价值不是“提供更多算法按钮”，而是产生优于单纯人工试算的优化与选型候选，并清楚回答：

- 当前机械臂方案能否完成规定任务；
- 不能完成时，问题出在结构、姿态、关节范围、碰撞、节拍、动力还是器件能力；
- 哪些结构尺寸、质量参数、传动比和器件组合更值得进入下一轮设计；
- 每个结论基于什么模型、任务、配置和计算证据。

产品采用“共享领域内核 + 统一计算任务层 + 七个薄界面插件”的总体架构。RobWork 提供数学、运动学、碰撞和路径规划基础；RobWorkStudio 作为桌面宿主和三维场景中心；RobWorkSim 提供刚体动力学模型、递归牛顿—欧拉算法和物理仿真基础。七个业务插件分别承担需求定义、机械臂建模、运动学、轨迹规划、动力学、电机/减速器选型和联合优化。

运动学、碰撞和动力计算只消费一个从权威参数化确定性编译的 SE(3) 规范模型；DH 只是编辑与交换视图，不是运行时真值。插件只提供编辑入口和结果解释，共享数据的唯一写入者是项目命令服务。

跨插件引用使用稳定对象 ID，RobWork 中 `RobotName.LocalName` 形式的设备作用域全名只由统一名称解析器生成；碰撞等跨插件工程逻辑只使用统一策略对象和共享评估器。名称前缀、碰撞开关、排除规则、安全距离或默认值不得在各插件中分别实现。

本次重构允许项目格式断代，不建设旧格式兼容层。现有代码中经过测试的算法、转换器和项目基础设施应迁移复用；旧界面、重复模型、临时适配层和失去用途的代码应在新链路通过验收后立即删除，不长期保留双轨实现。

发布按两个切片推进：R1 工程闭环版（建模、需求、运动学、轨迹、逆动力学、基础选型、报告）和 R2 优化规模化版（并行、检查点、联合优化、鲁棒性和大型性能目标），详见第 14 章。

## 2. 背景与现状判断

### 2.1 RobWork 能力边界

根据 RobWork 官方手册和本仓库锁定源码版本：

| 组成 | 适合承担的职责 | 本产品中的定位 |
| --- | --- | --- |
| RobWork | 数学、坐标变换、机器人模型、正/逆运动学、碰撞检测、路径规划和轨迹基础 | 权威基础算法库，不承载产品工作流 |
| RobWorkStudio | WorkCell 三维显示、状态交互、Qt 插件基础设施 | 桌面宿主、三维场景中心和插件容器 |
| RobWorkSim | DynamicWorkCell、刚体、递归牛顿—欧拉、物理引擎和仿真设备 | 动力学计算与正动力学验证基础 |

RobWork 官方将核心定位为机器人 C++ 工具箱，而不是完整的业务协作平台。因此，项目管理、工程数据语义、分析依赖、结果追溯、器件目录和产品化交互需要由本软件补齐，而不是继续堆入单个 RobWorkStudio 插件。

外部网页手册会随版本漂移，不作为验收依据；正式基线以第 11.5 节锁定的仓库版本为准。

### 2.2 已有二次开发成果

当前仓库已具备较多可复用资产，不应简单推倒重来。

| 领域 | 已有能力 | 建议 |
| --- | --- | --- |
| 项目基础设施 | `.rwproj` 清单、资源 Provider、事务保存、相对路径、项目创建/导入向导、工作流阶段状态 | 保留并收敛为新项目外壳 |
| 机械臂建模 | 参数化模型、标准 DH、关节位姿、URDF 导入、WorkCell/XML 生成、碰撞几何和模型指纹 | 保留转换与序列化内核，重建领域模型和界面 |
| 需求定义 | 任务点、工作区域、姿态规则、接近/撤离、Must/Should、校验、执行契约和诊断码 | 保留语义规则，改为自动快照而非显式冻结操作 |
| 运动学分析 | FK/IK、候选排序、关节裕量、奇异性、可操作度、碰撞、任务批处理、区域覆盖、三维诊断和导出 | 保留计算内核，拆分巨型界面和状态管理 |
| 结构优化 | 设计变量、候选模型、硬约束、随机/网格/拉丁超立方、Quick/Verified、缓存、灵敏度、快照和报告 | 保留可信组件，替换固定权重单目标决策和单线程编排 |
| 分析共享层 | 需求执行类型、工程评价接口、JSON/CSV、指标注册 | 扩展为统一领域与评估契约 |

现有四个业务插件约包含 9.7 万行 C++（含测试）。部分主界面文件体积过大，其中 `KinematicAnalysisWidget.cpp` 约 462 KB，说明界面已经承担了过多业务状态、计算编排和结果解释。结构优化目录中的文件数量和职责明显多于其他插件，且现有审查记录已发现双数据源、异步结果串项目、候选快照错配、变量语义冲突和重复持久化等问题。

### 2.3 当前主要问题

1. **领域对象不统一**：模型、需求、任务、候选和分析结果在不同插件中有重复或相似表达，容易形成双数据源。
2. **界面与业务耦合**：Widget 同时负责编辑、校验、运行、状态判断、文件读写和结果解释，难以测试和维护。
3. **插件之间通过实现细节协作**：下游逻辑容易依赖上游控件状态、私有 JSON 或当前 WorkCell 状态，而不是稳定契约。
4. **结果有效性对用户过于显性**：当前“发布、冻结、指纹、Stale”等内部概念会增加工程人员负担。
5. **优化能力尚未形成系统工程闭环**：现有优化以结构运动学和固定权重评分为主，未接入轨迹、动力学、器件选型与 Pareto 决策。
6. **大型任务能力不足**：当前优化为单工作线程；数千任务点、10 万级采样和万级候选需要新的任务调度、并行、缓存和检查点机制。
7. **历史兼容代码累积**：旧格式、Legacy 适配和新旧链路并存会持续扩大复杂度，本轮重构不再以历史文件兼容为目标。
8. **关节轴尚未成为一等领域数据**：现有 `JointTransformSpec` 只保存关节类型、RPY 和位置，运动轴被隐含为经姿态旋转后的局部 Z 轴。URDF 任意轴会在导入时折叠进 RPY，虽能维持当前串联模型的运动学等价，但原始轴、轴来源和轴对齐补偿无法独立编辑、追溯或无损往返。

## 3. 产品定义

### 3.1 产品愿景

让机械臂设计工程师在一个工程项目中完成“需求—方案—验证—优化—选型—评审”闭环，用可解释的计算证据缩短结构方案和驱动方案的反复试算周期。

### 3.2 目标用户

| 角色层级 | 用户 | 首版关键任务 | 成功表现 |
| --- | --- | --- | --- |
| 核心操作者 | 机械臂总体/结构工程师 | 建立或改造方案、设置变量、比较候选 | 不依赖软件开发人员即可完成标准主流程 |
| 专业操作者 | 运动学/轨迹工程师 | 验证可达、奇异、碰撞、连续运动和节拍 | 能从失败证据定位到任务、姿态、路径段或关节 |
| 专业操作者 | 动力学/驱动工程师 | 核算力矩、转速、功率并复核器件组合 | 关节侧需求、传动假设和器件裕量来源一致 |
| 结果消费者 | 项目/评审负责人 | 比较候选、确认风险和设计依据 | 能从报告独立复核输入、取舍、限制和未决风险 |
| 平台扩展者 | 软件与算法研发人员 | 扩展算法、插件和数据格式 | 通过稳定端口开发，不需要访问其他插件界面实现 |

### 3.3 业务目标

| 编号 | 目标 | 验收口径 |
| --- | --- | --- |
| OBJ-01 | 建立完整设计闭环 | 标准搬运案例可从建模运行至候选报告，中途不依赖外部手工拼接数据 |
| OBJ-02 | 产生优化与选型价值 | 能生成满足全部硬约束的 Pareto 候选，并解释候选相对基线的改进与代价 |
| OBJ-03 | 保证结论可信 | 每个正式结果可复算，且能定位到输入、算法设置和失败证据 |
| OBJ-04 | 降低工程使用门槛 | 常用流程不要求用户理解插件、哈希、Schema、冻结契约或求解器内部对象 |
| OBJ-05 | 支持大型批量分析 | 大任务在后台执行，可取消、恢复、流式查看，不阻塞或破坏项目 |
| OBJ-06 | 建立可持续代码基础 | 业务内核可独立测试；新旧链路不长期并存；重复能力只有一个权威实现 |

首个真实试点采用以下产品成功指标：

- 至少 5 名目标用户中，80% 能在不依赖软件开发人员操作的情况下完成标准搬运主流程；
- 标准项目从导入模型到生成候选报告，人工跨工具复制或手工拼接数据次数为 0；
- 相同快照复算的离散结论一致率为 100%，数值结果满足第 15.3 节容差；
- 正确性门槛：若不存在可行或改进候选，软件必须提供可复核的约束与搜索证据，不得强行给出“最优方案”；
- 业务价值指标：试点开始前由工程负责人签署并锁定基线、变量域、计算预算和保护指标；试点结束时至少一个候选被确认进入下一轮详细设计，且相对基线在质量、节拍、能耗或成本之一改善不少于 5%，同时保护指标不越过签署阈值；
- 试点发布时开放 Blocker 级缺陷为 0，未关闭 Critical 级缺陷均有负责人、影响说明和计划日期（缺陷等级定义见第 15.4 节）。

### 3.4 产品范围

首版范围：

- 一个项目当前只允许一个 `RobotDesign` 和一条目标可动串联主链；多机械臂不属于首版可计算范围；
- 4～7 轴工业串联机械臂（可含移动关节，动力与选型范围限制见第 8.5、8.6 节）；
- 新机型方案设计和既有机型参数改型；
- DH/关节位姿参数化建模、URDF 导入、STL/网格引用；
- 任务点、工作区域、接近/撤离、负载、障碍和节拍需求；
- 运动学、碰撞、路径、时间参数化和刚体动力学分析；
- 电机/减速器企业目录导入、筛选与组合校核；
- 结构、传动比和器件的分层联合优化；
- 候选比较、报告、自动快照、结果失效与恢复。

首版非目标：

- 一个项目内多机械臂协同、机器人间碰撞与任务同步；
- 从 STEP/CAD 装配自动识别关节和机械语义；
- 柔性体、结构强度、热、间隙、磨损、寿命等多物理高保真分析；
- 控制器代码生成、PLC 虚拟调试和现场安全认证；
- 移动机器人、并联机器人和复杂多机器人系统的正式支持；
- 云端账号、多人在线编辑、审批流和计算集群；
- 由软件团队持续维护完整真实厂商器件目录；
- 兼容或迁移现有旧项目格式。

软件输出属于方案设计和初步设计建议，不是制造图纸、详细结构校核或安全认证结论。电机、减速器和优化候选必须由具备相应职责的工程师复核后才能进入详细设计，软件不替代最终设计签署责任。

当前项目边界与扩展约束：首版 `ProjectRevision` 只能引用一个 `RobotDesign`，所有任务、工具、环境和结果均隐含属于该机械臂作用域。领域对象仍必须保存 `ownerScopeId`，运行时名称使用设备作用域映射；未来支持多机械臂时，通过把 `RobotDesign` 从单值扩展为按 `robotId` 索引的集合，并为任务、碰撞对、工具和结果增加明确机器人引用实现，不改变既有对象 ID 或 `.rwdesign` 目录语义。首版不得提前实现多机械臂 UI、调度或协同算法。

## 4. 产品与工程原则

1. **工程任务优先于插件**：用户看到的是设计阶段和下一步操作，不需要理解内部插件边界。
2. **一份数据，一个权威来源**：模型、需求、轨迹、器件和候选均只有一个领域定义；插件提供编辑入口，共享数据的唯一写入者是项目命令服务，插件不能复制后私自修改。
3. **临时操作与设计修改分离**：Jog、IK 预览、轨迹播放和临时显示不改变设计，不触发重算。
4. **结果必须带证据**：失败、不可行和数据不足必须区分，不得把“未检测”显示为“通过”，不得把“计算完整”显示为“证据完整”。
5. **硬约束先行**：Must 任务、碰撞、关节范围、动力和器件能力不允许被加权总分掩盖。
6. **默认简单，高级可见**：主界面只显示工程语言和必要参数；算法细节进入高级面板。
7. **长任务与界面隔离**：任何大批量计算不得占用 GUI 线程；结果按批次返回并可取消。
8. **迁移完成即删除旧实现**：Git 历史承担归档作用，源码树不保留长期双轨。
9. **避免过度防御**：校验集中在文件、用户输入、插件接口和工作进程等真实边界；领域内部不层层重复校验。
10. **避免样板抽象**：新增接口或包装层必须消除重复、隔离真实变化或提升可测试性，否则不引入。
11. **运动学权威源互斥**：标准 DH 与通用关节定义可以同时存在，但每个模型同一时刻只能有一个可编辑的权威参数化；另一种表示只能由系统生成并标明派生状态，不做破坏性双向同步。
12. **规范计算模型唯一**：无论权威参数化是 DH 还是显式关节，运行时只存在一个从权威表示确定性编译的 SE(3) 关节链规范模型（第 7.3 节）；DH 永远不是运行时真值。
13. **批量探索产物不是设计修订**：优化候选、筛选结果和扰动样本归运行结果所有，不进入项目修订历史；只有用户确认的设计决策（如“设为当前方案”）才产生新修订。
14. **身份与显示名称分离**：插件间引用一律使用稳定对象 ID；RobWork 中带机械臂名称前缀的运行时全名只在适配边界生成和解析，不把字符串拼接当作对象身份。
15. **工程策略单一权威**：碰撞、关节限制、单位/坐标约定、证据等级和其他跨插件规则分别只有一个类型化策略对象与一个权威实现；插件只能编辑或消费，不能维护私有开关、默认值或分叉算法。

## 5. 统一工作流

### 5.1 主流程

```text
创建或导入项目
  → 建立机械臂与环境
  → 定义任务需求
  → 运动学预检
  → 规划路径并计算节拍
  → 动力学校核
  → 电机/减速器匹配
  → 分层联合优化
  → 比较候选并输出评审报告
```

主窗口提供项目驾驶舱，显示每个阶段的输入完整度、当前结果状态、关键结论和下一步建议。工程师可自由返回上游修改，但软件必须明确显示受影响的下游结果需要重新计算。

### 5.2 新机型设计流程

1. 从串联机械臂模板创建项目，选择“标准 DH”或“通用关节”权威参数化，定义轴数、关节类型、关节原点、轴线和初始尺寸。
2. 选择材料和截面，软件估算质量、质心和惯量；已知数据可覆盖估算值。
3. 定义典型搬运任务、工具与 TCP、负载、障碍、节拍和安全裕量。
4. 完成运动学和路径预检，排除明显不合理的构型。
5. 计算动力包络并得到初始器件组合。
6. 联合探索结构尺寸、传动比和器件，输出 Pareto 候选。
7. 选择候选形成新方案分支，复算后进入工程评审。

### 5.3 既有机型改型流程

1. 导入 URDF 或现有参数模型，以通用关节表示生成不可修改的基线修订，并生成字段映射与不支持项报告。
2. 从基线创建可编辑方案分支，再校对或修正关节原点、轴线、限制、质量、惯量、工具/TCP 和碰撞模型；如需 DH，先执行可表达性与 FK 等价分析。
3. 选择允许修改的参数，其他参数默认锁定。
4. 用同一任务集评价基线和改型候选。
5. 报告必须给出每项指标相对基线的变化，避免只展示候选绝对分数。

### 5.4 用户可见状态

用户只看到以下状态：

| 状态 | 含义 | 用户动作 |
| --- | --- | --- |
| 输入未完成 | 缺少运行所需信息 | 按问题清单补充输入 |
| 可计算 | 输入完整且通过校验 | 启动当前阶段计算 |
| 计算中 | 后台任务正在运行 | 查看进度、暂停或取消 |
| 结果有效 | 结果对应当前设计输入 | 查看、比较或进入下一阶段 |
| 需要重算 | 相关设计输入已变化 | 查看变化原因并重新计算 |
| 证据不足 | 计算完成，但缺少碰撞、物性、目录或采样证据 | 补充数据或降低结论用途后重算 |
| 计算失败 | 系统未完成计算 | 查看错误和恢复建议 |
| 工程不可行 | 计算完成但违反工程约束 | 查看违反项并修改方案或需求 |

内部仍保存 Schema 版本、输入指纹、随机种子和算法配置，但普通界面不显示哈希值。

上表描述阶段结果，不代替任务执行状态。全局任务面板使用“排队中、运行中、暂停中、已暂停、取消中、已取消、已中断、失败、完成”显示任务生命周期；已取消、已中断或失败不会被显示成工程不可行。

### 5.5 会话态、编辑草稿与已应用设计

界面使用三个简单层次，计算只读取“已应用设计”：

1. **会话显示态**：视角、隐藏、着色、筛选、Jog 和播放位置，不保存为设计输入；
2. **编辑草稿态**：表单中尚未点击“应用”的修改，可以随项目保存为草稿，但不参与计算；
3. **已应用设计态**：当前方案、需求、分析配置、目录版本和优化研究定义，计算从这一层自动生成不可变快照。

以下操作属于会话态，不修改项目设计，也不使结果失效：

- Jog 移动机械臂；
- 双击任务点应用某个 IK 候选；
- 播放或暂停轨迹；
- 预览优化候选；
- 临时隐藏、着色或调整视角；
- 切换图表、单位显示和列表筛选。

以下操作属于设计修改，只有用户在一个表单或一组批量修改完成后确认“应用”，才产生新的项目修订并使相关结果显示为“需要重算”；不得对每个单元格弹出确认：

- 修改 DH、关节轴、零位、范围、速度或加速度限制；
- 修改结构尺寸、材料、质量、质心或惯量；
- 修改工具、TCP、负载、基座或障碍；
- 修改任务目标、区域、姿态、容差、路径规则或节拍；
- 修改器件目录、选型安全系数或优化变量/约束。

运行分析时系统自动保存只读输入快照，用户无需执行“发布”或“冻结”。

后台任务始终绑定启动时的项目修订。任务运行期间应用新设计时，旧任务可以继续并作为历史结果查看，但不得覆盖当前修订的结果状态。预览优化候选时，Jog、IK 预览和轨迹播放都投影到该候选的临时场景；退出预览后恢复当前方案。

## 6. 总体架构

### 6.1 分层

| 层次 | 职责 | 约束 |
| --- | --- | --- |
| RobWork/RobWorkSim 基础层 | 数学、模型、运动学、碰撞、规划和动力学 | 尽量通过稳定 API 使用，不写入产品状态 |
| 工程领域内核 | 统一业务对象、单位、坐标系、来源、依赖和状态 | 不依赖 Qt Widgets，不包含插件界面逻辑 |
| 计算与任务层 | 评估器、任务调度、缓存、检查点、工作进程和结果快照 | 计算输入不可变；不得回读当前界面状态 |
| 七个业务插件 | 编辑入口、可视化、运行入口、结果解释和工程建议 | 不访问其他插件控件或私有文件；不是共享数据的写入者 |
| 项目与报告横切层 | 项目清单、事务保存、恢复、诊断、报告和本地化 | 对所有插件提供一致行为 |

### 6.2 插件边界

插件“提供编辑入口”不等于“拥有数据”：所有共享领域对象的写入都通过项目命令服务完成（第 6.3 节）。

| 插件 | 提供编辑入口的对象 | 调用的共享能力 | 不应承担的职责 |
| --- | --- | --- | --- |
| 机械臂建模 | `RobotDesign`、`ToolDefinition`、`EnvironmentModel` | 模型编译、导入、质量惯量估算 | IK、优化搜索、器件筛选 |
| 需求定义 | `EngineeringRequirements` | 坐标解析、语义校验、批量导入 | IK、覆盖率计算、动力学 |
| 运动学 | 运动学配置 | FK/IK、共享碰撞评估、指标评估 | 修改权威模型/策略，或维护本地碰撞开关与排除规则 |
| 轨迹规划 | 路径约束与规划配置 | 路径规划、平滑、时间参数化、共享碰撞评估 | 私自计算另一套任务可达性或复制碰撞规则 |
| 动力学 | 动力学配置、摩擦与载荷假设 | 逆/正动力学、包络统计 | 维护器件目录或优化搜索 |
| 器件选型 | 目录版本引用、选型规则 | 组合筛选、曲线插值、裕量计算 | 修改轨迹或结构参数 |
| 优化 | `OptimizationStudyDefinition`、候选决策 | 编排各评估器、搜索、Pareto 分析 | 重复实现运动学、动力学和选型 |

### 6.3 权威所有权与插件端口

`ProjectRevision` 是已应用项目状态的聚合根，首版恰好拥有一个 `RobotDesign`，并统一拥有 `ToolDefinition` 引用、`DriveTrainDesign`、`EnvironmentModel`、`EngineeringRequirements`、`LoadCase`、`EngineeringPolicySet`、分析配置、`CatalogVersionRef` 和优化研究定义。所有机器人相关对象保存 `ownerScopeId`，首版该值必须等于项目的唯一 `robotId`；未来扩展为多机械臂时改为显式机器人索引，不依赖名称推断。插件不得直接写共享文件或修改其他插件持有的内存对象，只能向项目服务提交领域命令，由项目服务原子地产生新修订。

数据的唯一权威位置冻结如下：

| 数据 | 唯一权威位置 | 说明 |
| --- | --- | --- |
| 机器人法兰与默认 TCP | `RobotDesign` | 法兰坐标系和无工具默认 TCP |
| 可安装工具定义及工具几何 | `ToolDefinition` | 建模插件维护；任务与负载按引用使用，不复制几何 |
| 任务过程中的负载、夹取、释放 | `LoadCase` | 引用 `ToolDefinition` 与工件定义 |
| 当前已采用的传动方案 | `DriveTrainDesign` | 选型“应用”通过项目命令写入，选型插件不直接改设计 |
| 目录内容 | 不可变 `CatalogVersion` | 目录一经导入即不可变，更新产生新版本 |
| 项目中的目录选择 | `CatalogVersionRef` | 项目修订持有引用，历史结果不因目录更新而变化 |
| 选型结果 | 只读 `ComponentSelectionResult` | 属于运行结果，不直接修改设计 |
| 基座与障碍 | `EnvironmentModel` | 优化变量引用其字段路径，不复制第二份数据 |
| 稳定对象身份与局部名 | 各领域对象的 `ObjectIdentity` | 跨插件引用使用 `objectId`；名称不是主键 |
| RobWork 设备作用域全名 | 编译产物 `RuntimeNameMap` | 由 `IRuntimeNameResolver` 唯一生成和反解，不回写为领域主键 |
| 碰撞及其他跨插件工程规则 | `EngineeringPolicySet` | 项目命令统一修改；评估器只消费已解析策略，插件不保存私有副本 |

优化变量是对上表权威对象字段的引用（字段路径 + 值域），不存在独立的候选数据存储；候选的取值与结果归属 `OptimizationRunResult`（第 7.4 节）。

- 建模插件提供机器人、工具、传动基础参数和物理环境的编辑入口；
- 需求插件引用环境对象和工具定义，拥有任务场景、负载工况、所需证据等级和工艺事件的编辑入口；碰撞配对、参与对象和验证参数引用统一 `CollisionPolicy`，不再维护第二份障碍、工具几何或碰撞规则；
- 分析插件拥有各自的配置定义和不可变结果，不拥有上游模型；
- 优化插件拥有研究定义与运行结果，不拥有各评估器的领域算法；
- 报告横切层拥有 `ReviewReport`，只读取明确修订和结果，不读取当前界面。

薄插件通过以下稳定端口协作：

| 端口 | 职责 |
| --- | --- |
| `IProjectQuery` | 读取指定项目、方案分支和修订的领域对象 |
| `IProjectCommandService` | 校验并原子应用设计命令，产生新项目修订 |
| `IEvaluationScheduler` | 从不可变快照启动、暂停、恢复和取消任务 |
| `IResultRepository` | 追加和查询结果、证据及历史运行；工作进程不得直接写项目文件 |
| `ISceneProjection` | 把当前方案或候选投影到三维会话态，不回写设计 |
| `IDiagnosticCatalog` | 提供统一诊断码、中文文案和建议动作 |
| `IRuntimeNameResolver` | 在稳定对象 ID、领域局部名与 RobWork 设备作用域全名之间做唯一映射和反向解析 |
| `IEngineeringPolicyProvider` | 从指定项目修订/输入快照提供已解析的统一工程策略，不允许插件叠加私有默认值 |

这些端口用于建立真实边界，不为每个类机械增加接口或转发包装。

### 6.4 计算任务模型

所有长任务统一使用以下概念接口，具体 C++ 类型可在技术设计阶段定名：

```text
EvaluationRequest
  - projectId
  - branchId / projectRevision（SourceRevisionRef）
  - inputSnapshotId / evaluatorInputSliceId
  - runId / attemptId
  - evaluatorId / evaluatorVersion
  - evaluationMode: Quick | Verified
  - settings
  - settingsHash
  - randomSeed
  - resourceBudget

EvaluationResult<T>
  - outcome: Completed | Canceled | Failed | Interrupted
  - engineeringStatus: Pass | Warning | Infeasible | DataInsufficient | NotEvaluated
  - payloadCompleteness: Complete | Partial | None
  - payload: T
  - evidence
  - diagnostics
  - timing / resourceUsage

IEngineeringEvaluator<Request, Result>
  - dependencyManifest()
  - validate(request)
  - evaluate(request, progress, cancellation)

TaskHandle
  - capabilities()
  - progress()
  - pause()
  - resume()
  - cancel()
  - checkpoint()
```

轻量交互计算可在进程内运行；长时间优化、批量 IK 和批量动力学允许进入独立工作进程。工作进程只接收不可变快照，完成事件必须校验项目和运行身份，旧任务不得写入已切换的新项目。

合法结果组合为：`Completed` 可以对应 Pass、Warning、Infeasible 或 DataInsufficient，并提供完整结果；Canceled、Failed 或 Interrupted 只能对应 NotEvaluated，最多提供明确标记为 Partial 的诊断结果，不能进入正式报告或可行 Pareto 集。输入校验失败不创建运行结果。“正式可行”的完整判定见第 6.6 节。

长任务状态机统一为：

```text
Queued → Running → Pausing → Paused → Running
Queued | Running | Pausing | Paused → Canceling → Canceled
Running | Pausing | Paused | Canceling → Failed | Interrupted
Running → Completed
```

并非所有轻量任务都必须暂停或检查点恢复，任务通过 `capabilities()` 声明能力。暂停、取消和恢复只能在批次或评估器声明的安全点完成。终止原因与最终状态的对应关系冻结为：

| 终止场景 | 最终状态 | 附加要求 |
| --- | --- | --- |
| 用户取消后因超时强制终止工作进程 | `Canceled` | 附“强制终止”诊断，保留最近检查点 |
| 非用户触发的工作进程异常退出 | `Failed` | 附退出原因诊断 |
| 应用退出或系统中断后重启发现未完成运行 | `Interrupted` | 不得伪装为完整结果，检查点可恢复 |

### 6.5 阶段 A 架构契约需求

| 编号 | 优先级 | 要求 |
| --- | --- | --- |
| ARC-01 | P0 | `ProjectRevision` 是已应用共享数据的唯一聚合根，插件通过领域命令原子地产生新修订 |
| ARC-02 | P0 | 业务插件只能通过第 6.3 节稳定端口协作，不读取其他插件控件、内存对象或私有文件 |

| ARC-04 | P0 | 跨插件、结果和持久化引用使用稳定对象 ID；RobWork 设备作用域全名只由第 6.7 节统一名称解析器生成/反解，禁止各插件自行拼接、剥离或猜测机械臂名称前缀 |
| ARC-05 | P0 | 跨插件工程逻辑遵循第 6.7 节统一策略契约；碰撞等共享规则只有一个权威策略对象和一个共享评估实现，插件不得持有影响计算的私有开关、默认值或重复算法 |

| TASK-03 | P0 | 请求和完成事件携带项目、分支、修订、运行和尝试身份，旧任务不得成为其他会话的当前结果 |
| ERR-01 | P0 | 执行状态、工程判定和诊断类别正交；稳定诊断项以 `subjectObjectId` 绑定对象，并包含局部/运行时名称、实际值、期望值和建议动作 |
| EVI-01 | P0 | 评估模式、证据等级与 `RequiredEvidenceProfile` 契约及第 6.6 节正式可行判定全局唯一 |

### 6.6 评估模式与证据等级

`EvaluationMode` 与 `EvidenceLevel` 是全局正交契约，所有评估器统一使用，不允许多套口径：

```text
EvaluationMode = Quick | Verified
EvidenceLevel  = Screening | PreliminaryDesign | ExternallyValidated
```

- **Quick**：快速近似计算，用于排序、预览与大规模筛选；不得作为正式通过证据，可证明保守的硬淘汰规则除外（第 9.4 节）。
- **Verified**：正式证据级计算，可进入正式报告与可行 Pareto 集。
- **EvidenceLevel** 描述输入数据的可信度：`Screening`（筛选级，允许参数估算）、`PreliminaryDesign`（初步设计级，关键物性与目录数据已确认）、`ExternallyValidated`（外部验证级，已与独立工具或实测对照）。证据不足不得自动提升等级。
- **RequiredEvidenceProfile**：每种正式用途（如“Verified 候选进入评审报告”）声明必需评估器集合、各评估器最低证据等级、必需资源保真度（碰撞几何、目录曲线、物性来源）和允许警告类别。

正式可行判定冻结为：

```text
正式可行 ⇔
  所有必需评估器 outcome = Completed
  ∧ 对应 payload = Complete
  ∧ 证据等级满足 RequiredEvidenceProfile
  ∧ 不存在 DataInsufficient
  ∧ 不存在硬约束违反
  ∧ 执行模式 = Verified
```

违反任一条时不得显示“正式可行”，界面必须列出具体缺口。“计算完整”（Completed + Complete）不等于“证据完整”，实现与测试均以此谓词为准。

### 6.7 名称身份与统一工程策略

#### 6.7.1 RobWork 设备作用域名称

领域对象必须把身份、工程显示名和 RobWork 运行时名称分开：

```text
ObjectIdentity
  - objectId              稳定、不可由名称推导
  - ownerScopeId          Robot/Tool/Environment 等所有者作用域
  - localName             作用域内工程名称，例如 Joint1、TCP

RuntimeNameBinding
  - objectId
  - runtimeDeviceName     当前 RobWork Device 名称
  - runtimeScopedName     runtimeDeviceName + "." + localName
  - objectKind
```

- 在本产品生成或加载的 RobWork Device 内部，Joint、Frame、Device 所属 Object/Model 及其引用使用区分大小写的设备作用域全名，例如 `RobotA.Joint1`；`.` 是作用域分隔符。`WORLD` 和不属于该 Device 的外部场景对象不添加机械臂前缀，而使用各自作用域。
- 领域层、插件端口、项目文件、优化变量、关节限制、动力学 Link、碰撞对和允许接触对均引用 `objectId`，可以同时保存 `localName` 供显示，但不得把 `RobotA.Joint1` 字符串作为跨插件主键。
- 模型编译器一次性生成不可变 `RuntimeNameMap`；所有 WorkCell、DynamicWorkCell、CollisionSetup、ProximitySetup、轨迹、动力学和报告适配器复用该映射。除 `IRuntimeNameResolver` 实现内部外，禁止出现 `robotName + "." + localName` 或任意前缀剥离逻辑。
- 从 WorkCell/URDF/项目资源导入时，名称规范化只在导入边界执行一次。解析器同时接受受支持的局部名和设备作用域全名；双前缀、未知前缀、同一字符串映射多个对象或去前缀后重名必须报错，不得取第一个匹配项。
- 修改机械臂工程名称时，稳定 `objectId` 和领域引用不变；项目命令重新生成唯一 `runtimeDeviceName`、原子重编译全部运行时文件和名称映射。新模型中不得残留旧前缀，也不得出现 `RobotB.RobotA.Joint1` 一类双前缀。单纯重命名不改变基于对象 ID 的物理输入切片，因此不使既有数值结果需要重算；历史证据保留旧快照名称，新执行使用新映射。
- 普通界面默认显示 `localName`；诊断、导入报告和高级面板可同时显示局部名与运行时全名。错误必须优先绑定 `objectId`，即使运行时名称变化仍能定位同一工程对象。

#### 6.7.2 统一工程策略与碰撞语义

跨插件工程规则以项目修订内唯一的 `EngineeringPolicySet` 表达。策略是不可变值对象，通过项目命令修改并进入评估输入切片；它不是全局可变单例，也不是散落在 Widget、评估器和 XML Writer 中的若干布尔值。

首版 `CollisionPolicy` 至少区分：

```text
CollisionPolicy
  - collisionExecutionMode Enabled | DisabledForDraft
  - detectorBackend / version
  - collisionParticipationByObject
  - excludedPairs
  - allowedContactPairs
  - safetyDistance
  - pathValidationProfile  第 15.3 节细分/分辨率参数
  - policySchemaVersion
```

- `collisionExecutionMode` 只控制工程计算，不得与第 6.6 节全局 `EvaluationMode = Quick | Verified` 混用。`DisabledForDraft` 允许不带正式碰撞结论的草稿预览；当 `RequiredEvidenceProfile` 要求碰撞证据时，就绪校验必须阻止 Verified，而不是由某个插件静默重新开启或当作无碰撞。
- `collisionParticipationByObject` 决定哪些碰撞模型参与计算；`excludedPairs`/`allowedContactPairs` 决定配对规则；“显示碰撞几何”“高亮碰撞对象”是会话显示状态，不得改变上述计算策略、项目修订、缓存或结果当前性。
- `excludedPairs` 表示该对象对不进入检测，因此不能形成“已验证无碰撞”证据；`allowedContactPairs` 表示仍检测并记录接触，但按已批准工况不判为硬约束违反。同一对象对不得同时属于两者，未解析对象、重复/冲突规则或未说明来源必须阻止应用策略。
- RobWork `CollisionSetup`、`ProximitySetup` 以及路径验证器配置是同一 `CollisionPolicy` 的不同适配输出，不是三份权威配置。导入时先合并为一个策略草稿并报告冲突，导出时从同一策略和 `RuntimeNameMap` 确定性生成。
- 运动学、轨迹和优化必须调用同一个共享 `CollisionEvaluator`，并消费同一快照中的 `CollisionPolicy`、规范模型和 `RuntimeNameMap`。规划阶段需要不同采样密度时，只能选择策略内有版本的 `pathValidationProfile`，不能复制碰撞启用、排除或安全距离逻辑。
- 同一状态、同一策略下，各插件对碰撞对象、是否碰撞和允许/排除原因必须一致；差异只能来自显式记录的评估模式或验证 Profile，并在结果证据中展示。
- 其他跨插件规则采用同一模式：一个明确所有者、一个类型化策略对象、一个权威评估实现和一组稳定诊断码。新增规则前必须先确定权威位置和消费者，不允许先在某个插件增加局部开关再补同步逻辑。

## 7. 核心数据契约

### 7.1 共同约定

- 内部长度单位统一为 m，角度为 rad，质量为 kg，时间为 s，功率为 W；关节广义力类型化：转动关节为力矩 N·m，移动关节为力 N。界面可按工程习惯显示 mm、deg、kW。
- 每个姿态必须明确参考坐标系；不得依赖“当前选中坐标系”作为持久化语义。惯量张量必须连同参考点、参考姿态和参考坐标系一起保存。
- 每个可动关节必须显式保存 `Joint Type + Origin Pose + Axis`。`Origin Pose` 表示父连杆到项目坐标 `q=0` 时关节运动坐标系的刚体变换，`Axis` 在该关节坐标系中表达；轴必须为有限非零向量，进入领域对象时规范化并保留原始输入与来源。固定关节/固定 Frame 只保存 `fixed + Origin Pose`，Axis 为不适用且不执行缺失、规范化或零轴校验。本文 4～7 轴均指可动关节数。
- RPY 只作为界面输入和交换表示；持久化领域对象与计算接口使用无欧拉角奇异性的旋转表示。界面修改 RPY 时必须明确旋转顺序和单位。
- `KinematicAuthorityKind` 与来源信息正交：权威类型为 `StandardDH` 或 `ExplicitJoint`；`ImportOrigin` 记录模板创建、人工创建、URDF、WorkCell 或其他输入通道。URDF 导入完成后默认形成 `ExplicitJoint` 权威模型，而不是自动成为 DH 模型。
- 用户输入、导入文件和插件边界负责单位、范围、有限数和引用完整性校验。
- 单个工程值的 `ValueProvenance` 分为 `Estimated`、`Imported`、`UserSpecified`、`Measured`；它与 `ImportOrigin` 分别持久化，覆盖估算值时保留原来源和备注。
- 每个可被其他对象、插件、结果或报告引用的实体必须有稳定 `objectId`。`displayName/localName` 可以重命名，RobWork `runtimeScopedName` 可以重新编译，但任何引用都不得依赖字符串名称保持不变。
- `objectId` 在同一项目的分支、修订和重命名中保持不变；跨项目复制、重新导入或语义上新建对象必须生成新 ID，并在来源信息中记录原对象 ID。删除对象不复用旧 ID；历史结果继续绑定原 ID 并显示为历史证据。首版不支持自动合并两个分支，expected revision 冲突必须由用户选择保留或重新编辑。
- 影响计算结论的开关、默认值、阈值、包含/排除规则和算法 Profile 必须属于一个有 Schema 版本的类型化策略对象；会话显示状态不得混入工程策略。
- 结果对象不可原地修改；重新运行产生新的结果对象。
- 每个持久化对象使用统一头信息：Schema 版本、项目/分支/项目修订、对象 ID/对象修订、创建时间和来源。内容哈希用于内部追溯，默认不出现在界面。

结果内容身份与当前修订关联分离：结果对象的 `SourceRevisionRef`、输入切片和 payload 不可修改；当前项目只重新计算“切片是否匹配”的关联状态，不回写历史结果。运行时名称变化只影响 `RuntimeNameMap` 绑定校验，不改变基于 `objectId` 与物理内容身份的数值缓存键。

快照身份分两层，用于同时满足“完整溯源”和“字段级精确失效”：

- `SourceRevisionRef`：结果溯源到的项目修订，只用于展示与追溯；
- `EvaluatorInputSlice`：该评估器声明依赖的规范化输入切片及其内容身份。缓存键、当前性与失效判定只基于切片。

每个评估器通过 `EvaluatorDependencyManifest` 声明依赖：

```text
EvaluatorDependencyManifest
  - requiredFields            依赖的领域字段路径
  - requiredResources         网格、目录、物性等资源的版本与内容身份
  - requiredUpstreamArtifacts 上游结果引用（如 TrajectoryPlan 引用 KinematicResult）
  - optionalEvidence          不影响判定但进入报告的证据
```

`AnalysisSnapshot` 必须包含所有输入对象修订、分析配置、评估器与 RobWork/RobWorkSim 版本、随机种子、依赖清单、完整的已解析 `EngineeringPolicySet` 及 `RuntimeNameMap`。会影响判定的一切策略参数——包括碰撞开关、参与对象、后端、安全距离、细分参数、允许/排除接触对和扰动协议版本——都必须进入对应输入切片与缓存键，不得由插件运行时补默认值。进入 Verified 结果或正式报告的外部网格、目录、材料表和能力曲线必须复制到项目不可变资源区或内容寻址对象库，并在快照中保存内容哈希与副本引用；只保存外部路径和哈希的快照只能用于临时/Quick 结果。项目打包和资源清理不得删除仍被快照或报告引用的不可变资源。

### 7.3 运动学表示与权威性

#### 7.3.1 规范计算模型（运行时唯一真值）

所有运动学计算（FK、IK、Jacobian、轨迹、动力学建模）只消费一个规范模型：从权威参数化确定性编译得到的 SE(3) 关节链。每个可动关节相对父连杆的变换为：

```text
列向量齐次变换约定；乘积 A · B 对点先作用 B、再作用 A。

T_parent_joint(q) = OriginPose · Motion(â, q)

Revolute/Continuous:  Motion(â, q) = Rot(â, q)
Prismatic:            Motion(â, q) = Trans(â · q)
Fixed:                T_parent_child = OriginPose
```

契约要点：

- `â` 为规范化关节轴，在关节坐标系中表达；领域层同时保留原始输入轴与来源。
- `OriginPose` 在关节坐标系中完整定义 `q=0`（项目 Zero）；任何零位偏置只吸收在 `OriginPose` 内，运行时不叠加第二个偏置，避免双重偏置。
- 子连杆 Frame、视觉/碰撞几何、质心和惯量显式声明参考坐标系（默认所属连杆 Frame）；如需固定中间变换，编译为有稳定身份的固定 Frame，不改变可动关节数。
- `StandardDH` 权威只是编辑与交换视图：编辑 DH 后系统重新编译规范模型；反向导出 DH 仅在可表达性分析证明为 `Exact`/`ExactNonUnique` 时允许，有损投影必须拒绝或输出明确诊断，不得静默丢弃自由度（如非零 Y 偏移或绕 Y 旋转）。
- RobWork 以父子 Frame 变换树和独立 `State` 表达运动学，与该规范模型一致；适配层负责把规范模型编译为 WorkCell，不引入第二套运行时真值。

#### 7.3.2 权威参数化与转换

`RobotDesign` 必须区分“领域权威表示”和“运行时适配表示”：

- `StandardDH` 权威模型保存原生标准 DH 行、关节类型和变量语义；转动关节以 `theta` 为变量，移动关节以 `d` 为变量。系统由此生成对运动学语义无损的 `JointDefinition` 和规范计算模型。
- `ExplicitJoint` 权威模型直接保存 `JointDefinition`。任意 URDF 关节轴、特殊安装姿态和固定中间坐标系均以该表示保真保存。
- 两套数据可以共存，但只有权威表示可编辑。派生表示必须包含 `DerivedFrom`、转换算法版本和转换判定；不得在用户编辑通用关节后自动清零某个姿态分量、反算 DH 并覆盖原数据。
- 从 `StandardDH` 切换为 `ExplicitJoint` 是确定性转换，对权威运动学语义无损，切换会创建新的项目修订，原生 DH 作为旧修订证据保留。以后再由通用关节求解 DH 时不承诺逐项恢复原 DH 数值，因为等价 DH 可能不唯一。
- 从 `ExplicitJoint` 切换为 `StandardDH` 必须先执行可表达性分析。只有结果为 `Exact` 或经用户确认规范化方案的 `ExactNonUnique`，且 FK/轴线/附属坐标系验证通过时才允许切换。
- `Approximate` DH 只能作为只读诊断、初值或报告附录并显示残差；禁止参与 WorkCell 发布、正式分析或覆盖权威模型；其来源 `ExplicitJoint` 模型仍可按显式权威路径正常编译、发布和分析。`NotRepresentable` 不提供切换操作。

通用关节到标准 DH 的判定至少覆盖：单自由度转动/移动串联拓扑、标准 DH 行分解、平行/重合轴导致的非唯一性、重新分配连杆坐标系所需的几何与惯性补偿，以及固定中间变换。分支、闭环、并联、多自由度、耦合/Mimic、平面、浮动和其他超出标准 DH 的关节不得伪装成精确 DH。

DH `offset` 只在 DH→通用转换时参与生成 `q=0` 表示；Home 是独立的命名关节向量 `q_home`，不改变 Zero。

转换分析的规范状态如下：

| 状态 | 判定与允许动作 |
| --- | --- |
| `Exact` | 存在满足第 15.3 节 FK、全部世界轴线、Link 和附属 Frame 容差的标准 DH 表；允许预览并切换 |
| `ExactNonUnique` | 存在多个精确 DH 表；除满足 `Exact` 外，还必须输出规范化规则、备选原因并经用户确认后才能切换 |
| `Approximate` | 产生了候选 DH，但至少一项精确容差未满足；逐项报告残差，只读且禁止成为权威 |
| `NotRepresentable` | 拓扑/关节语义超出标准 DH 支持集，或确定性分析证明不存在精确分解；不提供切换 |
| `AnalysisFailed` | 求解器、资源或系统故障导致未完成判定；这是系统诊断，不得伪装成 `NotRepresentable` |

### 7.4 依赖与失效

核心依赖是有向无环图，而不是要求用户机械地按单向流水线操作：

```text
ProjectRevision
  = RobotDesign + ToolDefinition引用 + DriveTrainDesign + EnvironmentModel
    + EngineeringRequirements + LoadCase
    + EngineeringPolicySet + AnalysisConfiguration + CatalogVersionRef

ProjectRevision → KinematicResult
ProjectRevision + KinematicResult + IkBranchPolicy → TrajectoryPlan（含 ResolvedIkBranchSequence）
ProjectRevision + TrajectoryPlan + LoadCase → 关节侧 DynamicResult
DynamicResult + CatalogVersion + 选型规则
  → 各传动组合的电机侧校核 → ComponentSelectionResult（只读）

OptimizationStudyDefinition（绑定 BaselineRevisionRef + StudyDefinitionVersion）
  + DesignVector（对权威字段路径的取值）
      → CandidateInputSnapshot（临时不可变，不产生项目修订）
      → CandidateCompiler → CompiledCandidateArtifact（含 RuntimeNameMap）
      → 各域 Quick/Verified 评估结果
      → DesignCandidate（归属于 OptimizationRunResult）
      → 当前搜索域与预算内发现的 ParetoSet

用户执行“设为当前方案”
  → 项目命令创建方案分支 + 新 ProjectRevision → 完整复算

ProjectRevision + 选定结果集合 → ReviewReport
```

优化候选不产生 `ProjectRevision`：万级候选由 `IResultRepository` 按运行归档管理，可整体丢弃；只有“设为当前方案”才创建方案分支和正式修订。这避免修订历史膨胀、候选评估与设计修改混淆。

失效按依赖切片精确传播（第 7.1 节）。结果的当前性由其依赖切片的内容身份与当前修订对应切片比较决定，而不是比较整个修订号：

- 修改电机成本：运动学、轨迹评估器的输入切片不变，其结果保持“结果有效”，仅溯源引用更新；
- 修改 TCP：运动学切片变化，运动学及实际依赖它的下游结果显示“需要重算”；
- Jog、预览、播放：不改变任何切片。

旧结果仍是其原始快照的完整历史证据，只是与当前项目修订不再对应。内部使用 `完整性（Complete/Partial/Corrupt）`、`当前性（Current/Superseded）` 和 `工程判定` 三个正交维度，界面把 Superseded 简化显示为“需要重算”。

用户先做的器件选型是基线选型；联合优化中的器件选型复用同一个选型评估器，作为每个候选的内层计算，不形成第二套规则。

## 8. 七个插件功能需求

优先级定义：P0 是对应阶段形成可信闭环和发布所必需的能力；P1 是明确有价值但可在风险评审后延期的增强能力。P1 延期不等于删除，必须保留目标阶段和验收方法。P0 的范围解释遵循第 14 章发布切片：R1 范围 P0 支撑工程闭环，R2 范围 P0 支撑优化规模化。

第 7.3 节是运动学数据、变换公式和转换状态的规范性定义；本节只规定插件功能、用户操作、URDF 边界和验收，不另行改变数学语义。

#### 8.1.1 权威参数化和转换

| 操作 | 必须行为 |
| --- | --- |
| 编辑权威 DH | 原子更新原生 DH，并重新生成只读 `JointDefinition` 与运行时模型；不得再从浮点变换反推并覆盖原生 DH |
| 编辑权威通用关节 | 分别编辑类型、零位原点和轴；DH 区域只显示可表达性状态或只读投影 |
| DH→通用关节 | 使用统一标准 DH 约定确定性生成，对运动学语义无损；转换前后零位、Home、边界和采样状态的 FK、世界轴线及附属 Frame 一致，但不承诺日后反算得到逐项相同的 DH 数值 |
| 通用关节→DH | 先分析、再预览、后切换；非唯一时解释所选坐标系规范化规则，近似或不可表达时禁止设为权威 |
| 切换权威源 | 通过领域命令创建一个新项目修订，使实际依赖结果失效；旧修订和转换证据保留 |

首版标准 DH 统一采用 RobWork `type="schilling"` 约定，并以 `Rz(theta) · Tz(d) · Tx(a) · Rx(alpha)` 作为需求、预览、转换、XML 生成和报告的共同定义，不允许与改进 DH 或其他旋转顺序混用。DH 行必须包含关节类型：转动关节采用 `theta(q)=offset+q、d(q)=d0`，移动关节采用 `theta(q)=offset、d(q)=d0+q`；正方向遵循对应 +Z 轴的右手旋转或正向平移。当某个 RobWork XML DH 节点不能直接承载目标关节类型时，适配层应生成等价的通用 Joint/Frame，不能因此缩窄领域层标准 DH 语义。完整工程模型仍以 `RobotDesign` 为边界，DH 表本身不承担几何、碰撞、质量、惯量、限制、TCP 和器件语义。

#### 8.1.2 URDF 导入规则

- `<origin>` 解释为父 Link 到零位 Joint Frame 的变换；`<axis xyz>` 在 Joint Frame 中表达。长度、角度、质量和惯量按 URDF SI 语义导入。
- 轴规则只适用于 revolute、continuous 和 prismatic。显式轴可为任意方向，解析为双精度后必须全部有限；范数小于 `1e-12` 判为非法，否则规范化。非单位输入保留原值并报告规范化。缺失轴按标准使用 `+X`，生成带 `Defaulted` 警告的导入草稿；确认记录持久化前不得进入 Verified 分析。非法轴仍生成完整导入报告，但不得提交新项目修订或形成可计算 `RobotDesign`。不得沿用当前导入器在缺失 `<axis>` 时使用局部 `+Z` 的行为。
- 领域层保存原始 `Origin Pose + Axis`。如果 RobWork 运行时关节只沿局部 Z 轴运动，适配层可以生成轴对齐旋转，但必须同步补偿子连杆坐标、视觉/碰撞几何、质心、惯性坐标和惯量张量；该规范化不得改写领域层原始轴。
- `continuous` 必须保留连续语义；区域采样、优化和工程校核前要求用户定义工作范围，不得把任意 `±180 deg` 当作物理限位。
- 固定附件分支可以作为附件导入；存在多条可动分支时，只有用户明确选择一条 4～7 轴目标串联链后才能形成模型。被排除分支必须保存在导入证据并逐项报告，不得未经选择自动采用“最长/最佳链”。
- `planar`、`floating`、未知关节、Mimic/耦合、闭环和并联语义在首版均不得静默转为 FixedFrame。若它们位于目标链上，必须阻止形成可计算/可发布的 `RobotDesign`，不能通过主链选择绕过；若只位于被排除分支，仍须完整报告。
- URDF 不携带标准 DH 权威语义。URDF→DH 必须走第 7.3 节可表达性与等价验证，自动投影结果默认不具备权威性。
- 导入报告按 Error/Warning/Info 分类，至少列出字段路径、源值、采用值、原因和建议动作。任何被忽略、默认补全、规范化、重命名、资源缺失或拓扑裁剪都必须可观察。

| 编号 | 优先级 | 需求 |

| TRJ-01 | P0 | 支持关节空间点到点路径和由任务点组成的有序作业序列 |

| TRJ-03 | P0 | 调用 RobWork 规划器完成避障路径搜索，规划器与参数可配置 |
| TRJ-04 | P0 | 对路径进行简化和平滑；平滑后必须按第 15.3 节冻结的碰撞验证协议（自适应细分离散检测、安全距离、允许接触对与分辨率入快照）重新验证碰撞与关节限制 |
| TRJ-05 | P0 | 使用至少加速度连续的运动律按关节速度、加速度限制进行时间参数化，输出总节拍和分段时间 |
| TRJ-06 | P0 | 对无路径、分支跳变、奇异邻域和限制超标给出具体段落与原因 |
| TRJ-07 | P1 | 支持轨迹动画、曲线查看、路点局部重规划和标准轨迹导出 |
| TRJ-08 | P1 | 后续实现 jerk 上限、工艺速度和连续工艺轨迹；首版只保持评估接口可扩展，不创建空字段、空页面或占位模块 |

输入：规范模型、`RuntimeNameMap`、环境、需求、`LoadCase`、可用 IK 候选、`IkBranchPolicy` 和统一 `CollisionPolicy`。
输出：`TrajectoryPlan`。
关键异常：起终点不可行、无碰路径不存在、规划超时、IK 分支不连续、时间参数化失败。
P0 验收：标准搬运任务可生成完整时间轨迹并记录实际采用的 `ResolvedIkBranchSequence`；按同一 `CollisionPolicy` 和第 15.3 节验证策略未发现碰撞，碰撞对象与原因满足 AT-19 跨入口一致性，且位置、速度和加速度满足规定容差；不得把有限离散检查描述为数学上的连续安全证明。双击候选只预览；“用于规划/锁定分支”才会应用 `IkBranchPolicy` 设计修改。

### 8.5 动力学插件

**目标**：把时间轨迹转化为关节动力需求，并验证模型在刚体假设下的动态响应。

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| DYN-01 | P0 | 基于 RobWorkSim 刚体模型和递归牛顿—欧拉计算逆动力学 |

| DYN-03 | P0 | 输出每轴转角/位移、转速、加速度、类型化广义力（转动 N·m、移动 N）、机械功率、峰值和 RMS 包络；峰值必须报告持续时间窗和所在轨迹段，RMS 基于完整任务循环（含驻留） |
| DYN-04 | P0 | 输出与候选传动无关的关节侧结果；共享计算层提供唯一 `DriveTrainMappingEvaluator`，映射契约见下文冻结清单 |
| DYN-05 | P0 | 使用明确控制输入、初始状态、步长和容差的 RobWorkSim 正动力学场景进行响应一致性检查和异常检测 |
| DYN-06 | P0 | 物性或摩擦数据不足时标记可信等级，不把估算结果包装成精确结论 |

| DYN-08 | P1 | 提供各关节曲线联动、峰值定位和三维轨迹时刻回放 |

输入：`RobotDesign`、`TrajectoryPlan`、`LoadCase` 和摩擦假设。
输出：`DynamicResult`。
关键异常：物性缺失、惯量非法、状态不连续、积分不收敛或仿真发散。
P0 验收：标准二连杆算例和静态重力矩满足第 15.3 节动力学容差；真实机器人样例的峰值大小、所在轨迹段和关节排序与签署的独立对照数据一致。

**`DriveTrainMappingEvaluator` 映射契约（冻结）**——选型与优化共用，不得各自另算：

- 减速比/传动参数的正方向与单位（旋转传动无量纲比 `i`；直线传动为导程或等效折算，首版范围见 SEL-09）；
- 正向与反向功率流效率分别定义，不允许单一效率双向套用；
- 电机转子、减速器等效惯量和联轴器惯量向负载侧/电机侧的折算公式版本化；
- 摩擦归属唯一：关节摩擦已在 RNE 中计入（DYN-02），映射层只计入传动效率与减速器摩擦，不得重复计入关节摩擦；
- 峰值持续时间窗默认取器件目录声明的峰值时间能力，无目录数据时为 1 s；
- RMS 周期为完整任务循环（含驻留），与 DYN-03 一致；
- 制动、保持和再生工况显式声明；四象限工作方式与能量回馈策略作为声明假设进入证据，默认“无回馈、制动能量按耗散计”；
- 输出量类型化：旋转传动为 N·m/rad/s/W，直线传动为 N/m/s/W；
- 电机侧机械功、驱动器输入电能估算与可回馈能量分开输出，并标注所依赖的效率与回馈假设；纯关节侧 `DynamicResult` 不得直接宣称电能。

动力结论的证据等级采用第 6.6 节全局 `EvidenceLevel`：`Screening`（筛选级，允许参数估算，仅用于 Quick 排序）、`PreliminaryDesign`（初步设计级，关键连杆和负载物性已由用户确认，可进入首版 Verified 候选）、`ExternallyValidated`（外部验证级，已与独立工具或实测数据对照）。证据不足不得自动提升等级，报告必须说明运动律、摩擦和效率假设。

#### 8.7.1 阶段子集：OPT-B 与 OPT-D

为消除阶段 B 与完整优化需求的矛盾，优化需求按交付阶段拆为两个子集：

- **OPT-D（阶段 D 交付）**：OPT-01～10 全量验收——轨迹、动力、器件联合硬约束（OPT-03、OPT-05 完整语义）、并行/检查点规模化（OPT-06 完整语义）与鲁棒性协议（OPT-09）。

## 9. 联合优化方案

### 9.1 变量

首版允许的主要变量包括：

- 关节安装位置、DH 长度和偏置；
- 参数化连杆截面尺寸和材料，但只能从用户批准的离散截面/材料集合或经外部结构设计确认的上下界中选择；
- TCP/法兰偏置、基座位姿；
- 关节运动范围和设计安全裕量；
- 传动比、减速器型号和电机型号；
- 质量、质心和惯量只能在明确估算规则或授权覆盖范围内随结构变化。

所有变量都是对第 6.3 节权威对象字段的引用，不存在第二份候选数据存储。轴数、关节拓扑、并联支链和复杂齿轮传动拓扑不作为首版优化变量。

### 9.2 硬约束

- Must 任务和 Must 区域达到规定覆盖率；
- 任务与轨迹全程满足关节位置限制；
- 要求碰撞证据的工况按第 15.3 节碰撞验证协议未发现碰撞；
- 路径存在且满足连续性、速度、加速度和节拍上限；
- 关节、电机和减速器不超过连续及峰值能力；
- 物性、目录或碰撞证据不足，或证据等级不满足 `RequiredEvidenceProfile` 时不得判定为可行；
- 结构变量必须在工程边界内，且候选模型可成功编译。
- 优化截面和材料时必须满足用户给出的最小尺寸、质量或允许集合；软件不做强度/刚度校核，不得把轻量候选表述为结构已验证。

### 9.3 优化目标与指标分层

指标分四层，避免把所有可量化项都塞进 Pareto 目标导致非支配候选泛滥：

```text
Metric          始终计算和展示的比较指标
HardConstraint  决定可行性（第 9.2 节）
SoftConstraint  允许违反，产生独立惩罚或警告，不决定可行性
Objective       本次研究真正参与 Pareto 支配的指标
```

每个 `Objective` 必须声明：

```text
metricId / direction(Minimize|Maximize) / unit
aggregation（时间聚合：峰值或 RMS；任务聚合：最差、均值或总和）
requiredEvidenceLevel（该目标可信所需的最低证据等级）
comparisonTolerance（小于该容差的差异视为无差别，不构成支配）
```

默认八项比较指标：总体尺寸包络、结构质量、节拍、关节侧正机械功（默认“能耗”口径，见下）、器件质量、器件成本、最小关节裕量和最小驱动裕量。默认激活目标为节拍、结构质量、器件成本三项；用户可显式激活更多目标，激活数达到或超过 5 时界面提示 Pareto 区分度将显著下降。鲁棒性作为最终候选的 P0 复核指标，不作为默认优化目标。

能耗口径冻结：默认优化与比较使用关节侧正机械功（单位 J，由 `DynamicResult` 积分得到）；电机侧机械功、驱动器输入电能与可回馈能量仅当存在传动映射证据（目录效率数据 + 声明的回馈策略）时由 `DriveTrainMappingEvaluator` 输出，并在结果与报告中标注假设，不得与关节侧机械能混称。

SoftConstraint 的惩罚只作为独立警告/次级排序信息，不改变硬约束可行性，也不参与 Pareto 支配；只有用户显式将其提升为 Objective 时，才按 Objective 的方向、聚合和容差参与比较。

正机械功定义为 `W+ = ∫ max(P_joint(t), 0) dt`；离散轨迹使用记录时间戳上的梯形积分，并在结果中保留采样与积分规则。

### 9.4 分层求解流程

1. 编译设计空间并剔除无效变量组合。
2. 外层生成结构尺寸和传动比候选。
3. 使用 Quick 运动学与简化动力估算进行大规模筛选。Quick 不能作为正式通过证据；只有可证明保守的规则可以直接执行硬淘汰，其他淘汰候选必须按固定种子抽检并报告误淘汰率。
4. 对保留候选执行 Verified 运动学、轨迹和动力学计算。
5. 内层从目录匹配电机与减速器；无组合可行时把原因反馈给外层。
6. 对可行候选执行局部改进与鲁棒性/敏感度复核（按第 15.3 节协议）。
7. 形成“当前变量域、算法和计算预算内发现的 Pareto 集”，并用基线差异、硬约束证据和敏感参数帮助工程师选择；不得暗示已证明全局 Pareto 前沿。

## 12. 错误与诊断

诊断类别分为三类，并与执行状态、工程判定正交：

| 类型 | 含义 | 示例 | 界面处理 |
| --- | --- | --- | --- |
| 输入错误 | 数据不完整或不合法，无法可靠计算 | 坐标系/对象不存在、名称作用域歧义、惯量非法、目录字段缺失、策略冲突 | 定位编辑位置并给修复建议 |
| 工程不可行 | 计算完成，但设计违反约束 | 不可达、碰撞、节拍超限、无可用减速器 | 展示证据并支持比较或修改 |
| 系统错误 | 软件、算法或工作进程未完成任务 | 内部文件损坏、求解器异常、工作进程退出 | 保留项目，提供重试和开发诊断 |

取消和中断是执行状态，不属于错误类别。数据不足是完成计算后的工程判定；导入文件本身损坏属于输入错误，软件内部生成文件损坏属于系统错误。

稳定诊断项至少包含 `code、category、severity、retryable、subjectObjectId、localName、runtimeScopedName、actual、expected、action、causeCode`，用于测试、报告和技术支持；没有运行时名称的对象允许该字段为空，但不得以名称替代 `subjectObjectId`。普通用户主要看到中文说明。错误只在真实边界统一映射一次并保留原始原因，避免每层重复包装。

真实边界包括持久化读写、IPC、缓存/检查点反序列化、外部资源、插件入口、第三方求解器返回值和异步完成事件。领域内部通过受控构造、类型不变量和断言保持一致，不重复执行相同校验。

缓存键至少包含评估输入切片内容身份（第 7.1 节）、`EngineeringPolicySet` 内容身份、规范模型的对象 ID/物理内容身份、评估器 ID/版本、随机种子及会影响结果的计算预算。`RuntimeNameMap` 完整进入快照和执行绑定校验，但单纯运行时名称拼写变化不得污染基于稳定对象 ID 的数值缓存键。失败、取消和部分结果不得作为正式缓存命中。检查点必须记录格式版本、运行/尝试身份、算法状态、已完成批次和结果模式；恢复前由评估器显式判断策略、对象绑定和评估器兼容性，不兼容时拒绝恢复并保留原检查点供诊断。

## 13. 现有代码重构与删除策略

### 13.1 处理分类

| 分类 | 判断条件 | 处理方式 |
| --- | --- | --- |
| 保留 | 行为正确、接口清晰、已有独立测试 | 直接纳入新内核并补缺失契约测试 |
| 迁移 | 算法有价值，但依赖旧类型或界面 | 先以测试固定行为，再迁入新领域接口 |
| 重写 | 业务逻辑与 Widget/文件/全局状态紧耦合 | 按新数据流重写，不复制旧结构 |
| 删除 | 重复、未使用、仅兼容旧格式、装饰性配置或已被新实现替代 | 删除旧实现及只验证旧接口/旧界面的测试；仍需保留的行为先迁为新契约测试或黄金数据 |

### 13.2 建议保留和迁移的资产

- RobWorkStudio 项目清单、资源 Provider、事务保存和项目路径处理；
- RobotModelSpec、URDF 导入、WorkCell 转换和模型生成中已验证的纯计算部分；其中任意轴到内部局部 Z 的对齐及几何/惯性补偿算法可迁移，但现有隐式轴数据结构不能直接作为新领域契约；
- 现有 WorkCell 导入中识别 `RobotName.LocalName` 并恢复局部名的行为及其测试样本；行为迁入 `IRuntimeNameResolver`，原有逐字段 `stripDeviceScope` 调用不保留为多处实现；
- CollisionSetup/ProximitySetup 的解析、往返和相邻 Link 排除测试资产；解析结果迁入统一 `CollisionPolicy`，两种 XML 只保留为适配输出；
- 已验证的原生 DH 权威读取、Schilling 标准 DH 生成和有损投影识别逻辑；迁移后由新权威源与转换判定接口统一调用；
- 需求语义、姿态规则、导入和执行契约；
- 运动学、碰撞、覆盖率和候选排序的单一权威实现；
- 候选编译、参数适配、缓存、检查点、灵敏度和现有固定种子测试；
- RobWorkSim 的 DynamicWorkCell、RigidDevice、RecursiveNewtonEuler 和可选物理引擎。

### 13.3 必须消除的结构

- Widget 内的文件读写、领域校验、长任务算法和跨项目状态判断；
- 同一任务或需求在 UI 表格与执行快照中的双份权威数据；
- `JointTransformSpec` 仅以 RPY 承载任意轴、JSON 不保存独立 Axis、界面不能区分原始安装姿态与轴对齐旋转的隐式语义；
- 关节、限位、Drawable、CollisionModel、SceneFrame、Proximity 规则和动力学 Link 各自拼接或剥离机械臂名称前缀，以及用大小写不一致的裸字符串在插件间查找对象；
- `collisionSetup.enabled`、`proximitySetup.enabled`、分析插件碰撞开关、路径验证参数和显示碰撞几何开关互相推断或分别使用默认值；
- URDF 缺失或零轴静默使用局部 Z、不支持关节静默转为 FixedFrame、自动选择“最佳串联链”并跳过其他可动分支的行为；
- DH 与通用位姿持续双向回写、用近似投影覆盖原生 DH，或把 `Approximate` 结果当作可发布 DH 的路径；
- 优化模块内部重复实现的运动学、轨迹、动力学或选型逻辑；
- 旧项目格式读取、Legacy 迁移预览和新旧 Schema 双写；
- `Old/New/V2/Legacy` 长期并存的类型和构建目标；
- 无实际消费者的字段、未接入运行链路的“预留模块”和重复文案。

### 13.4 迁移门禁

每个模块按“行为清单 → 回归测试 → 新内核 → 新界面 → 切换 → 删除旧链路”执行。行为追踪未闭合时不得删除旧链路。建模迁移门禁还必须证明：Axis 可独立保存和编辑；原生 DH 不被反投影覆盖；URDF 任意轴经适配后 FK、世界轴线、几何和惯性等价；非法轴、未知关节和多可动分支不会形成可发布模型；所有设备内名称由同一 `RuntimeNameMap` 解析且重命名后无旧/双前缀。横切逻辑迁移门禁必须证明各插件共享同一 `EngineeringPolicySet` 和评估器，删除本地碰撞开关、默认值、名称处理与重复判定。阶段 B 结束时，新四插件闭环通过后，旧链路必须退出构建和发布包。代码删除以行为和测试覆盖为保护，不以代码行数为唯一目标；每个阶段必须提交行为映射、删除清单、依赖减少、安装包审计和恢复演练结果。

## 14. 分阶段实施路线

### 发布切片

为控制“全部标 P0”带来的范围风险，发布明确分为两个切片：

1. **R1 工程闭环版**（阶段 A+B+C 产出）：建模、需求、运动学、轨迹、逆动力学、基础选型和报告。R1 自身即可支撑试点预演与真实数据校核，是必须先稳住的闭环。
2. **R2 优化规模化版**（+阶段 D 产出）：并行评估、检查点恢复、分层联合优化、鲁棒性和大型性能目标（NFR-PERF-04～06）。

R1 是可独立安装、试点预演和回滚的正式发布切片，允许输出“初步设计级”评审报告，但必须显式列出模型、物性、碰撞和目录证据等级；R2 在不破坏 R1 `.rwdesign` Schema 的前提下增加规模化与联合优化能力。R1 不得依赖 R2 才能完成建模、需求、运动学、轨迹、动力学和基础选型闭环。

P0 优先级由此获得可解释的边界：R1 范围内的 P0 是工程闭环所必需，R2 范围内的 P0 是优化规模化发布所必需；任何一个切片内部不再存在“可以整体延期”的 P0。

12 个月是基线计划；当阶段 A 的契约评审在第 6 周通过后，阶段 B 可与 A 的剩余基础设施工作并行，从而争取 9 个月进入试点。契约评审必须明确数据所有权、端口、任务状态、诊断、快照与输入切片、缓存、检查点和验收容差，未通过时不得并行铺开七个插件。

核心团队按 6 人以上配置，至少覆盖：产品/机械臂系统负责人 1 名、C++/Qt 平台 2 名、运动学/规划算法 1 名、动力学/驱动 1 名、测试与体验 1 名。业务方另指定模型数据负责人和试点工艺/目录数据负责人。建议第 5～6 月用 R1 版本开展试点预演并确认首版真实数据；真实试点数据最迟在第 7 月、阶段 D 启动前完成首版签署；未就绪时可以继续标准数据集开发，但不得宣称进入真实试点验收。

### 阶段 A：基础重建（第 1～2 月）

交付：

- 现有行为、算法和数据资产清单；
- 统一领域对象、稳定身份/RobWork 作用域名称、单位/坐标系/来源约定，以及 `StandardDH | ExplicitJoint` 权威类型、SE(3) 规范计算模型、显式 Axis 和转换判定契约；
- `EngineeringPolicySet`、共享 `CollisionEvaluator` 和工程策略统一入口原型；
- 新项目格式（多文件事务保存）、自动输入快照、依赖切片与精确失效；
- 后台任务、取消、工作进程、诊断和恢复框架；
- 中文术语表和统一阶段导航原型。

阶段 A 固定门禁：

- A-GATE-01：连续执行 Jog、IK 预览和轨迹播放，项目修订号与结果当前性均不变化；
- A-GATE-02：应用 TCP 设计修改只产生一个新修订，运动学及下游结果变为 Superseded，原历史结果保持完整；修改电机成本不使运动学和轨迹结果失效（切片失效验证）；
- A-GATE-03：任务运行期间切换方案分支，旧任务结果只能追加为原分支历史，不得成为当前结果；

**Jacobian 统一尺度（冻结）**：Jacobian 线速度块单位为 m、角速度块单位为 rad，量纲不同不得直接混合。统一尺度规则为 `J_norm = [J_v / L* ; J_ω]`，特征长度 `L*` 默认取 Zero 位姿下基座原点到 TCP 的距离，且必须为有限正值；若退化为零或非有限，必须使用项目明确配置的正值回退并记录诊断，无法确定时输出 `DataInsufficient`，不得静默使用 0。项目可在分析配置中覆盖并记录；可操作度、条件数和奇异性指标一律基于 `J_norm` 计算。4/5 轴任务使用受约束位姿分量构成的任务子空间 Jacobian，约束分量由任务定义（REQ-01）声明。

姿态误差使用相对旋转的测地角并忽略四元数正负号；有向轴误差使用 `atan2(norm(a × b), a · b)`，不得用在接近 1 时精度不稳定的朴素 `acos(a · b)`。所有随机转换样本使用项目固定种子并在证据中记录；没有有限上下限的 continuous 关节只使用用户确认的工程工作范围。

**容差分层**：上表为算法级容差，适用于同一实现内的确定性对照与往返。与独立参考实现或外部工具的端到端对照使用第二层容差：位置 `1e-6 m`、姿态 `1e-6 rad`、力矩/力相对误差 `1e-4` 且绝对下限 `1e-6 N·m`（或 `N`）；真实机器人试点对照逐指标单独签署。两层容差不得混用，端到端测试不得套用算法级容差。

**碰撞验证协议（冻结）**：以下参数属于第 6.7.2 节统一 `CollisionPolicy.pathValidationProfile`，运动学、轨迹和优化不得在本地覆盖启用状态、对象参与、配对规则或安全距离。首版采用基于自适应细分的离散碰撞检测（RobWork 常用 `QEdgeConstraint` 即属此类，按分辨率检查边而非数学意义上的连续碰撞证明），不宣称绝对安全。协议参数：

- 后端：项目锁定的 RobWork 碰撞策略（PQP 或项目选定后端），策略与版本进入快照；
- 初始离散：每条路径边按路径参数 10 等分采样；
- 细分触发：相邻采样点任一关节位移超过步长上限（转动 `0.05 rad`、移动 `0.01 m`），或边中点与最近障碍距离低于安全距离加细分余量（默认 `0.005 m`）时二分细分。若最近障碍距离查询不可用，不得推断为“距离足够”，仅按关节步长继续细分；
- 终止：全部相邻采样满足步长与距离条件，或达到最大细分深度 8；深度耗尽仍不满足分辨率时判“验证不足”（DataInsufficient），不得判为通过；
- 安全距离默认 `0`（接触即碰撞），可按工况配置正值；允许接触对随快照保存；
- 结论措辞固定为“在本策略与分辨率下未发现碰撞”；未来若引入真正的连续碰撞检测后端，必须作为新的验证策略版本重新验证，不得与本协议混用。

**鲁棒性与敏感度协议（冻结）**：分三种模式，结论措辞不得混用：

1. **有界公差验证（P0，正式）**：仅当项目提供经工程负责人签署的制造/装配公差表时执行。每个候选用固定种子 64 点拉丁超立方在公差盒内采样；全部有效样本必须满足全部硬约束方可判“公差域内鲁棒通过”，任一样本违反硬约束判“鲁棒性不足”；任一样本模型编译失败必须单独报告并计入失败，不得计入分母替换。
2. **概率鲁棒性（P1）**：需要经签署的分布模型与置信口径，输出通过率的置信区间；未签署分布模型时禁止输出任何概率性结论。
3. **敏感度抽查（P0，默认）**：无签署公差时使用默认扰动（结构尺寸 `±0.5%`、质量/惯量 `±5%`、摩擦 `±20%`、传动效率向不利方向降低 2 个百分点）执行同款采样，输出各指标敏感度排序与最差裕量，标注“敏感度参考”，不得出现“鲁棒通过/鲁棒性不足”字样，也不得给出通过率式结论。

覆盖对象：最终比较的至多 10 个 Verified 候选（不足 10 个时全部执行），必须覆盖每个激活目标的 Pareto 极值点、膝点、用户选中项和多样性代表（目标空间最大—最小距离选取），不得只取排序前 10。

物理一致性：扰动不得独立缩放质量与惯量。几何相关扰动必须按解析估算规则重算质量/质心/惯量，或按一致性规则（惯量随质量与特征尺寸同步缩放）生成；每个样本的惯量张量执行正定性与三角不等式校验，非法样本单独报告，不得计入分母。

Quick 误淘汰审计使用固定种子，从每类淘汰原因和目标值区间分层抽取淘汰候选的 5%，且不少于 200 个（淘汰数不足时全部抽检），执行 Verified 复核。“Quick 淘汰但 Verified 满足硬约束，且相对已验证集合为非支配候选”计为误淘汰。误淘汰率必须不超过 1%，95% 置信上界不得超过 3%；超限时必须扩大保留池、禁用对应 Quick 淘汰规则并重新运行，禁止生成正式候选报告。

真实机器人或独立商业工具对照必须在试点前签署逐指标容差。若只有非同步或低精度数据，只能作为趋势/相关性证据，不替代上述解析与数值收敛门禁。

Windows Qt Widgets 和 GUI 测试必须在 Visual Studio x64 开发环境下运行，设置 `QT_QPA_PLATFORM=windows`，且一次只启动一个测试可执行文件。模型测试如仅使用 `QCoreApplication`，不需要 GUI 平台插件。

### 15.4 发布规则与缺陷等级

需求优先级与缺陷等级分离命名：**P0/P1 只表示需求优先级**；缺陷严重级别采用 **Blocker / Critical / Major / Minor**。

- Blocker：结果正确性缺陷、数据串项目、错误判定为通过、项目损坏——均为发布阻断项；
- Critical：主流程不可用或有误导性结论，必须有负责人、影响说明和计划日期；
- Major/Minor：按影响排期修复。

发布要求：

- P0 需求未通过时不得发布对应阶段；
- P1 可在评审确认风险、负责人和计划后延期；
- 所有已知错误必须能归类为输入错误、工程不可行或系统错误；
- 不允许以关闭测试、降低阈值或隐藏诊断代替修复；
- 发布时开放 Blocker 为 0，未关闭 Critical 均有负责人和计划日期。

## 18. 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 现有算法与 UI 隐式耦合比预期深 | 迁移延期或行为回归 | 阶段 A 建行为清单；先加模型测试再迁移 |
| 质量/惯量估算不准确 | 动力和选型结论偏差 | 显示来源与可信等级；支持权威值覆盖和多工况 |
| 大规模联合优化计算量过高 | 无法在工作站内完成 | Quick/Verified 分层、缓存、并行、预算和提前淘汰 |
| 器件目录字段不完整或不一致 | 选型不可复核 | 统一模板、导入报告、版本锁定和数据责任人 |
| RobWorkSim 正动力学模型与实际控制系统有差异 | 用户过度相信仿真 | 明确刚体假设；用解析和真实数据对照；报告限制 |
| DH、URDF 与 RobWork 内部坐标约定混淆 | 轴向、零位、几何或惯性被错误旋转，且可能在简单模型中不易发现 | 显式保存 Origin/Axis 和权威来源；轴对齐只在适配层；使用三入口黄金模型及世界轴线/FK/惯性等价测试 |
| RobWork 设备前缀遗漏、重复或重命名后残留 | 关节限制、碰撞对、动力学 Link 或结果证据绑定到错误对象 | 领域引用使用稳定 objectId；统一 RuntimeNameMap；导入/编译/重命名跨文件契约测试与静态扫描 |
| 各插件维护不同碰撞开关、排除规则或默认值 | 同一设计在运动学、轨迹和优化中得到相互矛盾的安全结论 | EngineeringPolicySet 与共享 CollisionEvaluator 单一权威；策略进入快照；AT-19 跨入口一致性门禁 |

| 范围全部标 P0 导致团队过载 | 关键闭环质量被稀释 | R1/R2 发布切片；阶段退出绑定切片验收而非功能数量 |
| 为“通用”而过早抽象 | 代码重新膨胀 | 首版只支持串联臂；抽象必须有两个真实消费者或明确替换点 |
| 为防错误层层兜底 | 重复逻辑和错误语义不一致 | 只在边界校验；内部依赖类型与不变量；错误统一转换一次 |
| 旧代码不及时删除 | 新旧链路继续分叉 | 阶段退出条件绑定删除清单和发布包审计 |

## 19. 已确认决策与默认值

1. 产品形态为 Windows x64 企业内网桌面版，不含云端协同。
2. 首版面向 4～7 轴工业串联机械臂，架构预留外部轴和其他机构扩展。
3. 软件服务方案与初步设计，新机型与改型同等重要。
4. 首版以通用搬运/上下料作为端到端验收工艺。
5. 建模采用 `StandardDH` 或 `ExplicitJoint` 单一权威参数化，URDF 导入形成 `ExplicitJoint`；CAD 只提供可视/碰撞网格。
6. 质量、质心和惯量以参数估算为默认，并允许导入或人工权威值覆盖。
7. 轨迹首版覆盖路径规划、平滑和速度/加速度时间参数化。
8. 动力学首版采用刚体逆/正动力学，不含柔性、热和寿命。
9. 电机/减速器目录采用内置模板与企业导入，不承诺维护厂商全集。
10. 优化采用硬约束先行、Pareto 决策和分层联合求解。
11. 用户不执行显式发布/冻结；系统在计算时自动创建输入快照。
12. Jog、预览和播放属于会话态，不影响设计基线。
13. 新项目格式允许断代，不建设旧格式兼容或迁移。
14. 现有可信内核复用，领域外壳和主要界面重建；迁移后及时删除旧代码。
15. 代码保持简洁，不引入过度防御、无价值抽象或机械样板。
16. 规划周期为 9～12 个月，核心团队按 6 人以上并行配置。
17. 可动通用关节的正式定义为 `Joint Type + Origin Pose + Axis`，Axis 是独立领域字段；固定关节只需 `fixed + Origin Pose`。现有 RPY+Pos+隐式局部 Z 仅作为待迁移实现。
18. DH 和通用关节只允许一个权威源；DH→通用对运动学语义无损，通用→DH 必须通过可表达性与 FK/轴线/附属 Frame 等价验证，不进行破坏性双向同步，也不承诺反算恢复逐项相同的 DH 数值。
19. URDF 可动关节轴不要求为 Z；缺失 axis 按标准采用局部 +X 并生成待确认草稿，零轴阻止提交新修订。内部局部 Z 规范化属于 RobWork 适配细节，不改变领域层原始 Origin/Axis。
20. URDF 首版只发布受支持的 4～7 轴串联模型；不支持关节和多可动分支不得静默固定化或裁剪。
21. 运行时运动学真值唯一：从权威参数化确定性编译的 SE(3) 关节链（第 7.3.1 节）；DH 只是编辑、导入和导出视图。
22. 优化候选不属于项目修订；候选、抽样与扰动样本归 `OptimizationRunResult` 所有，“设为当前方案”才创建方案分支与正式修订。
23. 结果当前性、缓存与失效基于评估器输入切片（`EvaluatorDependencyManifest`），不基于整个项目修订号；`SourceRevisionRef` 只承担溯源。
24. 关节广义力类型化：转动 N·m、移动 N；首版传动目录与选型只支持旋转传动，直线传动模板为 P1；移动关节进入目标链时选型给出明确“范围外”诊断。
25. 优化指标分为 Metric/HardConstraint/SoftConstraint/Objective 四层；默认激活目标为节拍、结构质量、器件成本；默认“能耗”口径为关节侧正机械功，电能指标必须带传动映射证据与假设。
26. 评估模式（Quick/Verified）与证据等级（Screening/PreliminaryDesign/ExternallyValidated）全局统一，正式可行判定按第 6.6 节冻结执行。
27. 碰撞验证为首版自适应细分离散协议（第 15.3 节），结论只表述为“在本策略与分辨率下未发现碰撞”；鲁棒性分有界公差验证、概率鲁棒性和敏感度抽查三种模式，未签署公差/分布时只输出敏感度参考。
28. 缺陷严重级别采用 Blocker/Critical/Major/Minor；P0/P1 只用于需求优先级。
29. 发布分 R1 工程闭环版与 R2 优化规模化版两个切片；外部依赖按 NFR-DEP-05 锁定版本基线。
30. 领域对象身份不使用名称：各插件、结果和持久化引用使用稳定 objectId；RobWork Device 内部全名统一由 `IRuntimeNameResolver` 按 `RobotName.LocalName` 生成和反解，任何插件不得自行补前缀或去前缀。
31. 碰撞及其他跨插件工程逻辑采用单一 `EngineeringPolicySet` 和共享评估器；CollisionSetup、ProximitySetup 与路径验证配置只是统一 `CollisionPolicy` 的适配输出，计算开关与纯显示开关严格分离。
