# 试点与交付模块详细方案（pilot-delivery）

- 方案版本：v0.3；需求基线：v0.8；架构检查点：`IRD-D2-20260829`
- 负责 WP：WP-25；阶段/发布：阶段 E / R1+R2（阶段 C 末完成试点数据签署门禁）；任务卡：`agent-tasks/WP-25-T01～T05`
- 契约：`architecture/testing-contract.md`（§4 人工证据）、`architecture/persistence-schema.md`；需求：§3.3、§14 阶段 C/E、§15.3（真实对照逐指标签署）、§15.4、§17
- 前置：WP-22～24；本模块为非代码模块，交付物全部是文档工件与人工流程

## 1. 模块职责

试点实施协议：试点数据签署流程、真实机械臂对照实验设计、用户研究协议、缺陷登记与发布检查表、交付材料清单。验证方式＝签署记录、检查表与真实环境演练（testing-contract §4"人工试点使用签署记录和报告工件，不以空 CTest 目标替代"）；系统冒烟（`run-tests.ps1 -Configuration Release -Regex '^sdurws_ird_system_test$'`）仅作辅助证据。非目标：修改业务实现、替代工程签署责任（需求 §3.4：软件不替代最终设计签署）、宣称真实机型选型在数据缺失时通过（§17）。

## 3. 试点数据签署流程（阶段 C 末门禁）

签署清单（`data-signoff.md`，逐项对应需求 §17；签署人＝业务数据负责人，产品负责人会签；最迟阶段 D 启动前完成首版签署）：

| 签署项 | 内容 | 缺失后果 |
| --- | --- | --- |
| 机械臂模型 | 台架型号、URDF/参数来源、轴数与关节类型、厂商允许能力 | 不得进入真实试点验收 |
| 工位与环境 | 工位、顺序、接近/撤离、节拍；基座/夹具/工件/地面/主要障碍 | 同上 |
| 工具/TCP 与负载 | 工具定义、TCP、负载质量/质心/惯量（至少两档） | 同上 |
| 公差表 | 制造/装配公差（有界公差验证输入） | 鲁棒性结论降级为敏感度参考 |
| 器件目录 | 在用/候选电机减速器目录及成本，版本锁定 | 选型结论不可复核 |
| 逐指标对照容差 | 每个对照指标单独签署容差 | 对照只能作趋势/相关性证据 |
| Must/Should 判据与安全系数 | 项目负责人认可 | 工程判定无权威依据 |

未签署数据只能用于标准样例验证或敏感度参考（需求 §14 阶段 C 退出条件）。

## 4. 真实机械臂对照实验设计

- 范围：至少 1 台真实机械臂＋1 类搬运/上下料任务（§14 阶段 E 退出条件）；环境、工具、负载与目录版本以 §3 签署件为准并全程锁定。
- 测量项（对照口径来源＝§17"控制器计算、厂商曲线、商业仿真或部分实测数据"）：TCP 位姿与重复性、多循环节拍统计、关节速度/加速度包络、关节力矩/功率（控制器可导出时）；每项记录测量方法、样本数与测量不确定性。
- 对照规则：软件结果 vs 对照源逐指标比较，仅使用该指标的签署容差（§15.3"真实机器人试点对照逐指标单独签署"，不得套用两层默认容差）；只有非同步或低精度数据时记为趋势/相关性证据，不替代解析与数值收敛门禁。
- 产出 `comparison-report.md`：每指标软件值、对照值、差值、签署容差、结论（满足/超差/趋势），差异分析与限制说明；若无可行或改进候选，必须给出可复核的约束与搜索证据，不得强行给出"最优方案"（§3.3 正确性门槛）。

## 5. 用户研究协议（冻结）

- 受试：≥5 名目标用户（覆盖 §3.2 核心操作者与专业操作者），匿名编号 U01～U05，只记录角色与经验，不记录身份信息。
- 任务脚本：固定脚本复用 WP-22-T05 的新机型/改型/错误恢复三脚本，在签署试点数据上执行；步骤、完成标准与"允许介入"定义事先书面冻结（`user-study-protocol.md`）。
- 记录表单（每受试一份，`templates/`）：逐任务完成率、介入次数（按原因分类：导航/术语/数据入口/计算等待/缺陷）、耗时、问题分类（映射 UX-01～08 与缺陷等级 Blocker/Critical/Major/Minor）。
- 成功口径（§3.3）：80% 受试不依赖软件开发人员完成标准搬运主流程；跨工具手工拼接次数＝0；相同快照复算离散结论一致率 100%。
- 伦理与数据保存：受试知情同意（自愿参与、可中止、数据用途说明）；录像/录屏仅用于分析，企业内网存储且访问限试点团队；原始数据保存至发布后 12 个月，之后仅保留汇总统计；发布后清理临时数据，签署记录与缺陷证据永久归档（WP-25 计划）。

## 6. 缺陷登记与发布检查表

- `defect-register.md`：每条缺陷记录等级（§15.4：Blocker/Critical/Major/Minor）、复现步骤、影响、负责人、状态与计划日期。Blocker＝结果正确性缺陷、数据串项目、错误判定为通过、项目损坏——试点发布前必须为 0；未关闭 Critical 必须有负责人、影响说明与计划日期。"不得以关闭测试、降低阈值或隐藏诊断代替修复"为登记表复核项。
- `release-checklist.md`：R1/R2 各自勾选——阶段退出条件、§3.3 业务指标（含至少一个候选进入下一轮详细设计且相对基线改善≥5%、保护指标不越阈值）、关键结论满足签署容差、缺陷门禁、安装演练（对接 WP-24 干净机协议）、样例/手册/培训齐备；由产品负责人、业务数据负责人与独立试点观察员三方签署（WP-25 计划独立评审）。

## 7. 交付材料清单

样例项目（标准搬运案例＋改型案例，可由 WP-02 黄金数据导出）、报告模板（对接 WP-12 `ReviewReport` 输出样例）、安装说明（对接 WP-24）、用户手册（主流程＋术语对接 WP-09 术语表）、培训材料（新机型/改型流程各一单元）。全部材料随发布包归档；修订走文档评审，不走代码门禁。

## 8. 验证与证据（非 CTest）

验证＝人工复核与签署：每份 `pilot/` 工件均有负责人签署与日期；对照实验附原始测量导出件及其哈希；用户研究附签署表单与汇总统计。辅助冒烟（可选，不替代上述证据）：

```powershell
pwsh -NoProfile -File .\RobWork\scripts\industrial-robot\run-tests.ps1 -Configuration Release -Regex '^sdurws_ird_system_test$'
```

退出条件（WP-25 计划）：达到 §3.3 业务指标、关键运动学/动力学结论满足已签署对照容差、开放 Blocker＝0、R1/R2 发布检查表完整。
