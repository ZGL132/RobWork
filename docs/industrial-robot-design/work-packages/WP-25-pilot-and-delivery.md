# WP-25 试点与交付实施计划

> 阶段/发布：阶段 E / R1+R2（阶段 C 末完成试点数据签署门禁）；人周 6～10（总纲 §5.4）。
> 负责范围：试点实施协议——试点数据签署流程、真实机械臂对照实验设计、用户研究协议、缺陷登记与发布检查表、交付材料清单。
> 责任分离：签署人＝业务数据负责人（产品负责人会签）、试点观察员独立于执行团队；本模块为非代码模块，交付物全部是文档工件与人工流程（module-design/pilot-delivery.md §1）。

**需求与契约：** 第 3.3、14、17 章及 §15.3（真实对照逐指标签署）、§15.4（缺陷等级）；引用 `architecture/testing-contract.md`（§4 人工证据）、`architecture/persistence-schema.md`、`architecture/evaluation-semantics.md`（§5 展示义务）；模块方案 `module-design/pilot-delivery.md`（v0.3）。

**拥有目录：** `docs/industrial-robot-design/pilot/`（七份工件＋task-scripts/＋templates/）、样例项目、报告模板、用户手册和培训材料。完整试点依赖 WP-22～WP-24；阶段 C 末数据签署是进入真实试点的前置门禁。

**输入/输出：** 输入＝已发布 R1/R2、签署的真实试点数据、WP-22-T05 用户任务脚本、WP-23 系统质量证据、WP-24 安装说明；输出＝签署记录、对照报告、用户研究报告、缺陷登记、发布检查表与交付材料。

## 1. 目标与非目标

**目标：** 用至少 1 台真实机械臂与 1 类搬运/上下料任务验证 R1/R2 工程价值，组织至少 5 名目标用户完成固定任务脚本，闭环缺陷并交付五项交付材料，形成三方签署的 R1/R2 发布检查表。
- 完成定义：§4 七项数据全部签署（阶段 C 末门禁）；对照报告逐指标按签署容差给出结论；用户研究报告覆盖 U01～U05 且达到 §3.3 成功口径；缺陷登记开放 Blocker＝0；发布检查表三方签署完整。

**非目标：** 不修改业务实现；不替代工程签署责任（需求 §3.4：软件不替代最终设计签署）；不宣称真实机型选型在数据缺失时通过（§17：数据缺失时只能用标准样例验证软件行为）；验证不以空 CTest 目标或测试命令替代人工签署与报告工件（testing-contract §4）。

## 2. 需求、契约与前置

- 需求：§3.3（业务目标与产品成功指标）、§14（阶段 C/E 退出条件、试点数据最迟阶段 D 启动前首版签署）、§15.3（真实对照逐指标单独签署、趋势/相关性证据边界）、§15.4（缺陷等级与发布规则）、§17（试点前置数据）。
- 契约：`architecture/testing-contract.md`（§4 人工证据：签署记录和报告工件）、`architecture/persistence-schema.md`、`architecture/evaluation-semantics.md`（§5 展示义务：`DataInsufficient`/`Partial`/`NotEvaluated`/`Superseded` 的用户可见口径，用户研究与缺陷定级引用）。
- 模块方案：`module-design/pilot-delivery.md`（v0.3；本计划对齐其 §2～§9）。
- 前置：WP-22（任务脚本来源，T03 复用 WP-22-T05 三脚本）、WP-23（系统质量证据）、WP-24（安装说明与干净机演练对接）；完整真实试点依赖 R1/R2 可安装版本。

## 4. 试点数据签署清单（阶段 C 末门禁，T01）

签署清单见 `data-signoff.md`，逐项对应需求 §17；签署人＝业务数据负责人，产品负责人会签；最迟阶段 D 启动前完成首版签署（需求 §14）：

| 签署项 | 内容 | 缺失后果 |
| --- | --- | --- |
| 机械臂模型 | 台架型号、URDF/参数来源、轴数与关节类型、厂商允许能力 | 不得进入真实试点验收 |
| 工位与环境 | 工位、顺序、接近/撤离、节拍；基座/夹具/工件/地面/主要障碍 | 同上 |
| 工具/TCP 与负载 | 工具定义、TCP、负载质量/质心/惯量（至少两档） | 同上 |
| 公差表 | 制造/装配公差（有界公差验证输入） | 鲁棒性结论降级为敏感度参考 |
| 器件目录 | 在用/候选电机减速器目录及成本，版本锁定 | 选型结论不可复核 |
| 逐指标对照容差 | 每个对照指标单独签署容差 | 对照只能作趋势/相关性证据 |
| Must/Should 判据与安全系数 | 项目负责人认可 | 工程判定无权威依据 |

未签署数据只能用于标准样例验证或敏感度参考（需求 §14 阶段 C 退出条件），不得进入真实试点验收。

## 5. 真实机械臂对照实验设计（T02）

- 范围：至少 1 台真实机械臂＋1 类搬运/上下料任务（§14 阶段 E 退出条件）；环境、工具、负载与目录版本以 §4 签署件为准并全程锁定。
- 测量项（对照口径来源＝§17"控制器计算、厂商曲线、商业仿真或部分实测数据"）：TCP 位姿与重复性、多循环节拍统计、关节速度/加速度包络、关节力矩/功率（控制器可导出时）；每项记录测量方法、样本数与测量不确定性。
- 对照规则：软件结果 vs 对照源逐指标比较，仅使用该指标的签署容差（§15.3"真实机器人试点对照逐指标单独签署"，不得套用两层默认容差）；只有非同步或低精度数据时记为趋势/相关性证据，不替代解析与数值收敛门禁。
- 产出 `comparison-report.md`：每指标软件值、对照值、差值、签署容差、结论（满足/超差/趋势），差异分析与限制说明；若无可行或改进候选，必须给出可复核的约束与搜索证据，不得强行给出"最优方案"（§3.3 正确性门槛）。

## 6. 用户研究协议（冻结，T03）

- 受试：≥5 名目标用户（覆盖 §3.2 核心操作者与专业操作者），匿名编号 U01～U05，只记录角色与经验，不记录身份信息。
- 任务脚本：固定脚本复用 WP-22-T05 的新机型/改型/错误恢复三脚本，在签署试点数据上执行；步骤、完成标准与"允许介入"定义事先书面冻结（`user-study-protocol.md`）。
- 记录表单（每受试一份，`templates/`）：逐任务完成率、介入次数（按原因分类：导航/术语/数据入口/计算等待/缺陷五类）、耗时、问题分类（映射 UX-01～08 与缺陷等级 Blocker/Critical/Major/Minor）；状态类误导（如 `DataInsufficient` 被展示为"不可行"，违反 evaluation-semantics §5）计为问题并定级。
- 成功口径（§3.3）：80% 受试不依赖软件开发人员完成标准搬运主流程；跨工具手工拼接次数＝0；相同快照复算离散结论一致率 100%。
- 伦理与数据保存：受试知情同意（自愿参与、可中止、数据用途说明）；录像/录屏仅用于分析，企业内网存储且访问限试点团队；原始数据保存至发布后 12 个月，之后仅保留汇总统计。

## 7. 缺陷登记与发布检查表（T04/T05）

- `defect-register.md`：每条缺陷记录等级（§15.4：Blocker/Critical/Major/Minor）、复现步骤、影响、负责人、状态与计划日期。Blocker＝结果正确性缺陷、数据串项目、错误判定为通过、项目损坏——试点发布前必须为 0；未关闭 Critical 必须有负责人、影响说明与计划日期；"不得以关闭测试、降低阈值或隐藏诊断代替修复"为登记表复核项。
- `release-checklist.md`：R1/R2 各自勾选——阶段退出条件、§3.3 业务指标（含至少一个候选进入下一轮详细设计且相对基线改善≥5%、保护指标不越阈值）、关键结论满足签署容差、缺陷门禁、安装演练（对接 WP-24 干净机协议）、样例/手册/培训齐备；由产品负责人、业务数据负责人与独立试点观察员三方签署（独立评审清单见"独立评审"节）。

## 8. 交付材料清单（T05）

五项：样例项目（标准搬运案例＋改型案例，可由 WP-02 黄金数据导出）、报告模板（对接 WP-12 `ReviewReport` 输出样例）、安装说明（对接 WP-24）、用户手册（主流程＋术语对接 WP-09 术语表）、培训材料（新机型/改型流程各一单元）。全部材料随发布包归档；修订走文档评审，不走代码门禁。

## 任务

### WP-25-T01 试点范围与固定目录

- **范围：** `pilot-plan.md`（固化 1 台机械臂、1 类搬运/上下料任务及环境、工具、负载与目录版本）与 `data-signoff.md`（§4 七项签署清单）。
- **前置：** 任务级无；WP 级＝WP-22～24（真实试点）；数据签署不依赖代码，可在阶段 C 末先行。
- **输出工件：** 试点计划、七项签署清单（业务数据负责人签署、产品负责人会签）。
- **验收断言：** ①清单七项逐项与需求 §17 对应且每项有签署人与日期（module-design/pilot-delivery.md §3）；②首版签署最迟阶段 D 启动前完成（§14）；③未签署数据的使用范围仅限标准样例验证或敏感度参考。

### WP-25-T02 算例与实测对照

- **范围：** 按 §5 设计执行真实机械臂对照实验，产出 `comparison-report.md`；原始测量导出件及其哈希归档。
- **前置：** T01（签署件锁定环境与容差）；WP 级＝可运行的 R1/R2 版本。
- **输出工件：** 对照报告、原始测量导出件与哈希、差异与限制说明。
- **验收断言：** ①每指标仅使用其单独签署容差，不套用默认两层容差（§15.3、module-design/pilot-delivery.md §4）；②非同步/低精度数据只作趋势/相关性证据；③无可行或改进候选时给出可复核的约束与搜索证据（§3.3）；④报告含每指标软件值、对照值、差值、容差与结论五要素。

### WP-25-T03 目标用户任务脚本

- **范围：** `user-study-protocol.md`（协议冻结）、`task-scripts/`（复用 WP-22-T05 三脚本）、`templates/` 表单、执行研究并产出 `user-study-report.md`。
- **前置：** T01（签署试点数据）；WP 级＝WP-22-T05 任务脚本就绪。
- **输出工件：** 冻结协议、每受试记录表单（U01～U05）、汇总统计报告、知情同意记录。
- **验收断言：** ①受试≥5 名且覆盖 §3.2 角色，编号 U01～U05、不记录身份信息；②介入原因按导航/术语/数据入口/计算等待/缺陷五类记录；③完成率、介入次数、耗时与问题分类齐备且映射 UX-01～08 和缺陷等级；④达到 §3.3 成功口径（80%／拼接＝0／复算一致率 100%）；⑤知情同意与数据保存符合 §6 伦理条款（module-design/pilot-delivery.md §5）。

### WP-25-T04 缺陷关闭与遗留项

- **范围：** `defect-register.md` 登记试点全部缺陷（来源＝对照实验、用户研究与安装演练），跟踪关闭或遗留。
- **前置：** T02、T03。
- **输出工件：** 缺陷登记表（等级、复现步骤、影响、负责人、状态、计划日期）。
- **验收断言：** ①试点发布前开放 Blocker＝0（§15.4、module-design/pilot-delivery.md §6）；②未关闭 Critical 均有负责人、影响说明与计划日期；③"不得以关闭测试、降低阈值或隐藏诊断代替修复"作为复核项逐条确认；④缺陷等级与 P0/P1 需求优先级分开命名。

### WP-25-T05 交付材料

- **范围：** §7 发布检查表（R1/R2 各一份，三方签署）与 §8 五项交付材料的编制、归档与随发布包交付。
- **前置：** T01、T02、T03、T04。
- **输出工件：** 发布检查表（三方签署）、样例项目、报告模板、安装说明、用户手册、培训材料。
- **验收断言：** ①检查表 R1/R2 独立勾选且含阶段退出条件、§3.3 业务指标（候选改善≥5%＋保护指标不越阈值）、签署容差结论、缺陷门禁、安装演练（对接 WP-24）与材料齐备七类条目（module-design/pilot-delivery.md §6）；②交付材料五项齐备并分别对接 WP-02/WP-12/WP-24/WP-09；③全部材料随发布包归档，修订走文档评审。

## 验证

验证＝人工复核与签署（testing-contract §4：人工试点使用签署记录和报告工件，不以空 CTest 目标替代）：

- `pilot/data-signoff.md`：七项试点数据的负责人签署记录（T01）；
- `pilot/comparison-report.md`：逐指标对照、差异与限制，附原始测量导出件及其哈希（T02）；
- `pilot/user-study-report.md`：≥5 名目标用户的完成率、介入次数、耗时和问题分类，附签署表单与汇总统计（T03）；
- `pilot/defect-register.md`：Blocker/Critical 缺陷及负责人、影响范围和计划日期（T04）；
- `pilot/release-checklist.md`：R1/R2 发布检查表，产品负责人、业务数据负责人与独立试点观察员三方签署（T05）。

每份 `pilot/` 工件均有负责人签署与日期；本 WP 不设测试命令验证入口，系统级自动化证据由 WP-23 门禁承担、安装证据由 WP-24 演练记录承担，均不在本 WP 重复提交。

## 11. 独立评审

由业务数据负责人、产品负责人和独立试点观察员共同复核签署记录与用户报告；独立试点观察员不得参与试点执行。评审范围：七项签署完整性、对照容差使用口径、用户研究成功口径判定、缺陷等级复核（含"不得以关闭测试、降低阈值或隐藏诊断代替修复"）、发布检查表勾选证据。

## 12. 迁移与删除

| 资产 | 处置 | 说明 |
| --- | --- | --- |
| 原始对照数据与过程报告 | 试点期保留，发布后按 §6 期限清理 | 清理前列入归档清单 |
| 签署记录与缺陷证据 | 永久归档 | 不得删除 |
| 临时试点工程文件 | 发布后清理 | 样例项目正式化后入库 |

## 退出条件

- 至少 1 台真实机械臂、1 类搬运任务和 5 名目标用户完成试点（§14 阶段 E）。
- 达到 §3.3 业务指标：80% 主流程独立完成率、跨工具手工拼接＝0、相同快照复算离散结论一致率 100%、至少一个候选进入下一轮详细设计且相对基线改善≥5%且保护指标不越阈值。
- 关键运动学/动力学结论满足已签署对照容差。
- 开放 Blocker 为 0，未关闭 Critical 均有负责人、影响说明和计划日期。
- R1/R2 发布检查表完整并三方签署。
