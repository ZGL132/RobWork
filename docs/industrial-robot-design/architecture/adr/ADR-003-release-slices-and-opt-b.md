# ADR-003：R1/R2 发布切片与 OPT-B 权威范围

- 状态：`Accepted`（2026-08-30 用户签署生效，签署记录见 [../review/2026-08-29-contract-review.md](../review/2026-08-29-contract-review.md) §5）
- 日期：2026-08-29
- 决策所有者：WP-00（需求/阶段），WP-20（OPT-B），WP-21（OPT-D），WP-24（发布）
- 必需评审者：产品负责人、WP-13～23 消费者、测试负责人、发布负责人
- 关联契约：`CTR-REL-001`、`CTR-OPT-001`
- 需求：OPT-01～10、NFR-PERF-04～06；v0.8 需求 第 8.7.1、14、19 章
- 受影响工作包：WP-00～25

## 背景

需求中大量能力为 P0，但完整联合优化、并行检查点、鲁棒性和大型性能目标无法与工程闭环同时一次性交付。若仅按 P0/P1 排序，团队容易把“R1 可用闭环”和“R2 规模化优化”混为同一发布；若各计划自行定义阶段 B 的优化范围，会产生不同的 OPT-B 清单和验收口径。

## 决策

1. R1 为可独立安装、试点预演和回滚的工程闭环版，覆盖阶段 A+B+C：建模、需求、运动学、轨迹、逆动力学、基础选型和报告。R1 不得依赖 R2 才能完成闭环。
2. R2 在不破坏 R1 `.rwdesign` Schema 的前提下增加阶段 D：并行评估、检查点恢复、分层联合优化、鲁棒性和大型性能目标。
3. OPT-B 是阶段 B 唯一静态优化范围：OPT-01、OPT-02（结构/传动变量）、OPT-03（仅运动学与碰撞静态硬约束）、OPT-04（静态指标与静态 Pareto）、OPT-06（仅缓存与确定性种子）、OPT-07、OPT-08 的静态子集。
4. OPT-D 为 OPT-01～10 全量语义，包含轨迹、动力、器件联合硬约束，完整并行/检查点规模化和鲁棒性协议。
5. 优化候选、抽样和扰动样本归 `OptimizationRunResult`，不得产生 `ProjectRevision`；只有用户执行“设为当前方案”才创建方案分支、新修订并完整复算。
6. 阶段、WP、追踪矩阵和验收报告不得建立另一份 OPT-B 集合；只引用需求 §8.7.1 和本 ADR。

## 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 所有 P0 一次发布 | 拒绝 | 工程闭环和规模化优化互相阻塞，无法形成稳定试点版本 |
| 阶段 B 只交付 UI 骨架 | 拒绝 | 不能证明静态候选编译、硬约束和 Pareto 主链路 |
| 各 WP 自行选择 OPT-B 子集 | 拒绝 | 追踪、测试和阶段门禁会出现多套口径 |
| R1 工程闭环 + R2 优化规模化 | 采用 | 切片可独立验收、部署和回滚，范围可审计 |
| 每个候选创建项目修订 | 拒绝 | 修订历史膨胀并混淆探索产物与设计决策 |

## 影响

- 同一 P0 的交付阶段必须按 R1/R2 解释，不能把 R2 P0 当作 R1 阻塞项。
- 阶段 B 不能以轨迹、动力或器件联合硬约束作为 OPT-B 退出条件。
- R1 Schema 必须为 R2 增量字段保留显式升级路径，但不得预实现 R2 业务能力。
- 报告必须标明结果属于 OPT-B 静态证据还是 OPT-D 全量证据。

## 迁移与回滚

追踪生成器、WP-20/21、测试清单和发布检查表统一引用权威集合。若阶段评审改变范围，先修改需求基线并以新 ADR 替代本 ADR，再同步所有消费者；不得只改某个工作包。R2 发布失败时可回滚到独立 R1 包和兼容项目修订。

## 验证证据

- 阶段 B：AT-09 静态子集、AT-18 阶段 B 链路、OPT-B 确定性复现；
- 阶段 C：R1 安装、回滚及完整工程闭环验收；
- 阶段 D：AT-09～14、NFR-PERF-04～06、检查点恢复和候选统计不重复；
- 静态校验：追踪矩阵和 WP 中不存在第二份 OPT-B 集合。

## 接受条件

1. 产品、WP-20/21、测试和发布负责人签署 R1/R2 与 OPT-B/OPT-D 边界；
2. 追踪矩阵、工作包和验收表对同一需求得出相同阶段/发布；
3. OPT-B 不引用阶段 C/D 前置能力；
4. 候选到正式修订的唯一应用路径在 D2/D3 契约化。
