# ADR-002：`.rwdesign` 目录式规范项目格式

- 状态：`Accepted`（2026-08-30 用户签署生效，签署记录见 [../review/2026-08-29-contract-review.md](../review/2026-08-29-contract-review.md) §5）
- 日期：2026-08-29
- 决策所有者：WP-04（项目与持久化），WP-11（安全导入导出）
- 必需评审者：WP-05/08/12/24 消费者、安全负责人、独立测试负责人
- 关联契约：`CTR-PER-001`、`CTR-PER-002`、`CTR-PER-003`
- 需求：ARC-01、CON-01、CON-03、NFR-REL-01、NFR-REL-04、NFR-SEC-01、NFR-SEC-02
- 受影响工作包：WP-04、05、08、11、12、20、21、24、25

## 背景

项目包含多版本领域对象、外部网格/目录副本、运行结果、检查点和报告，单文件原地覆盖无法同时满足崩溃一致性、历史证据保护和大工件增量写入。需求允许新格式断代，不要求兼容旧项目格式，因此可以选择更清晰的规范存储边界。

## 决策

1. `ProjectName.rwdesign/` 目录是唯一规范项目格式；ZIP 只允许作为传输封装，解包后必须按目录格式校验和使用。
2. `HEAD` 只保存当前分支和修订指针；`project.json` 保存项目级 ID 与格式版本；修订清单和内容寻址对象分离。
3. 对象文件不可变；结果、检查点和报告只追加。Verified/正式报告引用的外部资源必须复制到项目不可变资源区并受引用保护。
4. 多文件提交固定为“写入临时版本目录 → 校验全部文件、引用和哈希 → 原子切换提交指针”。任何失败都保持旧 `HEAD` 与旧版本完整。
5. 项目内路径使用 POSIX 分隔符并在边界规范化；绝对路径、路径穿越、资源区逃逸、解压炸弹和超预算输入必须拒绝。
6. 不建设旧项目格式兼容层；旧文件仅可由独立受控工具读取为迁移证据，不能形成第二种当前项目真值。

## 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 单一 JSON/XML 文件原地保存 | 拒绝 | 大资源、结果和检查点导致覆盖成本高，跨文件一致性不可证明 |
| ZIP 直接作为运行时真值 | 拒绝 | 随机写入、原子提交和资源流式访问复杂，安全边界模糊 |
| 嵌入式数据库作为首版格式 | 拒绝 | 引入额外依赖和迁移机制，不利于工件审计与内容寻址 |
| 目录规范格式 + ZIP 传输封装 | 采用 | 便于事务、增量工件、审计、恢复和安全校验 |
| 长期兼容旧格式 | 拒绝 | 与需求断代决策冲突并延长双轨实现 |

## 影响

- 保存、打开、打包、清理和恢复必须围绕版本目录与内容引用设计。
- 项目不是一个可随意复制的单文件；安装包和用户文档必须明确目录语义。
- ZIP 导入需要独立的路径和资源预算防护。
- Schema 和 format 版本必须分离，未知未来版本只读拒绝。

## 迁移与回滚

现有旧项目不自动迁移。可复用对象通过受控导入器生成新 `.rwdesign` 项目，并保留来源哈希和迁移判定。提交前失败删除/忽略临时版本；提交指针切换失败时重新打开旧 `HEAD`。新格式验收前旧插件只读，验收后从构建和安装包删除。

## 验证证据

- A-GATE-04：版本目录、资源写入、提交指针三个故障注入点；
- 项目逐文件哈希、引用完整性、未知版本和未提交目录恢复测试；
- 路径穿越、绝对路径、符号链接逃逸、递归深度和解压总量安全测试；
- Verified 结果在外部源删除后仍能复算的资源保护测试。

## 接受条件

1. D3 提供可解析的 project/revision/object/result/checkpoint Schema；
2. 保存状态机、原子边界和清理规则具有失败测试；
3. A-GATE-04 与 NFR-SEC-01/02 安全用例通过；
4. WP-04、05、08、11、12、24 完成消费者评审。
