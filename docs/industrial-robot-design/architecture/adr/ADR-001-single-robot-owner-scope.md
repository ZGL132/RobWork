# ADR-001：首版单机械臂与稳定所有者作用域

- 状态：`Proposed`
- 日期：2026-08-29
- 决策所有者：WP-03（领域身份），WP-04（项目聚合），WP-06（运行时名称）
- 必需评审者：产品/机械臂系统负责人、WP-05/07/12/13/15～21 消费者、独立测试负责人
- 关联契约：`CTR-DOM-001`、`CTR-DOM-002`、`CTR-NAM-001`
- 需求：ARC-01、ARC-04、CON-06、NFR-MNT-03、NFR-MNT-07
- 受影响工作包：WP-03～07、WP-12～23

## 背景

首版产品明确限定为“一个项目、一个 4～7 轴串联机械臂”，但领域对象、结果、碰撞对和 RobWork 名称都需要稳定引用。若因首版只有一个机械臂而省略所有者作用域，未来扩展多机械臂时必须改写所有对象 ID、项目引用、快照和历史证据；若直接用名称作身份，重命名、重复局部名和运行时前缀会导致错误绑定。

## 决策

1. 首版每个 `ProjectRevision` 恰好引用一个 `RobotDesign`，`project.json` 恰好保存一个 `robotId`。
2. 每个可跨模块、持久化、结果或报告引用的对象使用稳定 `ObjectId`，并保存 `ownerScopeId`；首版机器人相关对象的 `ownerScopeId` 必须等于唯一 `robotId`。
3. `localName` 和显示名称不是身份；重命名不得改变 `objectId`，删除的 ID 永不复用。
4. RobWork 设备内名称只由 `RuntimeNameMap`/`IRuntimeNameResolver` 在适配边界生成和反解，格式为 `RobotName.LocalName`；领域引用不得保存运行时名称作为主键。
5. 首版不实现多机械臂 UI、协同任务、机器人间碰撞或多机器人调度。未来扩展通过把单值 `RobotDesign` 升级为按 `robotId` 索引的集合，并增加显式机器人引用，不改变既有对象 ID 或 `.rwdesign` 目录语义。

## 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 首版省略 `ownerScopeId` | 拒绝 | 多机械臂扩展会破坏持久化、快照和历史证据身份 |
| 使用名称或 RobWork 全名作身份 | 拒绝 | 重命名、重复局部名、旧前缀和双前缀会产生错绑 |
| 首版直接实现多机械臂 | 拒绝 | 超出产品范围，并显著扩大碰撞、调度和 UI 复杂度 |
| 单机械臂约束 + 预留稳定作用域 | 采用 | 保持首版简单，同时提供无破坏扩展路径 |

## 影响

- 所有领域引用、碰撞对、快照、结果和报告必须携带稳定 ID，不能依赖显示字符串。
- 每次导入、复制、删除、重命名和运行时编译都需要身份与作用域校验。
- 公共类型增加 `ownerScopeId` 和名称映射工件，带来少量存储与测试成本。
- 未来多机械臂扩展仍需新 ADR，但无需迁移现有对象 ID 和历史证据。

## 迁移与回滚

旧插件中的名称引用只作为迁移输入；迁移器建立新 `ObjectId`/`ownerScopeId` 并记录来源，无法唯一解析的引用标记 `EvidenceOnly` 或拒绝迁移。新链路通过 A-GATE-06/AT-18 后删除分散的前缀拼接与剥离代码。若新映射未通过门禁，回滚到前一项目修订和旧只读链路，不得写入半映射项目。

## 验证证据

- A-GATE-06：相同局部名、相似前缀和机械臂重命名契约测试；
- AT-18：分阶段覆盖建模、需求、分析、优化和报告的对象解析；
- 静态扫描：非 WP-06 所有者目录不得新增设备前缀拼接/剥离；
- 持久化测试：重命名、分支、修订、删除和历史结果均保持原 `objectId`。

## 接受条件

1. `ObjectId`、`RobotId`、`ObjectIdentity` 和 `RuntimeNameMap` 的字段/Schema 在 D2/D3 冻结；
2. 所有消费者完成影响评审；
3. A-GATE-06 和首个可用阶段的 AT-18 子集通过；
4. 代码边界扫描能阻止非所有者前缀逻辑。
