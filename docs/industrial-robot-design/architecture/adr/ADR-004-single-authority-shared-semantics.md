# ADR-004：跨模块共享语义的单一权威所有者

- 状态：`Accepted`（2026-08-30 用户签署生效，签署记录见 [../review/2026-08-29-contract-review.md](../review/2026-08-29-contract-review.md) §5）
- 日期：2026-08-29
- 决策所有者：WP-03（单位/状态），WP-05（结果当前性），WP-06（名称），WP-07（策略/碰撞），WP-09（诊断），WP-18（传动映射）
- 必需评审者：全部业务 WP 消费者、架构负责人、独立测试负责人
- 关联契约：`CTR-DOM-002～004`、`CTR-NAM-001`、`CTR-POL-001`、`CTR-DIA-001`、`CTR-EXE-002～004`
- 需求：ARC-02、ARC-04、ARC-05、CON-02、CON-05、CON-06、EVI-01、NFR-MNT-03、NFR-MNT-07
- 受影响工作包：WP-03～23

## 背景

旧插件存在名称前缀、碰撞开关、状态判定、默认值、结果当前性和评估算法在多个入口重复实现的风险。同一模型可能因从运动学、轨迹或优化入口运行而得到不同对象绑定和工程结论。把所有共享逻辑放进一个巨型服务会形成新的耦合；允许每个插件自行实现则无法保持一致。

## 决策

1. 每类跨模块语义有且只有一个登记的权威类型、所有者和实现，消费者只通过公共端口使用。
2. 所有权冻结如下：WP-03 拥有身份、单位和正式可行谓词；WP-04 拥有项目命令；WP-05 拥有输入切片、结果和当前性；WP-06 拥有 `RuntimeNameMap`；WP-07 拥有 `EngineeringPolicySet`、`CollisionPolicy` 和共享碰撞评估；WP-08 拥有任务调度；WP-09 拥有诊断；WP-12 拥有报告；WP-18 拥有传动映射。
3. 消费者不得复制状态枚举、单位转换、默认值、诊断文案、名称处理、碰撞规则、当前性或传动映射；扩展需求必须先由所有者修改契约和测试。
4. 影响工程结论的规则必须进入版本化策略或输入切片；纯显示状态不得进入策略、缓存键或结果当前性。
5. 公共符号必须登记在 `symbol-registry.md`，公共契约必须登记在 `contract-registry.md`；未登记的跨模块 DTO、接口或规则不得进入公共头。
6. 所有权分散到有内聚性的模块，不建立“万能共享服务”；单一权威指语义唯一，不表示所有逻辑放在一个库。

## 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 每个插件复制共享规则 | 拒绝 | 默认值和算法漂移，跨入口结果无法复核 |
| 一个巨型全局服务拥有所有语义 | 拒绝 | 形成高耦合单点，职责和依赖方向失控 |
| 只靠代码评审约定一致 | 拒绝 | 缺少机器门禁和稳定所有者，长期必然漂移 |
| 按语义分所有者、每类只有一个实现 | 采用 | 保持内聚和依赖方向，同时可建立契约测试 |

## 影响

- 消费者变更共享语义需要跨 WP 协调，局部修改速度降低，但减少长期分叉和回归成本。
- 公共端口、注册表、契约测试和静态边界扫描成为合并门禁。
- 旧插件中的本地开关、映射和默认值必须先隔离为只读适配，再删除。
- 允许模块拥有私有算法，但一旦结果或配置跨模块交换，就必须升级为登记契约。

## 迁移与回滚

按“登记现有实现 → 黄金测试锁定 → 建立权威实现 → 消费者切换 → 静态扫描 → 删除副本”迁移。切换期间旧逻辑只读且不得进入新结果。任一消费者未通过契约测试时回滚该消费者适配，不回滚或复制权威语义；无法证明旧结果来源的内容标记 `EvidenceOnly`。

## 验证证据

- A-GATE-02/03：当前性、分支和迟到结果；
- A-GATE-06/AT-18：名称映射跨入口一致性；
- A-GATE-07/AT-19：统一策略和碰撞评估跨入口一致性；
- EVI-01 状态组合矩阵和正式可行谓词测试；
- 传动映射黄金数据：效率、反射惯量、摩擦不重复和能量口径；
- 静态扫描：非所有者目录中的前缀、策略副本、本地计算开关和重复 DTO 命中为零。

## 接受条件

1. 契约注册表和符号注册表的所有者/消费者联合评审完成；
2. D2 冻结状态、策略、当前性、名称和传动映射核心语义；
3. D3 提供公共接口、Schema 和静态边界规则；
4. 至少一个真实消费者对每类权威实现通过契约测试。
