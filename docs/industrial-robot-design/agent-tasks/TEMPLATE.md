# WP-XX-TYY 任务卡模板（16 字段标准，字段标记与 `README.md` 冻结口径一致）

> 每张任务卡按以下 16 个字段组织，字段名以 `- **字段名：**`（代码任务）或等价变体（非代码任务）出现；
> 非代码任务（试点/安装/用户研究/治理）变体：**交付步骤**＝实施步骤、**验证准备**＝RED 测试、**精确验证方式**＝精确验证命令。

1. `# WP-XX-TYY 标题`
2. - **Task ID / 需求 ID / ADR / 阶段：** 稳定需求 ID（不得只写"需求 §N"章节引用）＋阶段/发布＋权威契约清单
3. - **基线 commit：** 代码基线提交与文档语义源版本
4. - **前置任务及必需工件：** 明确任务 ID 与必需工件（不得写"由对应 WP 声明前置"）；禁止形成任务级依赖环
5. - **允许创建/修改/删除的文件：**（基目录 `<具体路径>`）创建/修改/删除逐项列出
6. - **禁止修改的文件和公共接口：** 上游冻结对象、公共头、权威文档与黄金数据
7. - **修改前接口：** 现状与缺口
8. - **修改后接口：** 交付的公共语义（引用契约编号，不复述正文）
9. - **实施步骤：** 有序步骤（非代码任务字段名为 **交付步骤：**）
10. - **RED 测试：** 先写先败的测试函数名（非代码任务字段名为 **验证准备：**）
11. - **最小实现：** 满足 RED 的最小交付范围
12. - **正常/边界/失败测试：** Given/When/Then 三例
13. - **精确验证命令：** 第一形式必执行（`run-tests.ps1`），脚本不可用时按回退顺序执行原生 cmake/ctest 两形式；命令直接复制可执行（无省略号、无 `grep`、无自然语言路径、无花括号展开）；目标名与已登记 target 一致
14. - **diff 和禁止项检查：** diff 允许清单核对＋静态搜索（`rg`）＋`check-boundaries.ps1` 零违规
15. - **证据工件：** `out/test-evidence/wp-xx/<run-id>/`（AGENTS §3，禁止写入模块源码树）
16. - **提交格式：** `WP-XX-TYY: 中文概括`＋空行后 `- ` 中文分条正文（新增/修改/测试/证据/修复）；- **停止与升级条件：** 升级触发点与独立评审者分离要求

转为 Ready 前必须通过（DOCUMENT-BASELINE §4）：需求与契约可追溯（稳定需求 ID）、前置完成且无依赖环、允许/禁止范围无歧义、失败与成功断言均完整、验证命令逐字可执行、证据路径为 `out/test-evidence/` 前缀、状态已在 [task-status.md](task-status.md) 账本登记。
