# 智能体任务卡

每张任务卡对应一个独立 worktree、分支和可评审提交。卡片是 WP 文件任务的执行上下文，不得替代需求或架构契约。

> 文档治理基线：`IRD-D0-20260829`  
> 默认状态：`Planned`。卡片必须逐张通过入口门禁后才能进入 `Ready`。

## 固定字段（D7 冻结的 16 字段结构）

每张卡按顺序包含以下 16 个粗体字段：

1. Task ID / 需求 ID / ADR / 阶段；
2. 基线 commit（代码基线 + 文档基线）；
3. 前置任务及必需工件（具体 Task ID，禁止"由对应 WP 声明"）；
4. 允许创建/修改/删除的文件（精确路径）；
5. 禁止修改的文件和公共接口；
6. 修改前接口；
7. 修改后接口；
8. 实施步骤（TDD 次序）；
9. RED 测试（具体测试函数名）；
10. 最小实现；
11. 正常/边界/失败测试；
12. 精确验证命令（双/三形式，禁省略号）；
13. diff 和禁止项检查；
14. 证据工件；
15. 提交格式 `WP-XX-TYY: <topic>`；
16. 停止与升级条件。

非代码任务卡（试点、安装演练、用户研究、交付）允许三个字段的等价变体：`交付步骤` 替代实施步骤、`验证准备` 替代 RED 测试、`精确验证方式`（签署记录/对照报告/人工检查表）替代精确验证命令；此类卡禁止出现 CTest 目标与"固定种子"类开发模板措辞。

WP-00～WP-25 的预期基线为 150 张独立任务卡；每张卡对应一个稳定 Task ID，进入对应阶段前必须完成其前置任务和证据要求。实际卡片数量、文件名和 WP 索引的一一对应关系必须由当前仓库中的 `validate-development-docs.ps1` 计算，不得以本说明中的数量代替校验结果。

## Planned 转 Ready 门禁

1. 需求、架构契约、模块方案和所属工作包均为当前可实施版本；
2. 前置任务及输入工件已完成，基线提交可定位；
3. 允许修改、禁止修改、公共接口所有者和提交边界明确；
4. 实施步骤不要求智能体自行决定跨模块字段、状态、公式或默认值；
5. Given/When/Then 覆盖失败、正常和边界路径；
6. 所有验证命令包含目标、参数、环境前置和预期结果，能够直接执行；
7. 证据位置、独立验证者、评审者和停止条件明确；
8. 任务 ID、真实构建目标、测试 ID 和需求追踪闭合。

任何一项不满足时保持 `Planned` 并报告阻塞。任务卡不得通过“按现有代码处理”“补充必要测试”或省略号把设计和验证责任转交给实施智能体。
